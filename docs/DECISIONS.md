# Decisions

Format: date — decision — why.

- 2026-10-09 — Fresh git repo in the project folder; the parent home directory is itself a git repo, so nested `git init` keeps history isolated.
- 2026-10-09 — MDX via `next-mdx-remote/rsc` instead of `@next/mdx`: lets frontmatter be parsed and Zod-validated per file at build time and keeps content outside `src/app`.
- 2026-10-09 — pnpm installed globally via npm (was absent).
- 2026-10-09 — Local machine has no `g++`; C++ reference solutions are verified in CI only, Python/Java locally. COVERAGE.md states this.
- 2026-10-09 — Depth over breadth: Levels 0–2 first; higher levels marked Planned if not reached.
- 2026-10-09 — Python solutions are the canonical tested solutions for every problem (executable in-browser too); C++/Java variants are added where verified.
- 2026-10-09 — `blockJS: false` in next-mdx-remote: it silently strips expression props like `questions={[...]}`; content is repo-authored and trusted.
- 2026-10-09 — Pyodide stdin uses the raw-byte `read` API: the line-based `stdin()` callback truncated lines over ~8 KB (found by the max-size test).
- 2026-10-09 — Browser-judged problems keep test data small (~50 KB) because tests ship to the client; full-scale constraints are discussed in editorials. Reference solutions are never sent to the client.
- 2026-10-09 — MDX exposes the trade-off table as `<TradeOffs>` (JSX tag names cannot contain a hyphen).
- 2026-10-09 — Memory usage is not measurable in browser workers; shown as "n/a" unless an external runner reports it.
- 2026-10-26 — The UI was deliberately pushed to a maximalist, highly interactive style at the owner's request (aurora background, gradient type, spotlight cards, live hero demo, confetti, scrubbers). This overrides the HIG's restraint and deference principles, as the global rules allow for explicit instructions. Kept from the HIG: WCAG AA contrast in both themes, visible focus, 44px minimum targets, text labels alongside colour, and every animation honouring prefers-reduced-motion (no autoplay, no confetti, instant counters).
- 2026-10-27 — Visualizer lessons were added as modules 11 to 14 (graphs, range queries, dynamic programming, string matching), one to two lessons each, rather than waiting for the full 11-26 plan: the visualizers already existed and each deserves a lesson. The module numbers and names are provisional and may be reorganised when the rest of Levels 2 and 3 are written. Each lesson has one problem with Python, JavaScript and Java verified locally and a C++ solution verified in CI only (no `g++` here).
- 2026-11-01 — The maximalist UI of 2026-10-26 was replaced, at the owner's request, by an editorial gallery style inspired by siteofsites.co: white canvas (light is now the default theme), one electric ultramarine accent with vermilion/cobalt/ochre/pine as secondary tints, tracked uppercase micro-labels, hairline-bordered tiles with solid colour covers and circular arrow buttons, pill buttons, a serif wordmark, and medium-weight display type. Aurora background, grid, gradient text, glows, card tilt and drop shadows were removed; legacy classes (`text-gradient`, `bg-gradient-brand`, `ring-glow`) remain as flat-colour aliases so unmigrated pages stay consistent. Kept: WCAG AA contrast in both themes (accent #0400D6 on white is about 12:1; the dark accent is periwinkle), visible focus, 44px targets, reduced-motion support. Only the look was borrowed, no assets or copy.
- 2026-11-01 — `Spotlight` no longer takes a `tilt` prop; the pointer-glow e2e test was replaced by a test that the arrow button fills on hover.
- 2026-11-01 — Problem `complexity` fields are a closed enum (`O(n)`, `O(n log n)`, ...), so linear-in-edges and `O((n + q) log n)` solutions are labelled `O(n)` and `O(n log n)`; the editorial states the precise bound.
- 2026-11-02 — Problem `m13-digit-hunt` caps `R` at 10^15 in the browser version so the JavaScript reference solution stays exact with `Number` (2^53 is about 9·10^15); the lesson and editorial say the idea scales to 10^18 with 64-bit integers.
- 2026-11-02 — `m11-lamp-rules` outputs only YES or NO, not an assignment, because many valid assignments exist and the judge compares exact output; the lesson shows how to extract one. `m11-pipe-network` uses Dinic's algorithm with recursion limited by the level depth (at most 200 vertices in the browser version).
- 2026-11-02 — `m13-stone-hops` caps heights at 10^5 (and C at 10^6) so every cross-multiplication in the hull trick stays below 2^53; this keeps the JavaScript reference exact without BigInt. The lesson tells readers to use `__int128`, long double or a Li Chao tree beyond that. `m15-path-boss` and `m14-fresh-substrings` use BFS order and explicit loops so deep trees and long strings do not rely on recursion.
- 2026-11-02 — `m11-cheap-shipping` restricts prices to be non-negative so successive shortest paths starts with no negative cycle; the lesson explains the potentials and cycle-cancelling fixes for negative prices. Its expected outputs are cross-checked by a cycle-cancelling solver (tiny graphs) and a Dijkstra-with-potentials solver (large graphs), neither of which shares code with the SPFA reference. `m13-truck-loads` requires non-negative weights because the quadrangle inequality, hence the divide and conquer optimisation, depends on non-decreasing prefix sums.
- 2026-11-02 — System design module 11 ("Distributed systems theory", Level 2) is written as four lessons that each run a small simulation and quote its **measured** output, as the consistent-hashing lesson does. Every measured table was regenerated by extracting the lesson's own `CodeRunner` program and running it (Python 3.13), and the quoted numbers were compared with the output. The failure-detection model is deliberately simple (one monitor, independent stalls); the lesson says so. Consensus (Raft) is left to module 12 rather than squeezed into this module.
- 2026-11-02 — System design module 12 ("Consensus and coordination") follows the same convention as module 11: each lesson quotes the output of its own program, regenerated before publication. Raft is taught from the paper's rules (terms, randomised timeouts, the up-to-date vote restriction, commit by majority in the leader's term); the log-safety simulation is a deliberately simplified model (whole-log copies, no message loss) used to show the invariant with and without the voting rule, not a Raft implementation. The first draft of the election simulation never terminated for a zero-width timeout spread, which is itself the lesson's point, so the published table starts at a 10 ms spread.
- 2026-11-02 — System design module 13 ("Microservice patterns") avoids repeating what modules 5, 8 and 10 already teach (gateways, queue-level retries, load shedding) and adds the missing angles: availability maths for dependency chains, retry amplification across layers (with a retry budget and circuit breaker compared in one simulation), CQRS with event sourcing, and schema compatibility. The retry simulation uses a fixed failure rate, so it shows load amplification but not the feedback loop of a real overload; the lesson says so. The compatibility lesson keeps a note that the first draft of its rules failed its own mechanical check (8 of 9) and was corrected, as an argument for testing compatibility instead of reasoning about it.
- 2026-11-02 — Lesson `CodeRunner` blocks run in the browser (Pyodide) with a 5 s default limit, and Pyodide is several times slower than native CPython. Several simulations written for modules 11 to 13 took 4 to 27 s natively and would have timed out for readers (the sandbox cannot reach the Pyodide CDN, so in-browser timing could not be measured here). Fix: `CodeRunner` gains an optional `timeoutMs` prop (default unchanged), the heavy gossip and consistency simulations were shrunk to about a second natively (their quoted tables were regenerated), and every demo that takes more than about half a second natively now sets `timeoutMs={30000}`. Rule for new lessons: keep each demo under about a second natively and set `timeoutMs` when it exceeds half a second.
- 2026-11-02 — System design module 14 ("Search systems") follows the measured-results convention and the new demo-size rule (about a second natively, `timeoutMs={30000}`). Two review points from writing it: (1) the first quiz arithmetic for BM25 saturation was wrong by hand (0.19 instead of 0.11) and was caught by running the expression, so quiz `predict` items should be run before publishing; (2) the ranking demo deliberately uses queries with very common words to stress each failure mode, and the lesson shows that on an easier query mix the simple baselines come close, so the numbers illustrate mechanisms, not expected production quality. The vector-search demo uses clean synthetic clusters, which flatters ANN; the lesson says so.
- 2026-11-02 — System design module 15 ("Security fundamentals") keeps every demo standard-library only (hashlib, hmac, json, html, ipaddress) so it runs in Pyodide with no package loading, and avoids sqlite3 for the same reason: the SQL-injection demo compares the structure ("shape") of a concatenated query with a parameterised one instead of executing SQL. The password-attack rates are round illustrative numbers, not benchmarks, and the lesson says so. The SSRF allow-list in the demo is intentionally simple and the lesson lists what a real defence adds (resolved-address checks, no redirects). Demos avoid backslashes (use `" ".join(s.split())` instead of a regex with `\s`) because backslashes inside the MDX template literal depend on JavaScript escaping and are easy to get wrong.
