## Intuition

A query like `distributed lock timeout` can match thousands of documents. The engine must put the best ten first. A first idea is to count how often the query words appear in a document. That fails in two ways:

1. **Common words dominate.** A document that says "the" a hundred times is not more relevant to a query containing "the".
2. **Long documents win unfairly.** A long document mentions every word more often simply because it has more words.

Two fixes give the classic scoring functions. **Inverse document frequency (IDF)** down-weights words that appear in many documents, so rare, informative words count more. **Length normalisation** and **term-frequency saturation** stop long documents and repeated words from running away with the score. BM25 combines all of this and is the default in Lucene, Elasticsearch and OpenSearch.

## Definition

For a collection of `N` documents, let `n(t)` be the number of documents containing term `t`, `f(t, d)` the number of times `t` occurs in document `d`, `|d|` the length of `d` in words and `avgdl` the average document length.

**TF-IDF:**

```text
score(d, q) = sum over query terms t of   f(t, d) * idf(t)
idf(t)      = ln( 1 + (N - n(t) + 0.5) / (n(t) + 0.5) )
```

**BM25:**

```text
score(d, q) = sum over t of   idf(t) * f * (k1 + 1) / ( f + k1 * (1 - b + b * |d| / avgdl) )      with f = f(t, d)
```

- `k1` (typically 1.2 to 2) controls **term-frequency saturation**: the contribution of a term grows with `f` but flattens out, so the tenth occurrence adds much less than the first.
- `b` (typically 0.75) controls **length normalisation**: with `b = 1` a document twice as long as average is penalised fully, with `b = 0` length is ignored.
- A term absent from a document contributes nothing.

Intuition for the saturation: if `f` is huge the fraction approaches `idf * (k1 + 1)`, a ceiling per term, so no single word can drown the others.

## Measuring relevance

Ranking quality needs **judgements**: for sample queries, which documents are relevant. Common metrics:

| metric | what it measures |
| --- | --- |
| precision@k | fraction of the top `k` results that are relevant |
| recall@k | fraction of all relevant documents found in the top `k` |
| MRR | average of `1 / rank` of the first relevant result |
| nDCG | graded relevance, with higher positions weighted more |

Offline metrics on a judged set, plus online measurement (click-through, reformulation rate, A/B tests), guide changes. Tuning relevance by feel on three favourite queries is how search quality quietly regresses.

## Code: four rankers on queries with common words

The program builds 600 synthetic documents about 10 topics with very different lengths (16 to about 300 words). Each document mixes topic words with common background words. A query has **one topical word and two very common words**, and a result is relevant when the document is about the query's topic. It scores every document with four functions and reports precision@10 over 200 queries.

from collections import Counter

random.seed(3)
TOPICS, TOPIC_WORDS, BACKGROUND = 10, 25, 400
topic_vocab = [[f"t{t}w{i}" for i in range(TOPIC_WORDS)] for t in range(TOPICS)]
background = [f"b{i}" for i in range(BACKGROUND)]
bg_weights = [1 / (i + 1) for i in range(BACKGROUND)]

docs, labels = [], []
for _ in range(600):
    t = random.randrange(TOPICS)
    length = int(random.lognormvariate(4.0, 0.6)) + 10
    words = [random.choice(topic_vocab[t]) if random.random() < 0.12 else random.choices(background, bg_weights)[0]
             for _ in range(length)]
    docs.append(Counter(words))
    labels.append(t)

N = len(docs)
df = Counter(w for d in docs for w in d)
doc_len = [sum(d.values()) for d in docs]
avg_len = sum(doc_len) / N

def idf(w):
    return math.log(1 + (N - df[w] + 0.5) / (df[w] + 0.5))

def score_count(d, q):
    return sum(1 for w in q if w in docs[d])

def score_tf(d, q):
    return sum(docs[d][w] for w in q)

def score_tfidf(d, q):
    return sum(docs[d][w] * idf(w) for w in q)

def score_bm25(d, q, k1=1.2, b=0.75):
    s = 0.0
    for w in q:
        f = docs[d][w]
        if f:
            s += idf(w) * f * (k1 + 1) / (f + k1 * (1 - b + b * doc_len[d] / avg_len))
    return s

def evaluate(score, queries, k=10):
    precision = 0.0
    for q, topic in queries:
        ranked = sorted(range(N), key=lambda d: (-score(d, q), d))[:k]
        precision += sum(labels[d] == topic for d in ranked) / k
    return precision / len(queries)

queries = []
for _ in range(200):
    t = random.randrange(TOPICS)
    q = random.sample(topic_vocab[t], 1) + random.sample(background[:30], 2)
    queries.append((q, t))

print(f"{N} documents, lengths {min(doc_len)} to {max(doc_len)} words (average {avg_len:.0f}), 200 queries")
print("each query: one topical word plus two very common words; relevant = same topic")
print(" ranking function              precision@10")
for name, fn in (("count of matched query words", score_count), ("raw term frequency", score_tf), ("TF-IDF", score_tfidf), ("BM25 (k1=1.2, b=0.75)", score_bm25)):
    print(f" {name:30s} {100 * evaluate(fn, queries):6.1f}%")

### Measured results

Running this exact program with Python 3.13 produced:

| ranking function | precision@10 |
| --- | --- |
| count of matched query words | 58.3% |
| raw term frequency | 16.8% |
| TF-IDF | 74.9% |
| BM25 (`k1 = 1.2`, `b = 0.75`) | **99.0%** |

The ordering tells the story. **Raw term frequency is the worst** (16.8%, close to the 10% chance level for 10 topics): the two very common query words appear many times in every long document, drowning the single topical word. Counting matched words is better because it ignores repeats, but it cannot tell the rare topical word from a common one (58.3%). **TF-IDF** weights the rare word properly (74.9%) but still favours long documents that repeat it. **BM25** adds saturation and length normalisation and finds the right topic for 99% of the top-10 slots. The data are synthetic and constructed to stress the failure modes, so the absolute numbers are not a prediction for your corpus; the lesson is *which mechanism fixes which failure*. On an easier query mix (change the query line to two topical words plus one common word and run it again) the figures become 97.8% for the simple count, 40.6% for raw term frequency, 98.2% for TF-IDF and 100.0% for BM25: the more the query helps, the less the ranking function matters.

## Beyond BM25

- **Field boosts:** a match in the title counts more than in the body (BM25F).
- **Phrase and proximity boosts:** terms close together score higher.
- **Freshness, popularity, personalisation:** blended in as extra signals.
- **Learning to rank:** a model (gradient boosted trees or a neural network) re-ranks the top few hundred BM25 candidates using many features, trained on click or judgement data.
- **Hybrid with vectors:** combine lexical and semantic scores (next-but-one lesson).
- **Shard-local statistics:** IDF is computed per shard by default, so on small or skewed shards the scores are slightly inconsistent; a distributed-frequency query mode fixes that at extra cost.

## Pitfalls

- Ranking by raw term counts.
- Tuning relevance against a few anecdotal queries instead of a judged set with a metric.
- Ignoring that analysis choices (stemming, stop words) change scores as much as the formula.
- Over-boosting recency or popularity until results stop matching the query.
- Comparing scores across different queries or indexes: BM25 scores are only meaningful for ranking within one query.
- Hiding a ranking change behind a deploy with no A/B test or rollback.
