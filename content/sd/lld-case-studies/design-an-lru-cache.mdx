## The problem

Design a cache with a **fixed capacity** that supports `get(key)` and `put(key, value)` in **O(1)** time. When it is full and a new key arrives, it **evicts the least recently used** entry. This is the classic low-level design question because it looks like a one-liner and then tests whether you can **combine two data structures** so that every operation, including the eviction, is constant time.

## Requirements

- `get(key)` returns the value or `None`, and marks the key as **most recently used**.
- `put(key, value)` inserts or updates, marks the key as most recently used and evicts the **least recently used** key if the capacity is exceeded.
- Both are **O(1)**.
- Capacity is fixed at construction and at least 1.
- Extensions to discuss: **eviction callback**, **time to live (TTL)**, **thread safety**, other **eviction policies**.

## Why one structure is not enough

| structure | lookup | find the least recently used | reorder on access |
| --- | --- | --- | --- |
| Hash map alone | O(1) | O(n) scan | no order at all |
| List or array alone | O(n) | O(1) at the end | O(n) to move an item |
| **Hash map plus doubly linked list** | **O(1)** | **O(1) (the tail)** | **O(1) (unlink and relink)** |

The trick: the **map** takes a key straight to its **node** in the list; the **list** keeps nodes in recency order, most recent at the head and least recent at the tail. Because the list is **doubly linked** and we hold the node, we can unlink it in O(1) without searching. **Sentinel** head and tail nodes remove every "empty list" and "single element" edge case.

## Class design

- `Node`: key, value, prev, next. The node stores the **key** too, because when we evict the tail we must also delete its key from the map.
- `LRUCache`: the map, the two sentinels and two private helpers, `_unlink` and `_push_front`. `get` and `put` are **compositions of those two helpers**, which keeps each method short and easy to check.
- `Cache` (an abstract base): `get` and `put`. A FIFO cache implements the same interface, which lets us **compare policies** and substitute one for another ([Liskov substitution](/sd/oop-and-design-patterns/solid-principles-in-practice/)).
- `TTLLRUCache`: **inherits** the LRU behaviour and adds expiry. The clock is **injected** (a function) so tests can control time.

## The code, with tests

The program below defines the classes, then **checks the cache against a trusted model**: Python's `OrderedDict` driven by the same 20,000 random operations, comparing the full recency order after **every** step. It then compares LRU with FIFO on three workloads.

from abc import ABC, abstractmethod
from collections import OrderedDict


class Node:
    __slots__ = ("key", "value", "prev", "next")
    def __init__(self, key=None, value=None):
        self.key, self.value, self.prev, self.next = key, value, None, None


class Cache(ABC):
    @abstractmethod
    def get(self, key): ...
    @abstractmethod
    def put(self, key, value): ...


class LRUCache(Cache):
    """Hash map for O(1) lookup + doubly linked list for O(1) recency order. Head = most recent."""
    def __init__(self, capacity, on_evict=None):
        if capacity < 1:
            raise ValueError("capacity must be at least 1")
        self.capacity, self.on_evict = capacity, on_evict
        self._map = {}
        self._head, self._tail = Node(), Node()      # sentinels remove every edge case
        self._head.next, self._tail.prev = self._tail, self._head

    def _unlink(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _push_front(self, n):
        n.prev, n.next = self._head, self._head.next
        self._head.next.prev = n
        self._head.next = n

    def get(self, key):
        n = self._map.get(key)
        if n is None:
            return None
        self._unlink(n)
        self._push_front(n)
        return n.value

    def put(self, key, value):
        n = self._map.get(key)
        if n:
            n.value = value
            self._unlink(n)
            self._push_front(n)
            return
        if len(self._map) >= self.capacity:
            victim = self._tail.prev
            self._unlink(victim)
            del self._map[victim.key]
            if self.on_evict:
                self.on_evict(victim.key, victim.value)
        n = Node(key, value)
        self._map[key] = n
        self._push_front(n)

    def keys_most_recent_first(self):
        out, n = [], self._head.next
        while n is not self._tail:
            out.append(n.key)
            n = n.next
        return out

    def __len__(self):
        return len(self._map)


class FIFOCache(Cache):
    def __init__(self, capacity):
        self.capacity, self._d = capacity, OrderedDict()
    def get(self, key):
        return self._d.get(key)
    def put(self, key, value):
        if key not in self._d and len(self._d) >= self.capacity:
            self._d.popitem(last=False)
        self._d[key] = value


class TTLLRUCache(LRUCache):
    """LRU plus expiry. Time is injected so tests are deterministic."""
    def __init__(self, capacity, ttl, clock):
        super().__init__(capacity)
        self.ttl, self.clock = ttl, clock
    def put(self, key, value):
        super().put(key, (value, self.clock() + self.ttl))
    def get(self, key):
        item = super().get(key)
        if item is None:
            return None
        value, expires = item
        if self.clock() >= expires:
            self._expire(key)
            return None
        return value
    def _expire(self, key):
        n = self._map.pop(key)
        self._unlink(n)


def hit_rate(cache, keys):
    hits = 0
    for k in keys:
        if cache.get(k) is not None:
            hits += 1
        else:
            cache.put(k, k)
    return hits / len(keys)

t = [0]

## What the output shows

- After `put a,b,c`, `get a`, `put d` in a cache of 3, the recency order is **d, a, c** and **b was evicted**: the least recently used key, not the oldest.
- The **eviction callback** reports that key 2 was evicted when key 3 arrived, after key 1 was touched.
- The **20,000-operation model check** passes: the hand-built list and map agree with `OrderedDict` on every get result and on the entire recency order after every operation. This is how you gain confidence in pointer code: compare it with a simple, obviously correct model on random input.
- The **TTL** cache returns the value at time 9 and treats it as expired at time 10 (and removes it).
- On a **Zipf-like workload** (a few keys are very popular, with a long tail) over 1,000 keys and a cache of 50, **LRU hits 45.6% against FIFO's 40.1%**.
- On a workload that mixes a **hot set of 20 keys** (70% of accesses) with **one-off scan keys** (30%), **LRU hits 69.4% against 60.1%**: LRU keeps touched keys, FIFO throws them out when they were inserted long ago.
- On a **loop over 51 keys with a cache of 50** both hit **0%**: with a cyclic pattern one larger than the cache, each key is evicted just before it is needed again. LRU is **not** a universal winner.

The numbers are from one run with fixed random seeds, so they are exactly reproducible, but they describe these synthetic workloads, not your traffic. Always measure with a trace of your own requests.

## Concurrency

`get` **mutates** the structure (it moves a node), so a cache hit is a write. Two threads calling `get` at once can corrupt the pointers. Options:

1. **One lock** around `get` and `put`. Simple and correct, the right first answer. (`functools.lru_cache` in the standard library does this for you.)
2. **Sharding**: split keys over N independent LRU caches by hash, each with its own lock. Contention drops by roughly N, at the cost of an eviction order that is only approximate across shards (each shard evicts its own least recently used key).
3. **Approximate LRU**: sample a few random entries and evict the oldest of the sample (Redis does this), or use a clock bit. Cheaper to maintain, slightly worse hit rate.
4. **Buffered recency updates**: record accesses in a buffer and apply them in batches, so readers do not contend on one lock (the idea behind modern libraries such as Caffeine in Java).

## Extending the design

| requirement | change |
| --- | --- |
| **Expiry (TTL)** | store an expiry time with the value; check on `get` (lazy expiry) and optionally sweep in the background so dead entries do not occupy space |
| **Different eviction policy** | the policy is "who is the victim?". Extract an `EvictionPolicy` interface (LRU, LFU, FIFO, random) and inject it ([strategy](/sd/oop-and-design-patterns/behavioral-patterns/)) |
| **LFU instead of LRU** | keep a frequency count; use buckets of nodes per frequency to stay O(1) |
| **Eviction callback** | an `on_evict` hook, used to write dirty entries back or to count evictions |
| **Weighted entries (size in bytes)** | capacity is a total weight; evict from the tail until the new entry fits |
| **Write-through or write-back** | a loader and a writer interface around the cache ([cache strategies](/sd/caching/caching-strategies/)) |
| **Statistics** | hit and miss counters, exposed as metrics ([observability](/sd/observability/logs-metrics-and-traces/)) |
| **Distributed** | shard keys over machines with [consistent hashing](/sd/databases-2/consistent-hashing/); each node runs a local LRU |

For the policy comparison in more depth see the [eviction policies](/sd/caching/eviction-policies/) lesson.

## Pitfalls

- Forgetting that `get` must **move the node to the front**; without it this is FIFO.
- Evicting the tail but **not deleting its key from the map** (hence the node stores its key).
- Updating an existing key by **inserting a second node** instead of updating and moving the first.
- Evicting when merely **updating** an existing key, or checking the capacity after inserting instead of before.
- Using `None` both as "missing" and as a stored value; real caches return a sentinel or a pair.
- Edge cases: capacity 1, updating the key already at the head, a `get` for a missing key.
- Calling `get` from several threads without a lock, since `get` is a write.
- Trusting LRU to help against a **sequential scan** or a loop slightly larger than the cache.
