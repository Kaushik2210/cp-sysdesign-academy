## Intuition

A recursive algorithm's running time is itself recursive: "to sort `n` items, sort two halves and then merge." Writing that as an equation,

```text
T(n) = 2 * T(n / 2) + n
```

is called a **recurrence**. To get a closed form, draw the recursion tree and add up the work level by level. Three things matter: how many subproblems (`a`), how much smaller they are (`b`), and how much work is done outside the recursive calls (`f(n)`).

## The recursion tree

For `T(n) = 2T(n/2) + n`:

```text
level 0:  1 problem of size n        work n
level 1:  2 problems of size n/2     work 2 * n/2 = n
level 2:  4 problems of size n/4     work 4 * n/4 = n
...
level k:  2^k problems of size n/2^k work n
```

There are `log2 n` levels, each costing `n`, so `T(n) = Theta(n log n)`. Every level costs the same; this is the signature of merge sort.

## The Master Theorem

For `T(n) = a * T(n / b) + f(n)` with constants `a >= 1`, `b > 1`, let `c* = log_b(a)`; the quantity `n^c*` is the cost of the leaves. Compare it with `f(n)`:

| Case | Condition | Result | Intuition |
| --- | --- | --- | --- |
| 1 | `f(n) = O(n^(c* - e))` for some `e > 0` | `T(n) = Theta(n^c*)` | leaves dominate |
| 2 | `f(n) = Theta(n^c* * log^k n)`, `k >= 0` | `T(n) = Theta(n^c* * log^(k+1) n)` | all levels comparable |
| 3 | `f(n) = Omega(n^(c* + e))` and `a * f(n/b) <= d * f(n)` for some `d < 1` | `T(n) = Theta(f(n))` | root dominates |

(The extra condition in case 3 is the *regularity* condition; it holds for ordinary polynomials.)

### Examples

| Algorithm | Recurrence | `a, b, c*` | `f(n)` vs `n^c*` | Result |
| --- | --- | --- | --- | --- |
| Binary search | `T(n) = T(n/2) + 1` | `1, 2, 0` | `1 = n^0` (case 2, `k = 0`) | `Theta(log n)` |
| Merge sort | `T(n) = 2T(n/2) + n` | `2, 2, 1` | `n = n^1` (case 2) | `Theta(n log n)` |
| Tree traversal / max of array by halves | `T(n) = 2T(n/2) + 1` | `2, 2, 1` | `1 < n^1` (case 1) | `Theta(n)` |
| Quickselect with perfect halving | `T(n) = T(n/2) + n` | `1, 2, 0` | `n > n^0` (case 3) | `Theta(n)` |
| Karatsuba multiplication | `T(n) = 3T(n/2) + n` | `3, 2, 1.585` | `n < n^1.585` (case 1) | `Theta(n^1.585)` |
| Strassen matrix multiplication | `T(n) = 7T(n/2) + n^2` | `7, 2, 2.807` | case 1 | `Theta(n^2.807)` |
| Naive 8-way matrix multiplication | `T(n) = 8T(n/2) + n^2` | `8, 2, 3` | case 1 | `Theta(n^3)` |
| Segment tree build | `T(n) = 2T(n/2) + 1` | same as tree traversal | case 1 | `Theta(n)` |

## Recurrences the master theorem does not cover

Subtracting a constant instead of dividing by one:

| Recurrence | Closed form | Reason |
| --- | --- | --- |
| `T(n) = T(n-1) + 1` | `Theta(n)` | unroll: `n` terms of 1 |
| `T(n) = T(n-1) + n` | `Theta(n^2)` | `1 + 2 + ... + n` (insertion sort worst case) |
| `T(n) = 2T(n-1) + 1` | `Theta(2^n)` | every call makes two; Towers of Hanoi |
| `T(n) = T(n-1) + T(n-2) + 1` | `Theta(phi^n)`, `phi ~ 1.618` | naive Fibonacci |
| `T(n) = T(sqrt n) + 1` | `Theta(log log n)` | repeated square roots |

For naive Fibonacci the number of calls is `2F(n+1) - 1`; measure it:

<CodeRunner snippets={{ python: `calls = 0

for n in (10, 20, 25):

    fib(n)
    print(n, calls)       # 177, 21891, 242785

## Uneven splits and the average case

Quicksort with a random pivot splits `n` into pieces of sizes `k` and `n - 1 - k`. If the pivot is always the minimum, `T(n) = T(n-1) + n = Theta(n^2)`. With an expected balanced split `T(n) = 2T(n/2) + n` giving `Theta(n log n)`. Even a constant-ratio split, such as `T(n) = T(n/10) + T(9n/10) + n`, gives `Theta(n log n)`: the tree is lopsided but its depth is still logarithmic and each level costs at most `n`. The master theorem does not apply directly, but the recursion tree does (the general tool is the Akra-Bazzi theorem).

## Using it in practice

1. Write the recurrence for time (and separately for memory: recursion depth plus extra arrays).
2. Identify `a`, `b`, `f(n)`.
3. Compute `n^(log_b a)` and compare with `f(n)`.
4. If the recurrence does not fit, draw the tree or unroll.

**Merge-sort-style counting** (the practice problem): inversions count uses the same split, count, merge pattern, so it inherits `Theta(n log n)` time and `Theta(n)` extra memory.

## Pitfalls

1. **Master theorem needs equal-size subproblems.** `T(n) = T(n/3) + T(2n/3) + n` is not in the standard form.
2. **Gaps between cases.** `f(n) = n / log n` with `a = b = 2` sits between cases 1 and 2; the theorem gives no answer (the real answer is `Theta(n log log n)`).
3. **Forgetting `f(n)`.** Cost outside recursion (copying slices, building lists) belongs in `f(n)`. Python's `arr[:mid]` makes each call `Theta(n)` even if the algorithm "just splits".
4. **Mixing up `log` bases.** Base changes only a constant, but exponent `log_b a` is a real exponent: `n^(log_2 3)` is not `n^(log_3 2)`.
5. **Recursion depth.** An `O(n)` deep recursion overflows the stack in Python at about 1000 frames by default and in other languages at around `10^5` to `10^6`.
