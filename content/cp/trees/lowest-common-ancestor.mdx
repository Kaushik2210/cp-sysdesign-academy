## Intuition

In a company tree, two employees' **meeting point** is the lowest manager above both. In a file system, it is the deepest folder that contains two files. In a family tree, the closest shared ancestor. This is the **lowest common ancestor** (LCA).

The slow way walks both vertices up one step at a time: `O(depth)` per query, which is `O(n)` on a long chain. Binary lifting makes each query `O(log n)` with a precomputed table of **jump pointers**: every vertex knows its 1st, 2nd, 4th, 8th, ... ancestor.

## Definition

Root the tree at `1`. Let `up[k][v]` be the `2^k`-th ancestor of `v` (the root points to itself, so jumping past it is harmless).

```text
up[0][v] = parent(v)
up[k][v] = up[k-1][ up[k-1][v] ]      (two jumps of 2^(k-1))
```

There are about `log2(n)` levels, so building takes `O(n log n)` time and memory. Also store `depth[v]`.

**Query `LCA(u, v)`**

1. Make `u` the deeper one. Lift it by `depth[u] - depth[v]`, taking one jump per set bit of the difference. Now both are at the same depth.
2. If `u == v`, that is the answer: one was an ancestor of the other.
3. Otherwise, for `k` from the highest level down to `0`: if `up[k][u] != up[k][v]`, jump both. They stop just **below** the LCA.
4. The answer is `up[0][u]`.

Step 3 is a binary search on "how far can both rise while still being different": jumps that would land on the same vertex (the LCA or above) are refused.

```python
LOG = max(1, n.bit_length())
up = [[1] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)
for v in range(2, n + 1):                    # parents have smaller numbers
    up[0][v] = parent[v]
    depth[v] = depth[parent[v]] + 1
for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k - 1][up[k - 1][v]]

def lca(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    diff = depth[u] - depth[v]
    for k in range(LOG):
        if diff >> k & 1:
            u = up[k][u]
    if u == v:
        return u
    for k in range(LOG - 1, -1, -1):
        if up[k][u] != up[k][v]:
            u, v = up[k][u], up[k][v]
    return up[0][u]
```

    for (int k = 0; k < LOG; k++) if ((diff >> k) & 1) u = up[k][u];

## What the table also gives you

1. **The k-th ancestor** of any vertex in `O(log n)`: jump along the set bits of `k`.
2. **Distance between two vertices:** `depth[u] + depth[v] - 2 * depth[lca]`.
3. **Is `a` an ancestor of `b`?** `lca(a, b) == a`.
4. **Path queries** with extra tables (for example the maximum edge weight on each jump).

| method | build | query | notes |
| --- | --- | --- | --- |
| walk up | none | `O(depth)` | fine for tiny or shallow trees |
| binary lifting | `O(n log n)` | `O(log n)` | simple, also gives k-th ancestors |
| Euler tour + sparse table | `O(n log n)` | `O(1)` | fastest queries, more code |
| offline Tarjan (with [union-find](/cp/graphs/union-find/)) | `O(n + q)` | amortized almost constant | all queries known in advance |

## Pitfalls

1. **Making the root's parent `0`.** Jumping past the root must stay at the root (point it to itself), or the comparison `up[k][u] != up[k][v]` breaks.
2. **Too few levels.** You need `LOG` with `2^LOG > n`, so a path of length `n - 1` can be lifted.
3. **Skipping the equal-depth step.** The "jump while different" loop is only valid when both are at the same depth.
4. **Returning `u` instead of `up[0][u]`** after the loop. At that point both are just below the LCA.
5. **Recursive DFS for depths on a path of `10^5` vertices** overflows the recursion limit in Python; use the input order if parents are numbered smaller, or an explicit stack.
6. **Memory.** `n * log n` ints is fine up to `2·10^5` in compiled languages; in Python use flat lists or `array`.
