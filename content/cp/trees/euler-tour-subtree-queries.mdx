## Intuition

A company tree: "what is the total bonus of this manager's whole team?" Walking down the tree for every question costs the size of the team, which for the CEO is everyone.

Here is the trick. Number the employees in the order a depth-first search **first visits** them. Everyone in the team of `v` is visited after `v` and **before the search leaves `v`**. So the team of `v` is a **contiguous block** of numbers: `v` itself followed by all of its descendants. A tree question becomes an **array range** question, and we already have tools for those: prefix sums, [Fenwick trees](/cp/range-queries/fenwick-trees/) and [segment trees](/cp/range-queries/segment-trees/).

## Definition

Run a depth-first search from the root and keep a counter.

- `tin[v]`: the counter value when the search **enters** `v`.
- `tout[v]`: the counter value when it **leaves** `v` (or equivalently `tin[v] + size[v] - 1`).

Then `u` lies in the subtree of `v` exactly when `tin[v] <= tin[u] <= tout[v]`, and the subtree of `v` is the range `[tin[v], tin[v] + size[v] - 1]` of the flattened array.

```text
          1                 tour:  1  2  4  5  3  6
        /   \                       tin: 1->1  2->2  4->3  5->4  3->5  6->6
       2     3              subtree of 2 = positions 2..4  (vertices 2, 4, 5)
      / \     \             subtree of 3 = positions 5..6  (vertices 3, 6)
     4   5     6
```

With that array:

| query | how |
| --- | --- |
| sum of a subtree | range sum over `[tin[v], tout[v]]` |
| change one vertex's value | point update at `tin[v]` |
| add a value to a whole subtree | range update (a difference array, or a Fenwick tree on differences) |
| is `a` an ancestor of `b`? | `tin[a] <= tin[b] <= tout[a]`, in `O(1)` |
| size of a subtree | `tout[v] - tin[v] + 1` |

## Computing tin and tout

Recursion overflows on a path of `10^5` vertices in Python, so use an explicit stack.

<Tabs>
<Tab label="Python">

```python
def euler(n, children):                 # vertices 1..n, root 1
    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    timer = 0
    stack = [(1, 0)]                    # (vertex, index of the next child to visit)
    while stack:
        v, i = stack.pop()
        if i == 0:
            timer += 1
            tin[v] = timer
        if i < len(children[v]):
            stack.append((v, i + 1))
            stack.append((children[v][i], 0))
        else:
            tout[v] = timer             # the last position used inside the subtree of v
    return tin, tout
```

function<void(int)> dfs = [&](int v) {

<Tab label="Java">

```java
int[] tin = new int[n + 1], tout = new int[n + 1];
int timer = 0;
int[] it = new int[n + 1];              // next child index per vertex
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
tin[1] = ++timer;
while (!stack.isEmpty()) {
    int v = stack.peek();
    if (it[v] < children[v].size()) {
        int c = children[v].get(it[v]++);
        tin[c] = ++timer;
        stack.push(c);
    } else {
        tout[v] = timer;
        stack.pop();
    }
}
```

**A shortcut when parents have smaller numbers.** If every parent's number is smaller than its child's (`p[v] < v`), no search is needed: compute `size[v]` with the backward loop `size[p[v]] += size[v]`, then hand out positions with the forward loop `tin[v] = next[p[v]]; next[p[v]] += size[v]; next[v] = tin[v] + 1`. This is what the practice problem uses.

Run the whole idea, with subtree sums and updates in a Fenwick tree checked against a brute force:

## More uses of the flattened tree

1. **Subtree updates:** add `x` to every vertex of a subtree with a range update.
2. **Path queries from the root:** with a Fenwick tree on differences, an update on a subtree adds to every descendant, and a point query gives the sum along the root path.
3. **Counting distinct values in subtrees** (offline, with a sorted query order) and **small-to-large merging**.
4. **Ancestor tests** in `O(1)`, used by LCA variants and by problems that ask "is `a` on the path to `b`?".
5. The full **Euler tour** that records a vertex every time the walk passes it (`2n - 1` entries) combined with a sparse table gives `O(1)` LCA.

<Callout type="tip" title="Subtree = range, path = something else">
The flattening works for *subtrees*. A path between two arbitrary vertices is not contiguous in the tour. Paths need LCA, binary lifting or heavy-light decomposition.
</Callout>

## Pitfalls

1. **Recursive DFS on deep trees.** A path of `10^5` vertices overflows the recursion limit in Python and can overflow the stack in C++ and Java.
2. **Off-by-one in the range.** The subtree is `[tin, tin + size - 1]`; using `tin + size` includes the next vertex.
3. **Mixing 0-based and 1-based positions** with a Fenwick tree, which needs 1-based positions.
4. **Assuming `tin` equals the vertex number.** It is the visit order, which depends on the order children are visited.
5. **Setting instead of adding.** A Fenwick tree supports `add`; to set a value add `new - old`.
6. **Forgetting disconnected input.** A tree is connected; if the problem gives a forest, run a search from every root.
