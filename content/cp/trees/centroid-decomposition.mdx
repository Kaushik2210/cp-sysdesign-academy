## Intuition

Many tree questions are about **all paths**: how many paths have length exactly `K`, what is the longest path with a given property, which vertex is the nearest marked one. Starting a search from every vertex costs `O(n^2)`.

Divide and conquer works on arrays by cutting in the middle. On a tree the right place to cut is the **centroid**, the vertex whose removal splits the tree into pieces that are all **at most half** as big. Every path in the tree then does one of two things: it **passes through the centroid**, or it lies **entirely inside one piece**. Paths through the centroid are easy to handle together, since they all share that one vertex. The other paths are the same problem on smaller trees, and each vertex is in only `log n` of those subproblems because pieces halve.

## Definition

A **centroid** of a tree with `m` vertices is a vertex `c` such that every component of the tree minus `c` has at most `m / 2` vertices. A centroid always exists: start anywhere and keep moving to a neighbour whose side holds more than `m / 2` vertices; the walk cannot go back and must stop.

**Decomposition.**

```text
solve(component):
    c = centroid of the component
    count / aggregate all paths that pass through c        # cost: O(size of the component)
    remove c
    for each piece left:  solve(piece)
```

Every removal at least halves the component size, so the recursion has depth `O(log n)` and each vertex belongs to `O(log n)` components. If the work per component is linear in its size, the total is `O(n log n)`.

The vertices picked as centroids form the **centroid tree**: each centroid's parent is the centroid of the component it was removed from. It has depth at most `log2(n) + 1`, and for any two vertices `u`, `v`, the path between them passes through their lowest common ancestor in the centroid tree.

**Counting paths of length exactly `K` through `c`.** Keep `cnt[d]`, the number of vertices at depth `d` (distance from `c`) in the branches handled so far, starting with `cnt[0] = 1` for `c` itself. For each branch of `c`:

1. For every vertex at depth `d` in the branch, add `cnt[K - d]` to the answer: these are partners in **earlier** branches or `c`.
2. Only after the whole branch is scanned, add its depths into `cnt`.

Step 2 must come after step 1, otherwise two vertices of the **same** branch would be paired, and their path does not go through `c`.

## Example, step by step

Tree with 5 vertices and edges `1-2, 1-3, 3-4, 3-5`; count pairs at distance `K = 2`.

Root the component at 1: subtree sizes are `1: 5`, `3: 3`, others 1 or 1. The child `3` holds `3 > 5 / 2` vertices, so move to 3; its children hold 1 each, so the centroid is **3**.

Branches of 3: `{1, 2}` (via 1), `{4}`, `{5}`. Depths from 3: vertex 1 at 1, vertex 2 at 2, vertices 4 and 5 at 1.

| branch | scan | pairs found | `cnt` after the branch |
| --- | --- | --- | --- |
| start | | | `cnt[0] = 1` |
| `{1, 2}` | vertex 1 (d = 1): `cnt[1] = 0`; vertex 2 (d = 2): `cnt[0] = 1` | 1: `(2, 3)` | `cnt[1] = 1`, `cnt[2] = 1` |
| `{4}` | vertex 4 (d = 1): `cnt[1] = 1` | 1: `(1, 4)` | `cnt[1] = 2` |
| `{5}` | vertex 5 (d = 1): `cnt[1] = 2` | 2: `(1, 5)`, `(4, 5)` | `cnt[1] = 3` |

Four pairs, all through centroid 3. Then 3 is removed and the pieces `{1, 2}`, `{4}`, `{5}` are processed the same way; none contains a pair at distance 2. Answer: **4**.

## Code

Recursion on a path-shaped tree is `n` deep, so this version uses a stack of components and BFS.

```python
removed = [False] * (n + 1)
par = [0] * (n + 1); sz = [0] * (n + 1)
ans = 0
stack = [1]
while stack:
    r = stack.pop()
    comp = [r]; par[r] = 0
    for v in comp:                                   # BFS the current component
        for to in adj[v]:
            if not removed[to] and to != par[v]:
                par[to] = v; comp.append(to)
    total = len(comp)
    for v in comp: sz[v] = 1
    for v in reversed(comp):
        if par[v]: sz[par[v]] += sz[v]
    c = r                                            # find the centroid
    while True:
        nxt = 0
        for to in adj[c]:
            if not removed[to] and to != par[c] and sz[to] * 2 > total:
                nxt = to; break
        if not nxt: break
        c = nxt
    cnt = [0] * (total + 1); cnt[0] = 1
    for to in adj[c]:                                # paths through c, branch by branch
        if removed[to]: continue
        q = [(to, c, 1)]; depths = []
        for v, p, d in q:
            depths.append(d)
            if 0 <= K - d <= total: ans += cnt[K - d]
            for nb in adj[v]:
                if not removed[nb] and nb != p: q.append((nb, v, d + 1))
        for d in depths: cnt[d] += 1                 # after the branch has been counted
    removed[c] = True
    for to in adj[c]:
        if not removed[to]: stack.append(to)
```

## What else the centroid tree gives you

| task | idea |
| --- | --- |
| count paths of length `K` (this lesson) | `cnt` array per centroid |
| count paths with length in `[L, R]` | the same, with a Fenwick tree over depths instead of `cnt[K - d]` |
| nearest marked vertex, with marking updates | for each vertex store its distance to every centroid ancestor (`log n` values); marking `v` updates `best[c]` for each ancestor `c`, a query takes `min(best[c] + dist(v, c))` |
| path with a maximum or minimum of some value | keep, per depth, the best value seen so far; combine with the current branch |
| assign labels so that equal labels have a larger label on the path | the centroid tree depth gives the label (Codeforces 321C) |

## Pitfalls

1. **Counting a branch against itself.** Add a branch's depths to `cnt` only after scanning it. Otherwise pairs inside one branch (whose path avoids the centroid) are counted.
2. **Forgetting the centroid itself.** `cnt[0] = 1` accounts for pairs `(c, v)`.
3. **Using a non-centroid.** Splitting at an arbitrary vertex gives `O(n^2)` on a path; the half-size guarantee needs a real centroid.
4. **Stale sizes.** After removing a vertex the subtree sizes must be recomputed for each component (they are, in the BFS pass above), not reused from the whole tree.
5. **Array bounds.** Depths are below the component size, so `cnt` of length `total + 1` is enough; guard `K - d` against negative or too large.
6. **Recursion depth.** The recursive version overflows on a path of `2·10^5` vertices when computing sizes. Use BFS order and an explicit stack, as above.
7. **Overflow.** A star with `K = 2` has about `n^2 / 2` pairs: use 64-bit counts.
