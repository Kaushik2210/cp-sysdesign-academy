## Intuition

[Euler tours](/cp/trees/euler-tour-subtree-queries/) turn **subtree** questions into array ranges. A **path** between two vertices is different: it goes up from `u` to a common ancestor and down to `v`, and the vertices of that path are scattered all over any Euler order.

The remedy: cut the tree into **vertical chains** and lay each chain out as a contiguous block of an array. A path then becomes a handful of pieces, each a contiguous range of one chain, and a segment tree answers each piece. The cutting rule that guarantees few pieces: from every vertex, keep the edge to its **heaviest child** (the one with the biggest subtree) and cut the rest. Light edges are rare on any path, because each light edge at least **halves** the subtree size you are in, so a path can cross at most `log2(n)` of them.

## Definition

Root the tree. For every vertex `v`:

- `size[v]`: number of vertices in its subtree.
- `heavy[v]`: the child with the largest `size` (or none for a leaf). The edge `v -> heavy[v]` is a **heavy edge**, all other child edges are **light**.
- Heavy edges form vertical **chains**. Every vertex is on exactly one chain (a leaf alone is a chain of one).
- `head[v]`: the top vertex of the chain containing `v`.
- `pos[v]`: the index of `v` in a global array, assigned so that **every chain occupies consecutive positions, top first**.

**Light edge bound.** Going from a vertex up to the root, every time you leave a chain through a light edge, the parent's subtree is more than twice as large as the child's (otherwise the child would have been heavy). So at most `log2(n)` chains are visited.

**Path query `u..v`** (here: maximum):

```text
res = -infinity
while head[u] != head[v]:
    if depth[head[u]] < depth[head[v]]:  swap(u, v)          # move the one whose chain top is deeper
    res = max(res, range_query(pos[head[u]], pos[u]))        # the whole chain piece from its top down to u
    u = parent[head[u]]                                      # jump over the light edge
if depth[u] > depth[v]:  swap(u, v)
res = max(res, range_query(pos[u], pos[v]))                  # same chain: one last contiguous range
```

Each loop iteration is one chain piece and costs one segment-tree query `O(log n)`, so a query costs `O(log^2 n)`. A **point update** is just a segment-tree point update, `O(log n)`.

For **edge weights**, store each edge's weight on its **deeper endpoint** and exclude the top vertex (the LCA) in the final range.

## Example, step by step

Tree with 9 vertices (root 1):

```text
1: children 2, 3
2: children 4, 5
5: children 6, 7
3: child 8
8: child 9
```

Subtree sizes: `size = [9, 5, 3, 1, 3, 1, 1, 2, 1]` for vertices `1..9`. Heavy children: `1 -> 2` (size 5 beats 3), `2 -> 5` (3 beats 1), `5 -> 6` (tie with 7, the first wins), `3 -> 8`, `8 -> 9`.

Chains (head, top first) and their positions:

| chain | vertices | head | positions |
| --- | --- | --- | --- |
| A | `1, 2, 5, 6` | 1 | 0, 1, 2, 3 |
| B | `3, 8, 9` | 3 | 4, 5, 6 |
| C | `4` | 4 | 7 |
| D | `7` | 7 | 8 |

Query the path **4 to 9** (it is `4, 2, 1, 3, 8, 9`):

1. `head[4] = 4`, `head[9] = 3`, different. The deeper head is 4 (depth 2 versus 1): query positions `[7, 7]`, then `u = parent[4] = 2`.
2. `head[2] = 1`, `head[9] = 3`, different. Now `v = 9`'s head is deeper (depth 1 vs 0): query positions `[pos[3], pos[9]] = [4, 6]`, then `v = parent[3] = 1`.
3. `head[2] = head[1] = 1`: same chain. `1` is shallower, so one last query `[pos[1], pos[2]] = [0, 1]`.

Three range queries for a path of six vertices. On a million-vertex tree the same loop needs at most about 20 pieces.

parent = [0] * (n + 1); depth = [0] * (n + 1)
order = [1]; seen = [False] * (n + 1); seen[1] = True
for v in order:                                   # BFS: parents come before children
    for to in adj[v]:
        if not seen[to]:
            seen[to] = True; parent[to] = v; depth[to] = depth[v] + 1; order.append(to)

size = [1] * (n + 1); heavy = [0] * (n + 1)
for v in reversed(order[1:]):
    size[parent[v]] += size[v]
for v in order[1:]:
    p = parent[v]
    if heavy[p] == 0 or size[v] > size[heavy[p]]:
        heavy[p] = v

head = [0] * (n + 1); pos = [0] * (n + 1); cur = 0
for v in order:                                   # each chain top lays out its whole chain
    if v == 1 or heavy[parent[v]] != v:
        u = v
        while u:
            head[u] = v; pos[u] = cur; cur += 1
            u = heavy[u]

def path_max(u, v):                               # seg_query(l, r) = max over positions l..r
    res = NEG
    while head[u] != head[v]:
        if depth[head[u]] < depth[head[v]]:
            u, v = v, u
        res = max(res, seg_query(pos[head[u]], pos[u]))
        u = parent[head[u]]
    if depth[u] > depth[v]:
        u, v = v, u
    return max(res, seg_query(pos[u], pos[v]))

    def update(self, v, x):
        i = self.size_t + self.pos[v]
        self.tree[i] = x
        i >>= 1
        while i:
            self.tree[i] = max(self.tree[2 * i], self.tree[2 * i + 1])

        l += self.size_t
        r += self.size_t + 1
        while l < r:
            if l & 1:
                res = max(res, self.tree[l])
                l += 1
            if r & 1:
                r -= 1
                res = max(res, self.tree[r])
            l >>= 1
            r >>= 1

## Where HLD pays off

| query | what to store |
| --- | --- |
| max or min on a path, point update | segment tree over positions (this lesson) |
| sum on a path, point or range update | Fenwick tree or lazy [segment tree](/cp/range-queries/lazy-propagation/) |
| add a value to every vertex on a path | lazy segment tree, same `O(log^2 n)` loop |
| subtree query | one range `[pos[v], pos[v] + size[v] - 1]` when children are visited **heavy first**, so HLD also gives an Euler order |
| LCA | the same loop; the answer is the shallower of `u`, `v` at the end, usually faster than binary lifting |
| edge weights | store on the deeper endpoint, query `pos[u] + 1` in the final range |

If you only need LCA or only subtree sums, an [Euler tour](/cp/trees/euler-tour-subtree-queries/) or binary lifting is simpler. HLD is the tool for **path aggregates with updates**.

## Pitfalls

1. **Wrong chain top to move.** Always move the vertex whose **chain head** is deeper, not the deeper vertex itself; otherwise you can jump past the LCA.
2. **Final range orientation.** After the loop `u` and `v` are on one chain; swap so `u` is the shallower, then query `[pos[u], pos[v]]`. A reversed range returns nothing.
3. **Positions must be contiguous per chain.** Assigning positions during an arbitrary DFS order breaks that; either walk each chain from its head (as above) or visit the heavy child first in a DFS.
4. **Edge versus vertex weights.** For edges, the LCA's own value must be excluded from the last range.
5. **Recursion depth.** The recursive formulation overflows the stack on a path of `2·10^5` vertices. Use BFS order as here, or an explicit stack.
6. **Segment tree identity.** Use a value below every possible weight (`-10^18`, not `0`) for a maximum, or negative weights break.
7. **Forgetting `log^2`.** Path queries cost `O(log^2 n)`, which is fine for `q = 2·10^5`; for harder limits combine with a segment tree that supports `O(1)` or `O(log)` per chain.
