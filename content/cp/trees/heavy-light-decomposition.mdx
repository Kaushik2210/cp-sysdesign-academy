## Intuition

A segment tree answers "maximum over positions `l..r`" in `O(log n)`, but only for a **line** of elements. On a **tree**, the question "what is the largest value on the path between `u` and `v`?" is about a path that bends up and down. Walking it vertex by vertex costs `O(n)` per query, which is hopeless if the tree is a long chain and you ask `10^5` times.

**Heavy-light decomposition** (HLD) cuts the tree into a few **vertical chains** so that every path from a vertex up to the root crosses only `O(log n)` of them. Lay each chain out as a contiguous stretch of an array and a path becomes `O(log n)` array ranges, each answered by a segment tree. Total per query: `O(log^2 n)`.

## Definition

Root the tree. For every vertex `v` let `size[v]` be the number of vertices in its subtree.

- The **heavy child** of `v` is the child with the largest `size`. (Leaves have none.)
- An edge from `v` to its heavy child is a **heavy edge**; every other parent-child edge is a **light edge**.
- Following heavy edges partitions the vertices into vertical **chains**. Each vertex is on exactly one chain, and each chain has a topmost vertex, its **head**.

**Key lemma.** Going from any vertex up to the root crosses at most `log2 n` light edges. Why: moving along a light edge from a child `c` to its parent `p`, the heavy child of `p` has `size` at least as large as `c`'s, so `size[p] >= 2 * size[c] + 1`. The subtree size at least doubles with every light edge, and it cannot exceed `n`.

Number the vertices so that **each chain occupies consecutive positions, head first**. Then the segment tree built over these positions can aggregate any piece of a chain with one range query.

## Query on a path `u -> v`

```text
res = identity
while head[u] != head[v]:
    if depth[head[u]] < depth[head[v]]: swap(u, v)      # move the one whose chain head is deeper
    res = combine(res, range(pos[head[u]], pos[u]))      # the piece of u's chain from its head down to u
    u = parent[head[u]]                                  # jump over the light edge above the head
# now u and v are on the same chain
if depth[u] > depth[v]: swap(u, v)
res = combine(res, range(pos[u], pos[v]))
```

Each loop iteration crosses one light edge from one of the two endpoints, so there are at most `2 * log2 n` iterations, each costing one `O(log n)` segment-tree query: **`O(log^2 n)`** per path query. Point updates cost `O(log n)`.

The loop ends exactly at the **lowest common ancestor**: the shallower of the final `u` and `v` is the LCA. HLD is therefore also a compact `O(log n)` LCA method with no extra table.

## Building it without recursion

On a path of `10^5` vertices, a recursive DFS overflows the stack. Compute everything with explicit stacks:

1. **Parents, depths and a preorder** with a stack-based DFS from the root.
2. **Subtree sizes and heavy children**: process the preorder in **reverse**; add each vertex's `size` to its parent's and track the parent's largest child.
3. **Positions**: walk the preorder; every time you meet a vertex that is the root or is *not* its parent's heavy child, it is a chain head: follow heavy children downward, assigning `head` and consecutive positions.

## Example, step by step

Tree: `0` with children `1`, `2`; `1` with children `3`, `4`; `2` with children `5`, `6` (a balanced tree of 7 vertices).

- Sizes: leaves 1; vertices `1` and `2` have 3; the root has 7. Where two children tie, either may be chosen; say the heavy children are `0 -> 1`, `1 -> 3`, `2 -> 5`.
- Chains: `0, 1, 3` (head 0), `4` (head 4), `2, 5` (head 2), `6` (head 6).
- Query from `4` to `5`: heads `4` and `2` differ. `4`'s head is deeper than `2`'s (depth 2 vs 1), so take the piece `[4]` and jump to `parent[4] = 1`. Now `u = 1` (head 0) and `v = 5` (head 2): `5`'s chain head `2` is deeper than `0`, so query the piece `[2, 5]` and jump to `parent[2] = 0`. Now both are on the chain headed by `0`: the final piece is positions of `0` and `1`. The route `4 - 1 - 0 - 2 - 5` was covered by three ranges: `{4}`, `{2, 5}`, `{0, 1}`. The LCA is `0`.

# adj, n, val are given; the tree is rooted at 0
parent = [-1] * n
depth = [0] * n
order, stack = [], [0]
while stack:
    u = stack.pop()
    order.append(u)
    for v in adj[u]:
        if v != parent[u]:
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)

size, heavy = [1] * n, [-1] * n
for u in reversed(order):
    p = parent[u]
    if p >= 0:
        size[p] += size[u]
        if heavy[p] == -1 or size[u] > size[heavy[p]]:
            heavy[p] = u

head, pos, cur = [0] * n, [0] * n, 0
for u in order:
    if parent[u] == -1 or heavy[parent[u]] != u:       # u heads a chain
        v = u
        while v != -1:
            head[v], pos[v] = u, cur
            cur += 1
            v = heavy[v]

# segment tree over `pos`: tree[n + pos[u]] = val[u]; range_max(l, r) inclusive
def path_max(u, v):
    res = NEG
    while head[u] != head[v]:
        if depth[head[u]] < depth[head[v]]:
            u, v = v, u
        res = max(res, range_max(pos[head[u]], pos[u]))
        u = parent[head[u]]
    if depth[u] > depth[v]:
        u, v = v, u
    return max(res, range_max(pos[u], pos[v]))

    """Heavy-light decomposition with a segment tree for maximum, built without recursion."""
    def __init__(self, n, edges, val):

            order.append(u)

                size[p] += size[u]

        i = self.pos[u] + self.n
        self.tree[i] = x
        i //= 2

        res, l, r = -10**18, l + self.n, r + self.n + 1

    def path_max(self, u, v):
        res, jumps = -10**18, 0
        while self.head[u] != self.head[v]:
            if self.depth[self.head[u]] < self.depth[self.head[v]]:
                u, v = v, u
            res = max(res, self._range_max(self.pos[self.head[u]], self.pos[u]))
            u = self.parent[self.head[u]]

        return max(res, self._range_max(self.pos[u], self.pos[v])), jumps

        while self.head[u] != self.head[v]:
            if self.depth[self.head[u]] < self.depth[self.head[v]]:
                u, v = v, u
            u = self.parent[self.head[u]]
        return u if self.depth[u] < self.depth[v] else v

def brute_path_max(h, val, u, v):
    res = -10**18
    while u != v:
        if h.depth[u] < h.depth[v]: u, v = v, u
        res = max(res, val[u]); u = h.parent[u]
    return max(res, val[u])

## Variations

| question | what changes |
| --- | --- |
| path sum, path xor, path gcd | any **associative** operation works; replace `max` in the segment tree. For non-commutative operations, remember which direction each piece is traversed. |
| values on **edges** | store the edge's value on the **child** endpoint; in the last same-chain query skip the position of the LCA itself (`pos[u] + 1 .. pos[v]`). |
| **subtree** query or update | give the heavy child the first DFS slot so that every subtree is a contiguous block `[pos[v], pos[v] + size[v] - 1]`; then subtree and path queries share one segment tree. |
| range **add** on a path | use a segment tree with lazy propagation (see the lazy propagation lesson) and the same `O(log n)` pieces. |
| path with a **Fenwick tree** | for sums with point updates, a Fenwick tree replaces the segment tree and is faster. |
| **LCA** only | the climbing loop alone, no segment tree, `O(log n)` per query. |
| count of **distinct** colours on a path | much harder; use Mo's algorithm on trees or offline techniques, not plain HLD. |

## When to use it

| tool | path query + update | notes |
| --- | --- | --- |
| walk up the parents | `O(n)` | fine for tiny trees or few queries |
| binary lifting | `O(log n)` for static paths | no updates of values along the path |
| Euler tour + segment tree | subtree queries and updates | does not handle arbitrary paths with an associative non-invertible operation |
| **HLD + segment tree** | `O(log^2 n)` path queries and point or range updates | the general-purpose tool |
| link-cut tree | `O(log n)` amortised, dynamic trees | when the tree **itself changes** (edges added and cut online) |
| centroid decomposition | queries about distances or counts among pairs | different problem family |

## Pitfalls

1. **Picking the heavy child by depth or by degree** instead of subtree size. Only subtree size gives the `log n` bound.
2. **Not making chains contiguous.** Positions must run head first down the chain; numbering by plain DFS order without following the heavy child breaks range queries.
3. **Comparing `depth[u]` instead of `depth[head[u]]`** in the loop. You must advance the vertex whose **chain head** is deeper.
4. **Forgetting the last same-chain query**, or using it before swapping `u` and `v` into depth order.
5. **Edge values handled on the wrong endpoint** (store on the child; skip the LCA position at the end).
6. **Recursion overflow** on a path graph. Use explicit stacks for the DFS, as above.
7. **Non-commutative operations.** The pieces collected from the two sides of the path must be combined in the correct order (and one side reversed).
8. **Rebuilding on every update.** Only the segment tree changes on a value update; the decomposition is fixed as long as the tree shape is.
