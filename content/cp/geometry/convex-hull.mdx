## Intuition

Hammer nails into a board at the given points, stretch a rubber band around all of them and let it snap tight. The shape the band takes is the **convex hull**: the smallest convex polygon that contains every point. Its **corners** are a subset of the nails, and every other nail lies inside the band or in the middle of one of its straight stretches.

The hull is one of the most useful objects in computational geometry. It gives the **diameter** (farthest pair of points), the **smallest enclosing rectangle**, the answer to "is this point inside the cloud", and the extreme points that matter for optimisation (the maximum of any linear function over a point set is attained at a hull corner).

## A convex set, formally

A polygon is **convex** if every interior angle is at most 180 degrees; equivalently, walking around it counter-clockwise you only ever turn **left** (or go straight). The orientation test from the previous lesson is all you need:

```text
a -> b -> c is a left turn   <=>   cross(b - a, c - a) > 0
```

A hull never makes a right turn. That one observation produces the algorithm.

## Andrew's monotone chain

1. **Sort** the points by `x`, breaking ties by `y`, and remove duplicates.
2. Build the **lower hull** from left to right with a stack. For each new point `p`: while the stack has at least two points and the last two stack points together with `p` do **not** make a strict left turn (`cross ≤ 0`), pop the top. Then push `p`.
3. Build the **upper hull** the same way scanning from right to left.
4. Join the two chains, dropping the last point of each (it is the first point of the other).

```text
lower hull:  pop while  cross(stack[-2], stack[-1], p) <= 0
upper hull:  same, scanning the sorted points in reverse
hull = lower[:-1] + upper[:-1]          (counter-clockwise, starting at the leftmost-lowest point)
```

Every point is pushed once and popped at most once, so after sorting the scan is `O(n)`. Total `O(n log n)`.

### Collinear points

The comparison `cross ≤ 0` pops points that lie **on** the line between two others, so the result contains only **strict corners**. If a problem wants collinear boundary points kept, use `cross < 0` instead. (Then the all-collinear input needs care: lower and upper hulls both contain all points.)

### Small inputs

With `0`, `1` or `2` distinct points the hull is just those points. When *all* points are collinear the two chains each end up as the two extreme points and the join gives `2` corners, with area `0`.

## Perimeter and area

Walk around the hull corners `h0, h1, ..., h(k−1)`:

```text
perimeter   = sum of |h(i+1) - h(i)|          (needs square roots, so use floats only at the very end)
2 * area    = | sum of ( x_i * y_(i+1) - x_(i+1) * y_i ) |        (shoelace, exact in integers)
```

```python
def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def convex_hull(points):                       # strict corners, counter-clockwise
    pts = sorted(set(points))
    if len(pts) <= 2:
        return pts
    lower = []
    for p in pts:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)
    upper = []
    for p in reversed(pts):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)
    return lower[:-1] + upper[:-1]

def twice_area(hull):
    n = len(hull)
    if n < 3: return 0
    return abs(sum(hull[i][0] * hull[(i + 1) % n][1] - hull[(i + 1) % n][0] * hull[i][1] for i in range(n)))
```

```cpp
typedef long long ll;
typedef pair<ll, ll> P;
ll cross(const P& o, const P& a, const P& b) { return (a.first - o.first) * (b.second - o.second) - (a.second - o.second) * (b.first - o.first); }

vector<P> convexHull(vector<P> pts) {          // strict corners, counter-clockwise
    sort(pts.begin(), pts.end());
    pts.erase(unique(pts.begin(), pts.end()), pts.end());
    int m = pts.size();
    if (m <= 2) return pts;
    vector<P> st(2 * m + 2);
    int k = 0;
    for (int i = 0; i < m; i++) {
        while (k >= 2 && cross(st[k - 2], st[k - 1], pts[i]) <= 0) k--;
        st[k++] = pts[i];
    }
    for (int i = m - 2, lowerSize = k + 1; i >= 0; i--) {
        while (k >= lowerSize && cross(st[k - 2], st[k - 1], pts[i]) <= 0) k--;
        st[k++] = pts[i];
    }
    st.resize(k - 1);
    return st;
}
```

## Using the hull

| task | how the hull helps |
| --- | --- |
| **diameter** (farthest pair) | only hull corners matter; **rotating calipers** finds it in `O(h)` |
| **minimum-area enclosing rectangle** | one side lies along a hull edge; rotating calipers again |
| is a point **inside the point cloud**? | a binary search over the hull fan, `O(log h)` |
| maximise `a·x + b·y` over the set | the best point is a hull corner |
| **Minkowski sum** of two convex polygons | merge the edge sequences by angle in `O(n + m)` |
| point set partition, **separating line** | convex hulls of the two sets must be disjoint |
| the *other* convex hull | maintaining lines instead of points gives the [convex hull trick](/cp/dynamic-programming/convex-hull-trick/) for DP |

## Variations

- **Upper or lower hull only:** the two chains above are exactly these; the upper hull is the key structure in several optimisation problems.
- **Dynamic hull** (insert and delete points): use a balanced tree of the hull, or an offline divide and conquer; much harder.
- **Graham scan:** sort by angle around the lowest point instead of by `x`; same complexity, trickier tie-breaking than the monotone chain.
- **Gift wrapping (Jarvis march):** `O(n · h)`; simple and good when the hull is tiny.
- **3D hulls and higher:** far more involved; not covered here.

## Pitfalls

1. **Not removing duplicates.** Repeated points make `cross = 0`; the `≤ 0` pop handles most cases, but handle `n ≤ 2` after deduplication to avoid returning the same point twice.
2. **Popping on `< 0` instead of `≤ 0`** keeps collinear boundary points (sometimes wanted, often not); decide from the statement.
3. **Dropping the last point wrongly.** Each chain's final point equals the other chain's first point; drop it exactly once.
4. **Wrong orientation convention.** The standard version produces counter-clockwise order; reverse the output if the problem wants clockwise.
5. **Overflow.** Cross products of differences up to `2·10^9` overflow 64 bits only beyond about `3·10^9` coordinates; use `__int128` there.
6. **All points collinear.** The output should be the 2 endpoints with area 0; check your code returns that and not an empty or looping result.
7. **Floating point.** Sorting and comparing with doubles invites mistakes; keep integers until the final perimeter.
