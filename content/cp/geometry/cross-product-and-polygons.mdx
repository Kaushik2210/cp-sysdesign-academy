## Intuition

Geometry problems have a reputation for being nasty, and almost all of the nastiness has one source: **floating-point numbers**. `0.1 + 0.2` is not `0.3`, two lines that should meet at a point miss by `1e-12`, and a comparison such as "are these three points on one line?" suddenly returns the wrong answer.

The cure is simple and powerful: **stay in integers**. If the input coordinates are integers, then almost every question a contest asks (which side of a line? do two segments cross? is a point inside a polygon? how big is the area?) can be answered *exactly* with one operation, the **cross product**, which only multiplies and subtracts integers. No division, no square roots, no epsilons.

This lesson builds the toolkit: vectors, the dot and cross product, orientation tests, segment intersection, polygon area, and point in polygon.

## Points and vectors

Treat a point `(x, y)` as a vector from the origin. The vector from point `a` to point `b` is `b − a = (bx − ax, by − ay)`.

Two products of vectors `u = (ux, uy)` and `v = (vx, vy)` do all the work:

```text
dot(u, v)   = ux * vx + uy * vy         = |u| |v| cos(angle)      sign tells acute / right / obtuse
cross(u, v) = ux * vy - uy * vx         = |u| |v| sin(angle)      sign tells which way v turns from u
```

- `cross(u, v) > 0`: `v` is **counter-clockwise** from `u` (a left turn).
- `cross(u, v) < 0`: `v` is clockwise from `u` (a right turn).
- `cross(u, v) = 0`: `u` and `v` are **parallel** (collinear if they share a point).
- `|cross(u, v)|` is the area of the parallelogram spanned by `u` and `v`, so **half of it is the area of the triangle**.

## Orientation: the one test to remember

Given three points `a, b, c`, the **orientation** is the sign of

```text
cross(b - a, c - a)  =  (bx - ax)*(cy - ay) - (by - ay)*(cx - ax)
```

| sign | meaning |
| --- | --- |
| `> 0` | `a → b → c` turns **left** (counter-clockwise) |
| `< 0` | turns **right** (clockwise) |
| `= 0` | `a, b, c` are **collinear** |

Everything below is built from this single function.

## Is a point on a segment?

`p` lies on the segment `ab` exactly when the orientation of `(a, b, p)` is `0` **and** `p` lies in the bounding box of `a` and `b`:

```text
cross(b - a, p - a) == 0   and   min(ax, bx) <= px <= max(ax, bx)   and   min(ay, by) <= py <= max(ay, by)
```

The collinearity test alone would accept points on the whole *line*; the bounding box restricts it to the segment.

## Do two segments intersect?

Segments `ab` and `cd` intersect when `c` and `d` are on **opposite sides** of line `ab`, and `a` and `b` are on opposite sides of line `cd`:

```text
d1 = orient(a, b, c)    d2 = orient(a, b, d)    d3 = orient(c, d, a)    d4 = orient(c, d, b)

proper crossing:    d1 * d2 < 0   and   d3 * d4 < 0            (use signs, not the product, to avoid overflow)
touching cases:     if some d is 0, check that point lies on the other segment (on_segment test)
```

Do the zero cases carefully: a segment can end exactly on another, or two segments can be collinear and overlap. A complete test is "proper crossing, or any endpoint lies on the other segment".

## Polygon area: the shoelace formula

For a polygon with corners `p0, p1, ..., p(n−1)` in order,

```text
2 * area = | sum over i of cross(p_i, p_(i+1)) |  =  | sum over i of ( x_i * y_(i+1) - x_(i+1) * y_i ) |
```

with indices taken modulo `n`. Keep the **doubled area**: it is always an integer, so there are no fractions. The signed sum is positive when the corners go counter-clockwise and negative when clockwise, which also tells you the orientation of the polygon.

## Point in polygon: ray casting

For a **simple** polygon (no self-intersections) and a point `p`:

1. If `p` lies on some side: it is on the **boundary**.
2. Otherwise cast a ray from `p` to the right (`+x`) and count how many sides it crosses. **Odd** means inside, **even** means outside.

Corners that lie exactly on the ray would be counted twice or not at all. The standard fix is a **half-open rule**: count a side only if one endpoint is **strictly above** the ray's `y` and the other is **not**:

```text
for each side (a, b):
    if (a.y > p.y) != (b.y > p.y):                        # the side straddles the line y = p.y
        crossing is to the right of p  <=>  cross(b - a, p - a) has the sign of (b.y - a.y)
        if so: toggle inside
```

The sign trick (positive for an upward side, negative for a downward side) avoids computing the intersection point with a division, so everything stays in integers.

def cross(o, a, b):                                     # orientation of o -> a -> b
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def on_segment(a, b, p):
    return cross(a, b, p) == 0 and min(a[0], b[0]) <= p[0] <= max(a[0], b[0]) and min(a[1], b[1]) <= p[1] <= max(a[1], b[1])

def sign(x): return (x > 0) - (x < 0)

def segments_intersect(a, b, c, d):
    d1, d2 = sign(cross(a, b, c)), sign(cross(a, b, d))
    d3, d4 = sign(cross(c, d, a)), sign(cross(c, d, b))
    if d1 * d2 < 0 and d3 * d4 < 0:
        return True                                     # they cross properly
    return on_segment(a, b, c) or on_segment(a, b, d) or on_segment(c, d, a) or on_segment(c, d, b)

def twice_area(poly):
    n = len(poly)
    return abs(sum(poly[i][0] * poly[(i + 1) % n][1] - poly[(i + 1) % n][0] * poly[i][1] for i in range(n)))

def locate(poly, p):                                    # "INSIDE", "OUTSIDE" or "BOUNDARY"
    n = len(poly)
    inside = False
    for i in range(n):
        a, b = poly[i], poly[(i + 1) % n]
        if on_segment(a, b, p):
            return "BOUNDARY"
        if (a[1] > p[1]) != (b[1] > p[1]):
            c = cross(a, b, p)
            if (b[1] > a[1] and c > 0) or (b[1] < a[1] and c < 0):
                inside = not inside
    return "INSIDE" if inside else "OUTSIDE"

typedef long long ll;
typedef pair<ll, ll> P;
ll cross(P o, P a, P b) { return (a.first - o.first) * (b.second - o.second) - (a.second - o.second) * (b.first - o.first); }
int sgn(ll x) { return (x > 0) - (x < 0); }
bool onSegment(P a, P b, P p) {
    return cross(a, b, p) == 0 && min(a.first, b.first) <= p.first && p.first <= max(a.first, b.first)
        && min(a.second, b.second) <= p.second && p.second <= max(a.second, b.second);
}
bool segmentsIntersect(P a, P b, P c, P d) {
    int d1 = sgn(cross(a, b, c)), d2 = sgn(cross(a, b, d)), d3 = sgn(cross(c, d, a)), d4 = sgn(cross(c, d, b));
    if (d1 * d2 < 0 && d3 * d4 < 0) return true;
    return onSegment(a, b, c) || onSegment(a, b, d) || onSegment(c, d, a) || onSegment(c, d, b);
}
ll twiceArea(const vector<P>& poly) {
    ll s = 0; int n = poly.size();
    for (int i = 0; i < n; i++) s += poly[i].first * poly[(i + 1) % n].second - poly[(i + 1) % n].first * poly[i].second;
    return llabs(s);
}
string locate(const vector<P>& poly, P p) {
    int n = poly.size(); bool inside = false;
    for (int i = 0; i < n; i++) {
        P a = poly[i], b = poly[(i + 1) % n];
        if (onSegment(a, b, p)) return "BOUNDARY";
        if ((a.second > p.second) != (b.second > p.second)) {
            ll c = cross(a, b, p);
            if ((b.second > a.second && c > 0) || (b.second < a.second && c < 0)) inside = !inside;
        }
    }
    return inside ? "INSIDE" : "OUTSIDE";
}

## Pitfalls

1. **Using floating point.** `float` comparisons and `atan2` produce wrong answers on exact boundaries. Stay in integers; if the input has decimals, scale them up (multiply by `10^k`) first.
2. **Overflow.** A cross product multiplies two differences; for coordinates up to `10^9` those reach `2·10^9`, and the product `4·10^18` is *just* inside `long long`. Beyond that, use `__int128` or Python integers. In JavaScript, plain numbers are exact only up to `2^53`: keep coordinates below about `10^6`, or use `BigInt`.
3. **Multiplying signs of large crosses.** Compare `sign(a) * sign(b)` instead of `a * b`, since the product of two large crosses can overflow.
4. **Forgetting the bounding-box check.** Collinear is not the same as on the segment.
5. **Corner cases in ray casting.** Without the half-open rule `(a.y > p.y) != (b.y > p.y)`, rays that pass through corners are double counted. Horizontal sides must never count; the rule excludes them automatically.
6. **Treating boundary as inside (or outside) by accident.** Decide the boundary behaviour explicitly and test it *before* the crossing count.
7. **Assuming the polygon is counter-clockwise.** The shoelace sum changes sign with orientation; take the absolute value, or normalise the orientation once.
8. **Self-intersecting polygons.** Ray casting and the shoelace area assume a *simple* polygon; for others they compute different things (even-odd fill, signed area).
