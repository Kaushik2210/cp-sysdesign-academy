## Intuition

Given `n` points, which two are closest? Checking all `n (n - 1) / 2` pairs is simple and takes `O(n^2)`: fine for a few thousand points, hopeless for a million. There is a classic way to do it in `O(n log n)`, and the idea is worth knowing for its own sake because it shows up everywhere in geometry: **the points that matter are the ones near a dividing line, and only a constant number of them can matter for each point.**

Think of two towns far apart: pairs of houses inside one town are handled within that town. The only new candidates are pairs that straddle the border, and a house deep inside one town cannot be closer to any house across the border than the best distance we already have.

## Definition

Squared distance: `d2(p, q) = (px - qx)^2 + (py - qy)^2`. Compare squared distances: they order pairs exactly like true distances and stay integers.

**Divide and conquer.**

1. Sort the points by `x`.
2. **Divide:** split at the middle index into a left half `L` and a right half `R`, and let `midx` be the `x` of the middle point.
3. **Conquer:** recursively find the closest pair in `L` and in `R`. Let `best` be the smaller squared distance.
4. **Combine:** the closest pair overall is either inside one half (already found) or **crosses** the dividing line. A crossing pair can only beat `best` if both points are within horizontal distance `sqrt(best)` of the line. Collect the points `p` with `(px - midx)^2 < best` into the **strip**.
5. Sort the strip by `y`. For each point `p` in the strip, compare it with the points after it **while their `y`-gap is less than `sqrt(best)`** (that is, `(dy)^2 < best`), updating `best` on the way.

## Why the strip scan is cheap

Take a strip point `p` and let `d = sqrt(best)`. Any later strip point that could improve `best` has `y` between `py` and `py + d`, and `x` within `d` of the dividing line: it lies in a rectangle of width `2d` and height `d`. Cut that rectangle into 8 squares of side `d / 2`. The diagonal of such a square is `d / sqrt(2) < d`, and two points of the **same half** are never closer than `d` (otherwise `best` would already be smaller), so each square holds **at most one point from each half**. The rectangle therefore holds only a small constant number of points, whatever the size of the strip. The classic careful count shows that comparing each point with the **next 7** strip points (in `y` order) is enough; the demo below measures 2 or 3 in practice, and the `break` on `(dy)^2 >= best` stops the scan even earlier.

## Complexity

Recurrence `T(n) = 2 T(n / 2) + O(n log n)` if the strip is sorted each time: `O(n log^2 n)` overall, fine for `n` up to a few `10^5`. To reach `O(n log n)`, keep each recursion sorted by `y` and **merge** the two sorted halves (as in merge sort), building the strip by filtering the merged list.

## Other approaches

| approach | time | notes |
| --- | --- | --- |
| all pairs | `O(n^2)` | the baseline and the checker |
| divide and conquer (above) | `O(n log^2 n)` or `O(n log n)` | the standard exam solution |
| **sweep line** | `O(n log n)` | sort by `x`, keep in an ordered set (by `y`) the points within `sqrt(best)` to the left of the sweep line; for each new point query a window of height `2 sqrt(best)` |
| randomised grid | `O(n)` expected | process points in random order with a hash grid of cell size `best / 2`; rebuild the grid when `best` decreases (Rabin / Khuller-Matias) |
| k-d tree | `O(n log n)` build, then nearest-neighbour queries | useful for many query points |

## Example, step by step

Points `(0,0), (4,0), (5,3), (5,-3), (5,0), (10,0)`.

- Sorted by `x` (ties by `y`): `(0,0), (4,0), (5,-3), (5,0), (5,3), (10,0)`.
- Split at index 3: left `(0,0), (4,0), (5,-3)`, right `(5,0), (5,3), (10,0)`. `midx = 5`.
- Left half (3 points, brute force): `d2((0,0),(4,0)) = 16`, `d2((0,0),(5,-3)) = 34`, `d2((4,0),(5,-3)) = 10` : best `10`. Right half: `d2((5,0),(5,3)) = 9`, `d2((5,0),(10,0)) = 25`, `d2((5,3),(10,0)) = 34`: best `9`. Overall `best = 9`.
- Strip: points with `(x - 5)^2 < 9`, i.e. `|x - 5| < 3`: `(4,0), (5,-3), (5,0), (5,3)`. Sorted by `y`: `(5,-3), (4,0), (5,0), (5,3)`.
- Scan: `(5,-3)` vs `(4,0)`: `dy = 3`, `3^2 = 9 >= best`, stop. `(4,0)` vs `(5,0)`: `dy = 0`, `d2 = 1 < 9`: `best = 1`. `(4,0)` vs `(5,3)`: `dy = 3`, `9 >= 1`, stop. Nothing else improves.
- Answer: `1` (the pair `(4,0)` and `(5,0)`, which straddle the dividing line).

import sys
sys.setrecursionlimit(10000)
pts = sorted(points)                           # sorted by x, then y

def d2(a, b):
    return (a[0] - b[0]) ** 2 + (a[1] - b[1]) ** 2

def closest(lo, hi):                           # smallest squared distance among pts[lo:hi]
    if hi - lo <= 3:
        return min((d2(pts[i], pts[j]) for i in range(lo, hi) for j in range(i + 1, hi)), default=float("inf"))
    mid = (lo + hi) // 2
    midx = pts[mid][0]
    best = min(closest(lo, mid), closest(mid, hi))
    strip = sorted((p for p in pts[lo:hi] if (p[0] - midx) ** 2 < best), key=lambda p: p[1])
    for i in range(len(strip)):
        for j in range(i + 1, len(strip)):
            if (strip[j][1] - strip[i][1]) ** 2 >= best:
                break
            best = min(best, d2(strip[i], strip[j]))
    return best

            for (int j = i + 1; j < hi; j++) best = min(best, d2(pts[i], pts[j]));

## Pitfalls

1. **Comparing true distances with `sqrt`.** Use squared integer distances end to end.
2. **Strip filter with `<=` or the wrong threshold.** Points with `(x - midx)^2 >= best` cannot improve the answer; using `>` or comparing `|x - midx|` against `best` (not its root) mixes squared and unsquared values.
3. **Breaking the inner loop too late.** The scan must stop as soon as `(dy)^2 >= best`; scanning the whole strip makes it `O(n^2)` on a vertical line.
4. **Duplicate points.** The answer is `0`; the strip filter with `best = 0` is empty, which is fine, but a sweep line must handle `best = 0` explicitly (the demo returns early).
5. **Splitting by index vs by value.** Split by index after sorting: many points may share the same `x`, and splitting by value can leave one half empty and recurse forever.
6. **Sorting the strip with an expensive comparator** on every level: it multiplies the cost; merge by `y` if you need `O(n log n)`.
7. **Overflow.** Squared distances reach `8 * 10^12` for coordinates `10^6` and `8 * 10^18` for `10^9`, which is at the limit of signed 64-bit.
8. **Using the hull or Delaunay triangulation when a simple sort suffices.** The closest pair is an edge of the Delaunay triangulation, but building it is far heavier than this algorithm.
