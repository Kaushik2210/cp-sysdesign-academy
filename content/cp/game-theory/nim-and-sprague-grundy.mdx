## Intuition

Two players alternate moves in a game with no chance and no hidden information. The one who cannot move loses. Who wins with perfect play? For small games you can search the whole game tree. For large ones, a few beautiful facts let you answer instantly:

- Every position is either **winning for the player to move** or **losing for the player to move** (this is a *normal-play impartial* game: both players have the same moves available).
- A position is **losing** exactly when **every** move leads to a winning position for the opponent (including the case of no moves). A position is **winning** when **some** move leads to a losing position.
- A pile game called **Nim** has a complete solution: XOR the pile sizes.
- **Every** impartial game behaves exactly like a Nim pile whose size is a number called its **Grundy value**. So many independent games played together reduce to one Nim position: XOR their Grundy values.

## Definitions

An **impartial game** has positions, a set of moves from each position (the same for both players) and ends when the player to move has no move; that player **loses** (normal play).

- **P-position** (previous player wins): the player to move loses with optimal play.
- **N-position** (next player wins): the player to move wins.

Recursion: a position is a P-position iff all its moves lead to N-positions; an N-position iff at least one move leads to a P-position. Terminal positions are P-positions. For a game on a directed acyclic graph this is a DP in reverse topological order.

### Nim

Several piles of stones. A move removes any positive number of stones from one pile. The last player to take a stone wins.

**Bouton's theorem.** A Nim position with pile sizes `a1, ..., ak` is a P-position **if and only if** `a1 xor a2 xor ... xor ak = 0`.

Why: (1) the terminal position (all piles empty) has XOR `0`. (2) From any position with XOR `0`, every move changes exactly one pile, so the XOR becomes non-zero: P positions only lead to N positions. (3) From any position with XOR `X != 0`, take the highest set bit of `X`; some pile `a` has that bit set; replace `a` by `a xor X`, which is smaller than `a`, and the total XOR becomes `0`: an N position always has a move to a P position.

**Winning move.** Compute `X`; pick a pile `a` with `a xor X < a`; reduce it to `a xor X`.

### Mex and Grundy numbers

For a set `S` of non-negative integers, `mex(S)` is the **minimum excluded value**: the smallest non-negative integer not in `S`. The **Grundy value** (nimber) of a position `p` is

```text
g(p) = mex { g(q) : q is reachable from p by one move }
```

A position with no moves has `g = 0`. Grundy value `0` means P-position; non-zero means N-position.

### Sprague-Grundy theorem

> Every position of an impartial game is equivalent to a Nim pile of size `g(p)`.
> The **sum** of games (a player chooses one component and makes one move there) has Grundy value `g(p1) xor g(p2) xor ... xor g(pk)`.

So for several independent games you compute each game's Grundy value separately and XOR them. The first player wins the sum exactly when the XOR is non-zero. The Nim pile of size `n` has `g = n` (its options are piles `0..n-1`, whose mex is `n`), which is how Bouton's theorem becomes a special case.

## Example, step by step

**A subtraction game.** One pile of `n` stones; a move removes 1, 3 or 4 stones. Grundy values:

- `g(0) = 0`. `g(1)`: options `g(0) = 0`, so `mex {0} = 1`. `g(2)`: options `g(1) = 1`, so `mex {1} = 0`.
- `g(3)`: options `g(2) = 0`, `g(0) = 0`: `mex {0} = 1`. `g(4)`: options `g(3) = 1`, `g(1) = 1`, `g(0) = 0`: `mex {0, 1} = 2`.
- `g(5)`: options `g(4) = 2`, `g(2) = 0`, `g(1) = 1`: `mex {0, 1, 2} = 3`. `g(6)`: options `g(5) = 3`, `g(3) = 1`, `g(2) = 0`: `mex {0, 1, 3} = 2`.
- The sequence is `0, 1, 0, 1, 2, 3, 2, 0, 1, 0, 1, 2, 3, 2, ...`, **periodic with period 7**.

Now a sum: three piles of sizes `5, 6, 9` in this game. `g(5) = 3`, `g(6) = 2`, `g(9) = 0`; the XOR is `3 xor 2 xor 0 = 1 != 0`: the first player wins. A winning move changes one pile so that the XOR becomes 0, for example change the pile `5` (Grundy `3`) to a position with Grundy `3 xor 1 = 2`: reachable by removing 1 stone (`g(4) = 2`).

**A game that splits (Kayles).** A row of `n` pins; a move knocks down 1 pin or 2 adjacent pins. The row splits into two independent rows (a sum). So `g(n) = mex of { g(a) xor g(b) : a + b = n - 1 or n - 2 }`, and the values begin `0, 1, 2, 3, 1, 4, 3, 2, 1, 4, 2, 6, ...`.

## Common games and their Grundy values

| game | rule | Grundy value or result |
| --- | --- | --- |
| Nim | remove any number from one pile | `g(n) = n` |
| subtraction game `S` | remove `k` in `S` from one pile | mex recurrence; usually periodic |
| take 1 to `k` stones | `S = {1, ..., k}` | `g(n) = n mod (k + 1)` |
| staircase Nim | move coins down a staircase | Nim on the **odd** steps only |
| Kayles | knock 1 or 2 adjacent pins; the row splits | `g(n) = mex of g(a) xor g(b)`; eventually periodic with period 12 (after a prefix of about 70 values) |
| misère Nim | the **last** player to move **loses** | as normal Nim, except when all piles have at most 1 stone: then the first player wins iff the number of non-empty piles is **even** |
| Wythoff's game | remove from one pile, or equal amounts from both | P-positions are Beatty-sequence pairs `(floor(k phi), floor(k phi^2))`, not a nim-sum |
| cycle (loopy) games | positions can repeat | need draw handling and retrograde analysis, outside Sprague-Grundy |

## How to approach a game problem

1. **Check it is impartial** (both players have the same moves) and ends in finite time. If the players have different moves (partizan), or can cycle, other tools apply.
2. **Decide the winning condition**: normal play (cannot move loses) vs misère.
3. **Brute force small cases** by memoised search; print the P-positions and Grundy values; look for a pattern (periodicity, `n mod (k + 1)`, binary structure).
4. **Decompose into independent components** (piles, rows after a split, tokens on separate graphs) and use `xor` of Grundy values.
5. **Compute Grundy values** by mex DP. If the state space is huge, find the period or a closed form.
6. **Verify** the formula against a brute force on small inputs before trusting it.

## Pitfalls

1. **Using win/lose labels for sums.** A sum of two N-positions can be N or P; only Grundy values combine correctly.
2. **Wrong mex**: it is the smallest non-negative integer **missing** from the set, not the maximum plus 1. `mex {0, 2} = 1`.
3. **Mixing normal and misère play.** The XOR rule is for normal play; misère needs the special case for piles of size at most 1.
4. **Forgetting that a move changes only one component** of a sum. If a move can affect two components at once (as in Wythoff), the XOR rule fails.
5. **Treating components as independent when they are not**, for example when a move on one pile depends on another.
6. **Processing positions in the wrong order**: compute Grundy values after all successors, in reverse topological order.
7. **Cycles.** Sprague-Grundy needs a finite game (a DAG). With repeating positions, use retrograde analysis with draws.
8. **Huge heaps without a pattern.** If values are not periodic, you cannot tabulate; look for structure instead of brute force.
