## Intuition

Every substring of a string is a **prefix of one of its suffixes**. The substring `ana` of `banana` is a prefix of the suffix `anana`. So if you could look at all suffixes at once, **sorted alphabetically**, then questions about substrings turn into questions about neighbouring entries in a list:

- Where does the pattern `ana` occur? All suffixes starting with `ana` sit in one **contiguous block** of the sorted list, so a binary search finds them.
- Which substring repeats the longest? Look at two **adjacent** sorted suffixes: the longer their shared prefix, the longer the repeat.
- How many different substrings are there? Count each suffix's prefixes, minus the ones shared with the previous suffix.

The sorted list of suffix start positions is the **suffix array**. It needs only `n` integers, unlike a suffix tree with its many nodes, and it is easy to build with a few lines of sorting.

## Definition

For a string `s` of length `n`:

- `sa[r]` is the start position of the suffix with rank `r` (the `r`-th smallest suffix, `r = 0 .. n-1`).
- `rank[i]` is the inverse: the rank of the suffix starting at `i`.
- `lcp[r]` is the length of the longest common prefix of the suffixes `sa[r-1]` and `sa[r]` (and `lcp[0] = 0`).

For `s = banana`:

```text
r   sa[r]   suffix     lcp[r]
0     5     a            0
1     3     ana          1      (a)
2     1     anana        3      (ana)
3     0     banana       0
4     4     na           0
5     2     nana         2      (na)
```

The LCP of **any** two suffixes (not just neighbours) is the **minimum** of `lcp` over the ranks between them. That makes a sparse table over `lcp` an `O(1)` "longest common extension" oracle.

## Building the suffix array

**Naive:** sort the suffixes by comparing them as strings: `O(n^2 log n)` in the worst case (comparisons can take `O(n)`), fine for `n` up to a few thousand.

**Prefix doubling** (`O(n log^2 n)`, or `O(n log n)` with a radix sort): suppose you already sorted all suffixes by their first `k` characters and stored a `rank` for each (equal prefixes get equal ranks). Then the order by the first `2k` characters is the order by the **pair** `(rank[i], rank[i + k])`, because the second half of `suffix i`'s first `2k` characters is the first half of `suffix i + k`. Sort by that pair, assign new ranks, double `k`. After `ceil(log2 n)` rounds all ranks are distinct and the array is sorted.

Faster constructions exist: radix-sorted doubling in `O(n log n)`, the **SA-IS** algorithm in `O(n)`, and the **DC3** algorithm. For contests, the `O(n log n)` doubling or the shorter `O(n log^2 n)` is almost always enough.

## Kasai's algorithm: the LCP array in `O(n)`

Computing each LCP by comparing characters directly can cost `O(n^2)` in total. Kasai's trick: process suffixes in **text order** `i = 0, 1, ..., n - 1`, and let `h` be the LCP of suffix `i` with its predecessor in sorted order. For suffix `i + 1`, the LCP with *its* predecessor is **at least `h - 1`**: if suffix `i` shares `h >= 1` characters with some `j`, then suffix `i + 1` shares `h - 1` characters with `j + 1`, and `j + 1` sorts before `i + 1`. So start the comparison at `h - 1` instead of 0. `h` goes up by at most `n` in total and down by 1 per step, so the total work is `O(n)`.

## Example, step by step

For `banana` the suffix array is `[5, 3, 1, 0, 4, 2]`.

- **Distinct substrings.** Total prefixes of all suffixes: `6 + 5 + 4 + 3 + 2 + 1 = 21`. Subtract `sum(lcp) = 0 + 1 + 3 + 0 + 0 + 2 = 6`: `15` distinct substrings.
- **Pattern search for `ana`.** Binary search the sorted suffixes for the first and the last whose first 3 characters are `ana`: ranks 1 and 2, positions `sa[1] = 3` and `sa[2] = 1`.
- **Longest repeated substring.** The largest `lcp` is 3 at rank 2, the substring `ana`.

<CodeRunner language="python" code={`import random
from bisect import bisect_left, bisect_right

def suffix_array_naive(s):
    return sorted(range(len(s)), key=lambda i: s[i:])

def suffix_array(s):
    """Prefix doubling: after round j the suffixes are sorted by their first 2^j characters."""
    n = len(s)
    sa = list(range(n))
    rank = [ord(c) for c in s]
    k = 1
    while True:
        key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
        sa.sort(key=key)
        new_rank = [0] * n
        for idx in range(1, n):
            new_rank[sa[idx]] = new_rank[sa[idx - 1]] + (key(sa[idx]) != key(sa[idx - 1]))
        rank = new_rank
        if rank[sa[-1]] == n - 1:
            return sa
        k *= 2

def lcp_array(s, sa):
    """Kasai: lcp[r] = longest common prefix of the suffixes sa[r-1] and sa[r] (lcp[0] = 0), in O(n)."""
    n = len(s)
    rank = [0] * n
    for r, i in enumerate(sa):
        rank[i] = r
    lcp = [0] * n
    h = 0
    for i in range(n):
        if rank[i] > 0:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]:
                h += 1
            lcp[rank[i]] = h
            if h > 0:
                h -= 1            # moving to the next text position loses at most one character of the match
        else:
            h = 0
    return lcp

s = "banana"
sa = suffix_array(s)
lcp = lcp_array(s, sa)
print("suffix array:", sa, [s[i:] for i in sa])
print("lcp array   :", lcp)
print("distinct substrings:", len(s) * (len(s) + 1) // 2 - sum(lcp))

for _ in range(300):
    t = "".join(random.choice("abc") for _ in range(random.randint(1, 25)))
    assert suffix_array(t) == suffix_array_naive(t)
    lc = lcp_array(t, suffix_array(t))
    assert len(t) * (len(t) + 1) // 2 - sum(lc) == len({t[i:j] for i in range(len(t)) for j in range(i + 1, len(t) + 1)})
print("doubling matches the naive sort, and the distinct-substring count matches a set, on 300 random strings")

def occurrences(s, sa, pattern):
    """All start positions of pattern, by binary search on the sorted suffixes: O(m log n)."""
    suffixes = [s[i:i + len(pattern)] for i in sa]          # only the first m characters matter
    lo, hi = bisect_left(suffixes, pattern), bisect_right(suffixes, pattern)
    return sorted(sa[lo:hi])

print("positions of 'ana' in banana:", occurrences(s, sa, "ana"))

def longest_repeated(s):
    sa = suffix_array(s)
    lcp = lcp_array(s, sa)
    best = max(range(len(s)), key=lambda r: lcp[r])
    return s[sa[best]:sa[best] + lcp[best]]

print("longest repeated substring of 'banana':", longest_repeated("banana"))

def longest_common_substring(a, b):
    """Join the strings with a separator that appears in neither; look at neighbours from different strings."""
    t = a + "#" + b
    sa = suffix_array(t)
    lcp = lcp_array(t, sa)
    best, where = 0, 0
    for r in range(1, len(t)):
        x, y = sa[r - 1], sa[r]
        if (x < len(a)) != (y < len(a)) and lcp[r] > best:
            best, where = lcp[r], sa[r]
    return t[where:where + best]

print("longest common substring of 'xabcdy' and 'zabcdw':", longest_common_substring("xabcdy", "zabcdw"))

## What you can compute

| question | method |
| --- | --- |
| occurrences of a pattern of length `m` | binary search on `sa`, comparing only the first `m` characters: `O(m log n)` |
| number of distinct substrings | `n(n+1)/2 - sum(lcp)` |
| longest repeated substring | the maximum value in `lcp` |
| longest common substring of `a` and `b` | join as `a + "#" + b` (a separator in neither), take the maximum `lcp` between adjacent suffixes that come from different strings |
| the `k`-th smallest distinct substring | walk the sorted suffixes, subtracting `(length - lcp)` new substrings from `k` until it fits |
| longest common extension of two positions | minimum of `lcp` over a rank range, with a sparse table: `O(1)` |
| how many times a substring occurs | the size of the `sa` block that shares that prefix, found with the `lcp` minima |
| longest palindromic substring | suffix array of `s + "#" + reverse(s)` plus a common-extension query (Manacher is simpler) |

## Choosing a string structure

| structure | builds in | strengths | cost |
| --- | --- | --- | --- |
| KMP / Z-function | `O(n)` | one pattern against one text | single pattern only |
| hashing | `O(n)` | fast substring equality, binary search on LCP | probabilistic |
| suffix array + LCP | `O(n log n)` | all substring queries on a **static** text, small memory | not for online appends |
| suffix automaton | `O(n)` | online, distinct substrings, occurrence counts | more intricate |
| suffix tree | `O(n)` | the most expressive | heavy memory and code |

## Pitfalls

1. **Comparing the first `m` characters only for pattern search.** Slice the suffix to the pattern length before comparing, otherwise longer suffixes sort "after" the pattern incorrectly.
2. **Off-by-one in the key `rank[i + k]`.** A suffix with no character at `i + k` must sort **before** anything that has one: use `-1`.
3. **Stopping too early.** Stop when all ranks are distinct (the largest rank is `n - 1`), not after a fixed number of rounds, otherwise strings like `aaaa...a` break.
4. **Wrong `lcp` indexing.** `lcp[r]` compares ranks `r - 1` and `r`; `lcp[0]` is 0.
5. **Forgetting `h -= 1` in Kasai**, which turns the linear algorithm quadratic.
6. **Joining two strings without a separator** that is absent from both, so an LCP crosses the boundary.
7. **Sorting with an `O(n)` comparator** on large inputs. Compare ranks, not slices, past the first round.
8. **Overflow of the answer.** The distinct-substring count is about `n^2 / 2`: 64-bit for `n` above `65000`.
