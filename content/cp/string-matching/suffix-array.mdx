## Intuition

[KMP](/cp/string-matching/kmp/) and the [Z-function](/cp/string-matching/z-function/) answer questions about **one pattern in one text**. Many harder questions are about **all substrings** of a text at once: how many are distinct, what is the longest one that appears twice, what is the `k`-th in alphabetical order. Looking at `n(n+1)/2` substrings directly is hopeless.

The key observation: **every substring is a prefix of a suffix**. A string of length `n` has just `n` suffixes. If we **sort the suffixes alphabetically**, suffixes that share a long prefix end up next to each other. That sorted list is the **suffix array**, and the lengths of the shared prefixes between neighbours is the **LCP array**. Together they make most substring questions look like questions about neighbouring entries in one sorted list.

## Definition

For a string `s` of length `n`:

- **Suffix array** `sa`: the starting positions of the suffixes in increasing alphabetical order.
- **Rank** `rank[i]`: the position of the suffix starting at `i` inside `sa` (the inverse permutation).
- **LCP array** `lcp[r]`: the length of the longest common prefix of the suffixes `sa[r-1]` and `sa[r]` (with `lcp[0] = 0`).

Example for `s = banana`:

| `r` | `sa[r]` | suffix | `lcp[r]` |
| --- | --- | --- | --- |
| 0 | 5 | `a` | 0 |
| 1 | 3 | `ana` | 1 (`a`) |
| 2 | 1 | `anana` | 3 (`ana`) |
| 3 | 0 | `banana` | 0 |
| 4 | 4 | `na` | 0 |
| 5 | 2 | `nana` | 2 (`na`) |

**Distinct substrings.** Walk the sorted suffixes. Suffix `sa[r]` has `n - sa[r]` prefixes, but the first `lcp[r]` of them already appeared as prefixes of the previous suffix, so only the rest are new:

```text
distinct substrings = sum over r of ( (n - sa[r]) - lcp[r] ) = n(n+1)/2 - sum(lcp)
```

For `banana`: `21 - (0+1+3+0+0+2) = 15`.

**Other uses of the same two arrays.**

| question | how |
| --- | --- |
| does pattern `P` occur in `s`? | binary search on `sa` comparing `P` with suffixes: `O(|P| log n)` |
| longest repeated substring | `max(lcp)` |
| longest common substring of two strings | build for `a + '#' + b`, take the maximum `lcp` between neighbours that come from different strings |
| LCP of any two suffixes | range minimum of `lcp` between their ranks (a [sparse table](/cp/range-queries/sparse-table/)) |
| `k`-th smallest distinct substring | walk `sa` subtracting `(n - sa[r]) - lcp[r]` |

## Building the suffix array: prefix doubling

Sorting all suffixes by comparing characters can cost `O(n^2)` per comparison on a string like `aaaa...a`. **Prefix doubling** avoids this by sorting on 1, 2, 4, 8, ... leading characters:

1. Start with `rank[i] = s[i]`.
2. For `k = 1, 2, 4, ...`: sort the suffixes by the **pair** `(rank[i], rank[i + k])` (use `-1` when `i + k >= n`). Because `rank` already orders suffixes by their first `k` characters, this orders them by their first `2k` characters.
3. Re-rank: equal pairs get equal ranks, otherwise the next rank.
4. Stop when all ranks are distinct (all suffixes are different within `2k` characters).

There are at most `log2(n)` rounds, each a sort: `O(n log^2 n)` with a comparison sort, `O(n log n)` with radix sort.

## LCP in linear time: Kasai's algorithm

Computing each `lcp[r]` by direct comparison costs `O(n)` each. **Kasai's observation:** let `h` be the LCP of suffix `i` with its sorted predecessor. Then suffix `i + 1` has LCP **at least `h - 1`** with *its* predecessor (remove the first character from both). So process `i = 0, 1, ..., n-1` in text order, keep `h`, and only ever **decrease it by 1** per step: the total work is `O(n)`.

```python
n = len(s)
sa = sorted(range(n), key=lambda i: s[i])
rank = [ord(c) for c in s]
k = 1
while k < n:
    key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
    sa.sort(key=key)
    tmp = [0] * n
    for idx in range(1, n):
        tmp[sa[idx]] = tmp[sa[idx - 1]] + (key(sa[idx]) != key(sa[idx - 1]))
    rank = tmp
    if rank[sa[-1]] == n - 1:           # all ranks distinct: done
        break
    k *= 2

rank = [0] * n
for idx, i in enumerate(sa):
    rank[i] = idx
lcp = [0] * n
h = 0
for i in range(n):                      # Kasai
    if rank[i] > 0:
        j = sa[rank[i] - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[rank[i]] = h
        if h > 0:
            h -= 1
    else:
        h = 0
```

## Choosing a string structure

| structure | build | good at |
| --- | --- | --- |
| prefix function / Z-function | `O(n)` | one pattern against one text, borders, periods |
| Manacher | `O(n)` | palindromes |
| string hashing | `O(n)` | equality and LCP via binary search; collision risk |
| **suffix array + LCP** | `O(n log n)` | counting and ordering substrings, repeats, many patterns on one text |
| suffix automaton | `O(n |alphabet|)` | distinct substrings, occurrence counts, online construction |
| suffix tree | `O(n)` | same as the array, more memory and code |

## Pitfalls

1. **Not stopping when ranks are distinct.** The loop must end by `k >= n` at the latest, otherwise `rank[i + k]` is read for every `i` for no reason; the early exit also saves rounds on random strings.
2. **Missing the sentinel `-1`.** A suffix shorter than `k` has no second key; it must sort **before** any longer suffix with the same first half. Using `-1` (smaller than every rank) does that.
3. **Comparing the new rank with equal keys.** Equal pairs must get **equal** new ranks, or later rounds treat identical prefixes as different.
4. **Kasai with the wrong decrement.** Only `h -= 1` when `h > 0`, and reset to 0 when `rank[i] == 0` (no predecessor).
5. **Overflow.** The distinct-substring count reaches `n(n+1)/2`: use 64-bit integers.
6. **Python speed.** Tuple-key sorting is fine up to about `10^5`; at `10^6` use a radix-sort doubling, SA-IS, or a compiled language.
7. **Concatenating strings.** When joining two strings, put a separator that occurs in neither (like `#`), or common substrings will spill across the join.
