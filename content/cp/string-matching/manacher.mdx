## Intuition

A palindrome has a **centre**: the middle letter for odd lengths, the gap between two middle letters for even lengths. Around one centre, palindromes are **nested**: if `abcba` is a palindrome centred on `c`, so are `bcb` and `c`. So everything about the palindromes at a centre is captured by one number, the largest radius.

The simple method expands around each of the `2n - 1` centres, which costs `O(n^2)` on a string like `aaaa...a`. Manacher's insight is that **neighbouring centres are related by mirror symmetry**. If you are inside a big palindrome, the part to the right of its centre is a reflection of the part to the left, so you already know a lot about the right half without comparing anything.

## Definition

For a string `s` of length `n`:

- `d1[i]` = number of odd-length palindromes centred at `i` (equivalently the radius, counting the single letter).
- `d2[i]` = number of even-length palindromes centred **between** `i - 1` and `i`.

Each such palindrome corresponds to exactly one substring, so the total number of palindromic substrings is `sum(d1) + sum(d2)`, and the longest palindrome comes from the largest `2 * d1[i] - 1` or `2 * d2[i]`.

**The mirror trick.** Maintain `[l, r]`, the palindrome found so far that reaches farthest to the right. For a new centre `i` with `i <= r`, its mirror image `j = l + r - i` lies inside the same palindrome, so the palindrome around `i` is at least as large as the one around `j`, **clipped at the border `r`**:

```text
k = min( d1[l + r - i], r - i + 1 )          # already verified, no comparisons needed
while s[i - k] == s[i + k]:  k += 1          # only try to grow beyond what is known
d1[i] = k
if i + k - 1 > r:  l, r = i - k + 1, i + k - 1
```

If `i > r` start from `k = 1` (no information). Even lengths use the same idea with shifted indices.

**Why linear.** The expansion loop only ever advances past `r`, and `r` never moves left, so across all centres the number of successful comparisons is at most `n`. The clipped starting value costs `O(1)`.

## Example, step by step

`s = abaab`. Odd palindromes: every single letter (5) and `aba`. Even palindromes: `aa` at the gap between positions 2 and 3, and `baab` around the same gap.

| `i` | letter | `d1[i]` | what it covers |
| --- | --- | --- | --- |
| 0 | `a` | 1 | `a` |
| 1 | `b` | 2 | `b`, `aba` |
| 2 | `a` | 1 | `a` (neighbours `b` and `a` differ) |
| 3 | `a` | 1 | `a` (neighbours `a` and `b` differ) |
| 4 | `b` | 1 | `b` |

`d1 = [1, 2, 1, 1, 1]`, sum 6.

For even centres, `d2[i]` counts palindromes between `i - 1` and `i`. Only `i = 3` (between the two middle `a`s) works: `aa`, then `baab`, so `d2[3] = 2`. All other `d2` are 0, so `d2 = [0, 0, 0, 2, 0]`, sum 2.

Total: `6 + 2 = 8` palindromic substrings: `a, b, a, a, b, aba, aa, baab`.

A mirror step on `abacaba`: centre `3` (`c`) has `d1[3] = 4`, reaching `[0, 6]`. For centre `5`, the mirror is `l + r - i = 1`, where `d1[1] = 2`. Clipped by the border `r - i + 1 = 2`, so `k` starts at 2 and the loop needs no comparison that succeeds beyond the border: `d1[5] = 2` without re-checking the letters inside. The full array is `d1 = [1, 2, 1, 4, 1, 2, 1]`.

## Alternatives

| method | time | when to use |
| --- | --- | --- |
| expand around every centre | `O(n^2)` worst case | `n` up to a few thousand, simplest code |
| interval DP on `[i, j]` | `O(n^2)` time and memory | when you also need palindromic *partitions* |
| string hashing plus binary search per centre | `O(n log n)` | when you already have rolling hashes; has collision risk |
| **Manacher** | `O(n)` | the standard answer for counting or finding the longest palindrome |
| palindromic tree (eertree) | `O(n)` | counting **distinct** palindromes, advanced |

## Pitfalls

1. **Counting palindromes versus distinct palindromes.** The sums `d1 + d2` count every occurrence at every position. For distinct palindromic substrings you need an eertree or hashing.
2. **Wrong mirror index for even lengths.** For `d2` the mirror is `l + r - i + 1`, not `l + r - i`, because even centres sit between letters.
3. **Forgetting to clip by `r - i + 1`.** Without the `min`, the mirrored radius may claim letters beyond the known palindrome.
4. **Not updating `[l, r]`.** The window must move only when the expansion passes the old `r`; otherwise the linear bound is lost.
5. **Overflow.** The count is up to `n(n+1)/2`, about `5·10^11` at `n = 10^6`: use 64-bit integers.
6. **Reading the string.** The input is a single line; trailing newline or carriage return characters create phantom letters, so strip them.
