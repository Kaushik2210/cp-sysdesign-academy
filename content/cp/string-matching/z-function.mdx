## Intuition

The [prefix function](/cp/string-matching/kmp/) answers "what is the longest border ending here?". The **Z-function** asks a more direct question about each position: "starting here, how far does the string keep matching **its own beginning**?"

For `s = aabxaab`, position `4` starts the suffix `aab`, which matches the first three characters of `s`, so `z[4] = 3`. Position `1` starts `abxaab`, which shares only `a` with the start, so `z[1] = 1`.

## Definition

`z[i]` is the length of the longest common prefix of `s` and `s[i..]`. By convention `z[0] = n` (or `0`; this lesson uses `n`).

| s | a | a | b | x | a | a | b |
| --- | --- | --- | --- | --- | --- | --- | --- |
| z | 7 | 1 | 0 | 0 | 3 | 1 | 0 |

## Computing it in linear time

Naively comparing from every position is `O(n^2)` (think of `aaaa...a`). The trick is to remember the **window** `[l, r)`: the segment that starts at some `l`, matches a prefix of `s`, and reaches furthest to the right.

For a position `i` inside the window (`i < r`), the text `s[i..r)` is a copy of `s[i-l..r-l)`. So `z[i]` is at least `min(r - i, z[i - l])` without any comparison. Then extend by direct comparison. If `i + z[i]` passes `r`, the window moves to start at `i`.

Every successful comparison moves `r` right, and `r` never moves left, so all comparisons together are `O(n)`.

    n = len(s)
    z = [0] * n

    l = r = 0

vector<int> z_function(const string& s) {
    int n = s.size();
    vector<int> z(n, 0);
    z[0] = n;
    for (int i = 1, l = 0, r = 0; i < n; i++) {

int[] zFunction(String s) {
    int n = s.length();
    int[] z = new int[n];
    z[0] = n;
    for (int i = 1, l = 0, r = 0; i < n; i++) {
        if (i < r) z[i] = Math.min(r - i, z[i - l]);
        while (i + z[i] < n && s.charAt(z[i]) == s.charAt(i + z[i])) z[i]++;

## What you can do with it

1. **Pattern search.** Compute `z` of `p + "#" + s` (a separator that appears in neither string). Every `i` with `z[i] == |p|` marks an occurrence of `p` in `s`. This is KMP's job, with a different but equivalent table.
2. **Smallest period.** The smallest `k` with `k + z[k] == n` and `n % k == 0` gives a period, if any, so the string is `n / k` copies of `s[:k]`.
3. **Borders.** `s[i..]` is a border exactly when `i + z[i] == n`, so all borders come from the positions where the Z-value reaches the end.
4. **Counting distinct substrings, string compression and similarity sums**, all of which reduce to "how long is the match with the prefix at each position".

| structure | answers | strength |
| --- | --- | --- |
| prefix function | longest border ending at each position | natural for streaming text and automata |
| Z-function | longest match with the prefix starting at each position | natural for "compare every suffix with the start" |
| string hashing | equality of arbitrary substrings | handles queries on any two substrings, but is probabilistic |

<Callout type="tip" title="Z and prefix function convert into each other">
Both arrays hold the same information about the string, and either can be derived from the other in `O(n)`. Pick whichever makes the problem's wording easier.
</Callout>

## Pitfalls

1. **Forgetting the separator** in `p + s`. Without it a match can cross the join and `z` values can exceed `|p|`.
2. **Starting the loop at `0`.** Begin at `i = 1`; `z[0]` is set by convention (here `n`) and is never read by the shortcut, since inside the window `i - l >= 1`.
3. **Using `<` instead of `<=` in the bound.** The loop condition is `i + z[i] < n`.
4. **Not updating the window** only when `i + z[i] > r`.
5. **Overflow when summing.** A sum of Z-values reaches `n(n + 1) / 2`; use 64-bit integers.
6. **Confusing `z[i]` with the prefix function.** `z[i]` starts at `i`; `pi[i]` ends at `i`.
