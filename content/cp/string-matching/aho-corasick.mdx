## Intuition

[KMP](/cp/string-matching/kmp/) finds **one** pattern in a text in `O(n + m)`. Now imagine a spam filter with ten thousand banned words, or a DNA tool searching a genome for thousands of motifs. Running KMP once per word costs `k` full passes over the text. **Aho-Corasick** reads the text **once** and finds every occurrence of every pattern simultaneously.

The idea combines two things you already know:

- A **trie** stores all the patterns as paths of letters from a common root, sharing common prefixes.
- KMP's **failure function** says "if the next letter does not extend my match, fall back to the longest shorter match that is still alive". Do exactly that, but **over the trie**.

The result is a finite automaton: after reading each letter you are in one state, and that state tells you the longest suffix of the text so far that is a prefix of some pattern.

## Definition

1. **Trie.** Insert each pattern. Each node `v` stands for the string `str(v)` spelled by the path from the root. Mark nodes where a pattern ends (count duplicates).
2. **Failure link.** `fail[v]` is the node for the **longest proper suffix of `str(v)` that is also a node of the trie** (the root if none). For children of the root, `fail` is the root.
3. **Transition function** `go(v, c)`: from state `v` reading `c`:
   - if `v` has a child `u` by `c`, move to `u`;
   - otherwise follow failure links until some node has a child by `c` (or you reach the root and stay).
4. **Match reporting.** If you are in node `v`, then every pattern that ends at the current position is a node on the chain `v, fail[v], fail[fail[v]], ...` that is marked as a word end. Define

```text
total[v] = ends[v] + total[fail[v]]
```

so that `total[state]` is **the number of patterns ending at the current position**, found with one array lookup.

**Building with a BFS.** Process nodes in order of depth (so `fail[v]`, which is shallower, is already done):

```text
for each child u of v by letter c:  fail[u] = go(fail[v], c)
for each letter c with no child:    go(v, c) = go(fail[v], c)         # complete the table
```

Filling in the missing transitions turns the automaton into a **complete DFA** (one transition per letter for every state), so scanning the text needs no loops: `state = go[state][c]`.

**Complexity.** Building costs `O(L * sigma)` where `L` is the total pattern length and `sigma` the alphabet size (or `O(L)` with a map and amortised failure-chain walking); scanning costs `O(n)`. Reporting each occurrence separately costs `O(n + z)` where `z` is the number of occurrences.

## Example, step by step

Patterns `he`, `she`, `his`, `hers`; text `ushers`.

Trie nodes: `h`, `he` (word), `her`, `hers` (word), `hi`, `his` (word), `s`, `sh`, `she` (word).

Failure links: `h`, `s`, `hi`, `her` point to the root; `he -> root`; `sh -> h`; `she -> he` (suffix `he` of `she` is a pattern node); `his -> s`; `hers -> s`.

Scan:

| letter | state | patterns ending here (via the failure chain) |
| --- | --- | --- |
| `u` | root | none |
| `s` | `s` | none |
| `h` | `sh` | none |
| `e` | `she` | `she`, and through `fail`, `he` |
| `r` | `her` | none |
| `s` | `hers` | `hers` (and `fail = s` is not a word) |

Total: `she`, `he`, `hers`: **3** occurrences. The two matches at the fourth letter come from walking the failure chain `she -> he`, which `total[she] = ends[she] + total[he] = 1 + 1 = 2` captures in one step.

class AhoCorasick:
    def __init__(self, patterns, alphabet="abcdefghijklmnopqrstuvwxyz"):
        self.alpha = alphabet
        self.next = [{}]              # next[v][ch] = child, filled completely after build()
        self.ends = [0]               # how many patterns end exactly here
        self.word = [[]]              # which patterns end exactly here (for reporting matches)
        for idx, pat in enumerate(patterns):
            v = 0
            for ch in pat:
                if ch not in self.next[v]:
                    self.next[v][ch] = len(self.next)
                    self.next.append({}); self.ends.append(0); self.word.append([])
                v = self.next[v][ch]
            self.ends[v] += 1
            self.word[v].append(idx)
        self.fail = [0] * len(self.next)
        self.total = self.ends[:]
        self.build()

    def build(self):
        q = deque()
        for ch in self.alpha:
            u = self.next[0].get(ch)
            if u is None:
                self.next[0][ch] = 0          # missing edge at the root: stay at the root
            else:
                self.fail[u] = 0
                q.append(u)
        while q:
            v = q.popleft()
            self.total[v] += self.total[self.fail[v]]
            for ch in self.alpha:
                u = self.next[v].get(ch)
                if u is None:
                    self.next[v][ch] = self.next[self.fail[v]][ch]     # follow the failure link implicitly
                else:
                    self.fail[u] = self.next[self.fail[v]][ch]
                    q.append(u)

        state, answer = 0, 0
        for ch in text:
            state = self.next[state][ch]
            answer += self.total[state]
        return answer

    def find_all(self, text, patterns):

        state, found = 0, []
        for i, ch in enumerate(text):
            state = self.next[state][ch]
            v = state
            while v:
                for idx in self.word[v]:
                    found.append((i - len(patterns[idx]) + 1, patterns[idx]))
                v = self.fail[v]

    """How many strings of length n over the alphabet contain no banned word? DP over the automaton states."""

## Applications

| problem | how the automaton helps |
| --- | --- |
| count all occurrences of many patterns | scan once, add `total[state]` per letter |
| does any banned word occur | stop at the first state with `total[state] > 0` |
| report which patterns occur, and where | follow the failure chain (or **dictionary links** that skip to the next word-end node) at each position |
| count strings of length `n` avoiding (or containing) patterns | DP over `(length, automaton state)`: `dp[i + 1][go[v][c]] += dp[i][v]`, skipping unsafe states |
| shortest string containing all patterns (shortest superstring) | bitmask DP over the set of patterns, with automaton states |
| longest or shortest match ending at each position | store `depth` of the nearest word-end node on the failure chain |
| online filters on a stream of characters | the state is all you keep between characters |

## Compared with other multi-pattern tools

| tool | time | notes |
| --- | --- | --- |
| KMP per pattern | `O(k n + L)` | too slow for many patterns |
| hashing every length | `O(n * distinct lengths)` | at most `O(sqrt L)` distinct lengths, probabilistic |
| suffix array / automaton of the text | `O(n log n)` build, `O(m)` per pattern | good when the text is fixed and patterns arrive online |
| **Aho-Corasick** | `O(n + L + z)` | patterns fixed, text streamed |

## Pitfalls

1. **Forgetting to propagate the word counts along failure links.** Without `total[v] += total[fail[v]]`, nested patterns such as `he` inside `she` are missed.
2. **Processing nodes in the wrong order.** `fail[v]` must be final before it is used: use a BFS (by depth), not a DFS.
3. **Not completing the transitions.** A missing child must be copied from the failure node, otherwise the scan needs a failure-chain loop (still correct, but harder to reason about and slower in the worst case).
4. **Failure link of a root child** must be the root, not itself.
5. **Counting duplicate patterns once.** Keep a multiplicity (counter) at word-end nodes if the list may repeat words.
6. **Memory.** `nodes * 26` integers; for large alphabets use a map per node or a compressed transition table.
7. **Overflow of the total** on repetitive texts: `n * k` can pass `2^31`.
8. **Case, separators and alphabet.** Map characters to `0..sigma-1` consistently in both the build and the scan.
