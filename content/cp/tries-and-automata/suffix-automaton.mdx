## Intuition

The **suffix automaton** (also called DAWG, directed acyclic word graph) of a string `s` is the **smallest** deterministic automaton that accepts exactly the **substrings of `s`**. It answers "is `t` a substring of `s`?" by walking `t` through the automaton, and it carries enough structure to answer many substring questions in linear time:

- the number of **distinct substrings**,
- the **longest common substring** of two strings,
- how many **times** a substring occurs,
- the lexicographically `k`-th substring, the shortest string that is **not** a substring, and more.

A trie of all suffixes would have `O(n^2)` nodes. The surprise is that merging nodes that behave identically leaves **at most `2n - 1` states and `3n - 4` transitions**, built in `O(n)` time.

## Definition

For a substring `u` of `s`, let `endpos(u)` be the set of positions in `s` where an occurrence of `u` **ends**. Two substrings with the same `endpos` set are indistinguishable for the purposes of extending them to the right, so they live in the **same state**.

Facts that make the structure work:

- All strings in one state are **suffixes of the longest one** in it, and their lengths form a contiguous range `len[link[v]] + 1 .. len[v]`.
- The **suffix link** `link[v]` leads to the state of the longest suffix of `v`'s strings that belongs to a different state (a *larger* `endpos` set, since a shorter string occurs at least as often). The links form a tree rooted at the empty-string state.
- A **transition** `v --c--> w` means: appending `c` to any string of `v` gives a string of `w`.

### Building it online

Add the letters of `s` one at a time, keeping `last`, the state of the whole prefix read so far.

```text
extend(c):
    cur = new state; len[cur] = len[last] + 1
    p = last
    while p exists and p has no transition on c:  p --c--> cur;  p = link[p]
    if p does not exist:                 link[cur] = root
    else:
        q = p's transition on c
        if len[p] + 1 == len[q]:         link[cur] = q               (q already represents exactly the right strings)
        else:                            split q:
            clone = copy of q (transitions and link), len[clone] = len[p] + 1
            redirect transitions of p and its suffix-link ancestors that pointed to q, so they point to clone
            link[q] = link[cur] = clone
    last = cur
```

Why the clone is needed: after adding `c`, the strings of `q` that are not longer than `len[p] + 1` now occur at one more end position than the longer strings of `q`, so their `endpos` sets differ and the state must be split in two. The amortised analysis (each step moves along the suffix links of `last`, whose depth increases by at most one per letter) gives total time **`O(n)`** transitions (times the alphabet handling).

## Using it

### Distinct substrings

Each state `v` (other than the root) stands for `len[v] - len[link[v]]` different substrings, and different states hold different substrings. So

```text
distinct substrings = sum over v != root of ( len[v] - len[link[v]] )
```

### Longest common substring of `s` and `t`

Build the automaton of `s`. Run `t` through it, keeping the current state `v` and the matched length `l`:

```text
for each letter c of t:
    while v != root and v has no transition on c:  v = link[v];  l = len[v]
    if v has a transition on c:  v = go(v, c);  l += 1
    best = max(best, l)
```

`l` is always the length of the longest suffix of the part of `t` read so far that occurs in `s`. Total `O(|s| + |t|)`.

### Occurrence counts

Mark the states created for prefixes (not clones) with `cnt = 1`, then add each state's `cnt` into its suffix-link parent, processing states in decreasing order of `len`. Then `cnt[v]` is `|endpos(v)|`, the number of occurrences of every string in state `v`.

What the output shows:

- On **400 random string pairs** over 2 to 4 letters, the automaton's **distinct substring count** equals a brute-force set of all substrings, and its **longest common substring** equals a brute-force search, in every case.
- **State counts** for `n = 5,000` stay below the limit of 2 states per letter:

| string | states | per letter | transitions (limit 14,996) | clones |
| --- | --- | --- | --- | --- |
| random over 26 letters | 6,282 | 1.26 | 11,258 | 1,281 |
| random over 2 letters | 9,978 | 2.00 | 13,733 | 4,977 |
| `a` followed by 4,999 `b` | 9,999 | 2.00 (exactly `2n - 1`) | 9,999 | 4,998 |
| all the same letter | 5,001 | 1.00 | 5,000 | 0 |

- The worst case for the number of states is a string like `abbb...b`, which reaches the bound `2n - 1 = 9,999` exactly. A string of one repeated letter needs only `n + 1` states, and has just `n` distinct substrings (`a`, `aa`, ..., `a^n`).
- Distinct substrings: roughly 12.5 million for each random string of length 5,000 (close to the maximum `n(n + 1)/2 = 12,502,500`), computed from only a few thousand states.

The counts come from one seeded run; the brute-force checks establish correctness.

## Suffix automaton, suffix array or hashing?

| task | suffix automaton | suffix array + LCP | hashing |
| --- | --- | --- | --- |
| number of distinct substrings | `O(n)` build, one sum | `O(n log n)` build, `n(n+1)/2 - sum(LCP)` | `O(n^2)`, or heavy |
| longest common substring of two strings | `O(n + m)` | concatenate; `O(n log n)` | binary search plus hash sets, `O(n log n)`, probabilistic |
| occurrences of a pattern | walk, then `cnt[v]` | binary search on the array | rolling hash scan |
| lexicographic order of suffixes | not provided directly | provided | not provided |
| memory | states times alphabet (or maps) | a few integer arrays | tiny |
| ease of writing | short once memorised, subtle | moderate | easiest |

Pick the suffix automaton for **substring counting and matching** on one or two strings; pick the suffix array when **suffix order** (lexicographic questions, LCP queries between suffixes) matters.

## Pitfalls

1. **Forgetting the clone's transitions and link.** The clone copies **all** transitions of `q` and `link[q]`; omitting that corrupts the automaton silently.
2. **Redirecting the wrong transitions.** After cloning, walk `p` up the suffix links redirecting only those transitions that still point to `q`.
3. **Memory.** Allocate `2n` states with a full alphabet table: for `n = 10^6` and 26 letters that is 52 million entries. Use maps or a smaller alphabet when needed.
4. **Mixing up the last state.** `last` must become `cur` (the new prefix state), never the clone.
5. **Counting occurrences without excluding clones.** Only non-clone states start with `cnt = 1`.
6. **Processing order for propagation.** Sort states by `len` (counting sort) and go from the longest to the shortest; the link tree is not in index order.
7. **Using one automaton for several strings** without separators or resetting `last`. Either build one automaton per string or separate strings with a unique character, and beware matches that cross the separator.
8. **Off-by-one in the walk.** On a failed transition set `l = len[v]` **after** moving to `link[v]`, not before.
