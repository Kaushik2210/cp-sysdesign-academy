## Intuition

Intervals (meetings, jobs, ranges of a number line) are the home turf of greedy algorithms. They come with a natural order, the number line, so "sort, then sweep once" is usually all it takes. Which end you sort by, **start or finish**, and what you do when you meet an overlap is the whole game.

This lesson covers five patterns:

1. Maximum number of non-overlapping intervals (activity selection): sort by **finish**.
2. Merge overlapping intervals: sort by **start**.
3. Minimum number of points that hit every interval: sort by **finish**.
4. Maximum overlap, or the number of rooms needed: **sweep** over events.
5. Cover a segment with the fewest intervals: sort by **start**, extend as far as possible.

## 1. Activity selection

Given intervals `[s_i, e_i)` (the end is excluded, so `[1,3)` and `[3,5)` do not conflict), choose the most pairwise disjoint intervals.

**Greedy.** Sort by end time. Take an interval if its start is at least the end of the last taken one.

**Proof (exchange).** Let `g` be the interval with the smallest end. Take any optimal solution `O`, ordered by time, and let `o_1` be its first interval. Because `end(g) <= end(o_1)` and every other interval of `O` starts at or after `end(o_1)`, replacing `o_1` with `g` keeps `O` valid and the same size. So some optimal solution contains `g`. Everything that conflicts with `g` is removed, and what remains (intervals starting at or after `end(g)`) is the same problem again. By induction greedy is optimal. ∎

<CodeRunner language="python" code={`def activity_selection(iv):
    iv = sorted(iv, key=lambda x: x[1])      # by finish time
    last = -10**18
    chosen = []
    for s, e in iv:
        if s >= last:
            chosen.append((s, e))
            last = e
    return chosen

iv = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
res = activity_selection(iv)
print(len(res), res)
`} />

**Rules that look reasonable and are wrong.** Run them against each other:

- Earliest **start** first: `[0,10), [1,2), [3,4)`. Greedy takes the long one and gets 1, optimal is 2.
- **Shortest** first: `[0,5), [4,6), [5,10)`. The shortest `[4,6)` conflicts with both others; greedy gets 1, optimal is 2.

<CodeRunner language="python" code={`def pick(iv, key):
    last = -10**9
    n = 0
    for s, e in sorted(iv, key=key):
        if s >= last:
            n += 1
            last = e
    return n

a = [(0, 10), (1, 2), (3, 4)]
b = [(0, 5), (4, 6), (5, 10)]

    print(name,
          "by end:", pick(iv, lambda x: x[1]),
          "by start:", pick(iv, lambda x: x[0]),

## 2. Merging intervals

Sort by start and sweep, extending the current block while the next interval starts at or before the block's end.

<CodeRunner language="python" code={`def merge(iv):
    iv = sorted(iv)
    out = []
    for s, e in iv:
        if out and s <= out[-1][1]:
            out[-1][1] = max(out[-1][1], e)
        else:
            out.append([s, e])
    return out

print(merge([(1, 3), (2, 6), (8, 10), (15, 18), (17, 20), (6, 7)]))
`} />

For closed intervals, touching endpoints merge (`s <= end`); for half-open intervals, `[1,3)` and `[3,5)` also join into `[1,5)` in the sense of covered points, so the same test applies when you want the covered set.

## 3. Minimum points that hit every interval

Place the fewest integer points so that every closed interval `[l, r]` contains a point. Sort by right end; whenever the next interval is **not** hit by the last point (`l > last`), place a point at its right end `r`.

**Proof.** The interval with the smallest right end `r` must receive a point somewhere in `[l, r]`. Every other interval has right end at least `r`; if it contains some `x <= r` of this one's range, it also contains `r` (it extends from at most `x` to at least `r`). So a point at `r` hits whatever any other position in `[l, r]` could hit: moving the point to `r` never hurts. Remove everything containing `r` and repeat. ∎

<CodeRunner language="python" code={`def min_points(iv):
    iv = sorted(iv, key=lambda x: x[1])
    last = None
    pts = []
    for l, r in iv:
        if last is None or l > last:
            last = r
            pts.append(r)
    return pts

print(min_points([(1, 3), (2, 5), (4, 6), (7, 9), (8, 12)]))
`} />

This is the same sort order as activity selection, and in fact the minimum number of points equals the maximum number of pairwise disjoint intervals (a duality worth remembering).

## 4. Maximum overlap by sweeping events

How many rooms are needed for a set of meetings? Turn every interval into two **events**: `+1` at the start and `-1` at the end. Sort events by time and keep a running count; the maximum of the count is the answer. For half-open intervals, process `-1` before `+1` at the same time, so `[1,3)` and `[3,5)` share a room.

<CodeRunner language="python" code={`def max_overlap(iv):
    events = []
    for s, e in iv:
        events.append((s, 1))
        events.append((e, -1))
    events.sort()                 # at equal time, -1 comes before +1
    cur = best = 0
    for _, d in events:
        cur += d
        best = max(best, cur)
    return best

print(max_overlap([(1, 3), (2, 5), (3, 6), (4, 7), (7, 9)]))
`} />

(`(3, -1)` sorts before `(3, 1)`, which is exactly the tie rule we want.) Cost `O(n log n)` for the sort, `O(n)` for the sweep.

## 5. Cover a segment with the fewest intervals

Given a target `[0, L]` and a set of intervals, pick the fewest whose union covers it. Sort by start. Keep the current covered prefix `[0, cur]`. Among all intervals with `start <= cur`, take the one with the largest end; if it does not extend `cur`, covering is impossible. Repeat until `cur >= L`. The proof is the "farthest reach" argument from the refuel problem: any interval starting at or before `cur` and reaching less far than the best one is dominated.

<CodeRunner language="python" code={`def cover(iv, L):
    iv = sorted(iv)
    cur, i, used = 0, 0, 0
    while cur < L:
        best = cur
        while i < len(iv) and iv[i][0] <= cur:
            best = max(best, iv[i][1])
            i += 1
        if best == cur:
            return -1
        used += 1
        cur = best
    return used

print(cover([(0, 3), (2, 6), (5, 9), (1, 4), (8, 12)], 12))
print(cover([(0, 3), (5, 9)], 9))
`} />

## Pitfalls

<Callout type="pitfall" title="Interval bugs">
1. **Open vs closed ends:** decide whether touching intervals conflict, then use `>=` or `>` consistently, including in the tie order of sweep events.
2. **Sorting by start when you need end** (activity selection and point stabbing), or the reverse for merging.
3. **Using the previous interval's end instead of the running maximum** when merging: `[1,10], [2,3], [4,5]` has to keep end 10 after the nested interval.
4. **Integer vs real points:** for closed integer intervals a point can sit at an endpoint; for real intervals the same greedy still applies.
5. **Ties on the sort key:** with the same end, order by start is irrelevant for activity selection but a second key keeps output deterministic.
</Callout>
