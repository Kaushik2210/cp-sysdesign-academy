## Intuition

**Interval DP** solves problems where a segment `[i, j]` is built from two smaller segments split at some point `m`:

```text
dp[i][j] = min over i < m < j of  ( dp[i][m] + dp[m][j] )  +  cost(i, j)
```

There are `O(n^2)` intervals and `O(n)` split points for each, so the plain DP is `O(n^3)`: fine for `n = 400`, hopeless for `n = 3000`. **Knuth's optimisation** observes that in many such problems **the best split point moves monotonically**: if you make the interval a little longer, the best split never jumps backwards. So you only need to look at split points **between the best splits of two neighbouring intervals**, and the total work over all intervals collapses to `O(n^2)`.

Typical problems: **cutting a stick** (each cut costs the length of the piece), **merging adjacent piles** (each merge costs the combined size), **optimal binary search trees** (build a tree of minimum expected search cost), and similar "recursive splitting" tasks.

## Definition

Let `opt[i][j]` be the **smallest** `m` achieving the minimum for `dp[i][j]`. The optimisation applies when

```text
opt[i][j-1]  <=  opt[i][j]  <=  opt[i+1][j]
```

(the best split of `[i, j]` lies between the best split of `[i, j-1]` and that of `[i+1, j]`). So compute the intervals in **increasing order of length**, and for `[i, j]` search only `m` from `opt[i][j-1]` to `opt[i+1][j]`.

### When is it valid?

A sufficient condition on the cost function `w(i, j) = cost(i, j)` (the **quadrangle inequality** and **monotonicity**):

```text
w(a, c) + w(b, d)  <=  w(a, d) + w(b, c)      for  a <= b <= c <= d      (quadrangle inequality)
w(b, c)  <=  w(a, d)                            for  a <= b <= c <= d      (monotone on the lattice of intervals)
```

For the stick problem `w(i, j) = p[j] - p[i]` holds with **equality** in the first line, and monotonicity is obvious. For merging piles, `w(i, j)` is the sum of the piles from `i` to `j`, which also satisfies both. Without such a property the monotonicity of `opt` can fail and the answer will be wrong, so check the condition, or test the optimised DP against the cubic one on random small inputs.

### Why the total work is quadratic

Fix the length `gap = j - i`. The ranges searched for the intervals of this length are `[opt[i][j-1], opt[i+1][j]]`. Consecutive intervals `[i, j]` and `[i+1, j+1]` share an endpoint of their ranges: the upper end of the first, `opt[i+1][j]`, is the lower end of the second, `opt[i+1][j]`. The ranges therefore **telescope**: their total length over one `gap` is at most `n` plus the number of intervals. With `n` values of `gap`, the total is `O(n^2)`.

### The stick problem in code

Points `p[0] = 0 < p[1] < ... < p[k] < p[k+1] = L`. `dp[i][i+1] = 0`; for longer intervals `m` ranges over the interior points, clamped to `i + 1 .. j - 1`.

<Tab label="Python">

```python
size = k + 2
dp = [[0] * size for _ in range(size)]
opt = [[0] * size for _ in range(size)]
for i in range(size - 1):
    opt[i][i + 1] = i
for gap in range(2, size):
    for i in range(size - gap):
        j = i + gap
        best, arg = None, -1
        for m in range(max(opt[i][j - 1], i + 1), min(opt[i + 1][j], j - 1) + 1):

                best, arg = v, m
        dp[i][j] = best + p[j] - p[i]
        opt[i][j] = arg
```

## Related optimisations

| technique | recurrence shape | speed-up |
| --- | --- | --- |
| **Knuth** | `dp[i][j] = min over m of dp[i][m] + dp[m][j] + w(i, j)` (interval) | `O(n^3)` to `O(n^2)` |
| **Divide and conquer optimisation** (previous lessons) | `dp[g][j] = min over k < j of dp[g-1][k] + w(k, j)` (layers) | `O(g n^2)` to `O(g n log n)` |
| **Convex hull trick and Li Chao tree** | `dp[j] = min over k of dp[k] + a_k * x_j + b_k` | `O(n^2)` to `O(n log n)` |
| **Monge matrices and SMAWK** | row minima of a totally monotone matrix | linear per layer |
| **Aliens trick (Lagrangian relaxation)** | a count constraint on a convex cost | `O(n log C)` |

Knuth's optimisation is the one for **interval** recurrences with a split point. The related result by Yao (1980) shows the quadrangle inequality is what makes it work.

## Pitfalls

1. **Applying it without the property.** If `w` does not satisfy the quadrangle inequality, `opt` may not be monotone and the result is silently wrong. Always cross-check against the cubic DP on small random inputs.
2. **Forgetting to clamp `m`** to `i + 1 .. j - 1`. For `gap = 2` the unclamped range can include `i` or `j`, which gives an invalid (too cheap) split.
3. **Initialising `opt` wrongly** for `j = i + 1`. A common choice is `opt[i][i+1] = i` with the clamp above; or `i + 1` with the other clamp. Be consistent.
4. **Taking the largest minimiser on ties** in one place and the smallest in another. Use the same tie rule everywhere (the smallest).
5. **Processing in the wrong order.** Intervals must be computed by increasing length so `opt[i][j-1]` and `opt[i+1][j]` exist.
6. **Overflow.** Costs sum to about `L * k` and more: use 64-bit integers.
7. **Memory.** Two `n x n` tables: 1000 by 1000 is fine, 5000 by 5000 is 25 million entries each (consider `int` for `opt`).
8. **Mixing up merging piles with cutting a stick**: in merging, the cost of an interval is the **sum of the piles** (a prefix-sum difference), not a difference of positions.
