## Intuition

You have an array `f` indexed by **bitmasks**: `f[mask]` is a number attached to the set of bits in `mask`. Often you need, for every mask, the **sum of `f` over all of its submasks** (all masks whose set bits are a subset of those of `mask`):

```text
F[mask] = sum of f[sub]  over all sub with  sub & mask == sub
```

Computing `F[mask]` for one mask by listing its submasks costs `2^(number of set bits)`. Doing it for **every** mask costs `3^bits` in total (every bit is: absent, present in `mask` only, or present in both). For 20 bits that is 3.5 billion operations. **Sum over subsets (SOS) DP** computes all `F` in **`bits * 2^bits`** operations (about 21 million for 20 bits) by handling **one bit at a time**.

## Definition

Think of the bits as dimensions of a `bits`-dimensional cube with two points per axis. The sum over submasks is a **prefix sum on this cube**, and a multi-dimensional prefix sum is computed by doing a one-dimensional prefix sum along each axis in turn:

```text
for b in 0 .. bits-1:
    for mask in 0 .. 2^bits - 1:
        if mask has bit b:
            f[mask] += f[mask without bit b]
```

After processing bits `0..b`, `f[mask]` holds the sum over the submasks that differ from `mask` only in bits `0..b` (they may drop any of those bits but must keep every bit above `b`). After all bits, `f[mask]` is the sum over **all** submasks. The update can be done in place: when bit `b` is processed, `f[mask]` (which has the bit) reads `f[mask without b]` (which does not), and masks without bit `b` are never changed in this pass, so the value read is still the one from the previous pass.

Cost: `bits * 2^bits` additions (half of the masks have each bit, so `bits * 2^(bits-1)`).

### Variations

| need | change |
| --- | --- |
| sum over **supersets** `F[mask] = sum of f[sup]` with `sup` containing `mask` | for masks **without** bit `b`: `f[mask] += f[mask | bit]` |
| **max** or **min** over submasks | replace `+=` with `max`/`min` (SOS works for any associative, commutative operation that is idempotent or invertible as needed) |
| the **inverse** (recover `f` from the subset sums; **Möbius transform**) | for each bit, `f[mask] -= f[mask without bit]` |
| number of pairs `(i, j)` with `a_i & a_j == 0` | count `cnt[mask]`, sum over submasks of the **complement** of `a_i` |
| for each `a_i`, does a submask or supermask exist in the array (with a witness) | store an index or a value instead of a count and combine with `max` |
| **subset convolution** `h[S] = sum over A subset S of f[A] * g[S minus A]` | rank by popcount and use the zeta and Möbius transforms: `O(2^n n^2)` |
| counting by **inclusion-exclusion** over a set of conditions | Möbius transform over the subset lattice |

def zeta_subsets(f, bits):
    """f[mask] becomes the sum of the original f over all submasks of mask. Returns the number of additions."""
    adds = 0
    for b in range(bits):
        bit = 1 << b
        for mask in range(1 << bits):
            if mask & bit:
                f[mask] += f[mask ^ bit]
                adds += 1
    return adds


def mobius_subsets(f, bits):
    """The inverse: recover the original values from the subset sums."""
    for b in range(bits):
        bit = 1 << b
        for mask in range(1 << bits):
            if mask & bit:
                f[mask] -= f[mask ^ bit]


def zeta_supersets(f, bits):
    for b in range(bits):
        bit = 1 << b
        for mask in range(1 << bits):
            if not mask & bit:
                f[mask] += f[mask | bit]

What the output shows:

- With **12 bits** and random values, the SOS result equals the sum over every submask for all **4,096** masks. It uses **24,576 additions**, while enumerating submasks mask by mask visits **531,441** (that is `3^12`).
- The gap grows quickly: for **16 bits** about **82 times** fewer operations (524,288 against 43,046,721), for **20 bits** about **332 times** (10,485,760 against 3,486,784,401), for **22 bits** about **680 times**.
- The **inverse transform** (subtracting in the same order) recovers the original values exactly.
- The **superset** version gives the same answer as brute force for the example mask `000000101101`.

The counts are exact for the stated sizes; the checks against brute force establish correctness.

## Typical uses

1. **Counting submasks or supermasks in an array**, as in the practice problem.
2. **Pairs with `a_i & a_j = 0`**: for each `a_i`, the number of `a_j` that are submasks of its complement `~a_i`.
3. **DP over subsets where the transition ranges over submasks**: if `dp[mask]` needs `combine over sub of mask`, SOS can sometimes turn the `3^n` transition into `n * 2^n`.
4. **Existence queries** such as "is there another number in the array that is a submask of `x`, and which one", by storing an index in `f`.
5. **Inclusion-exclusion made mechanical**: the Möbius transform computes, for each set `S`, the count of objects whose "bad set" is exactly `S` from the counts of objects whose bad set is contained in `S`.

## Pitfalls

1. **Wrong loop order.** The outer loop must be over **bits**, the inner over masks. Swapping them computes something else.
2. **Updating the wrong side.** For submask sums add from `mask without bit` into `mask`; for supermask sums, the other direction.
3. **Not counting multiplicity.** Put `f[v] += 1` (not `= 1`) when values can repeat.
4. **Too many bits.** The array needs `2^bits` entries: 20 bits is 1 million, 24 bits is 16 million (about 64 MB in 32-bit integers).
5. **Overflow.** Sums over submasks can exceed 32 bits when values are large: use 64-bit.
6. **Mixing indices.** The value of a number is its index into the array; compress or limit the range first if values are large (or use bits of a hash if exactness is not required).
7. **Using SOS when only one query is needed.** For a single mask, enumerating its submasks directly is cheaper.
8. **Forgetting that the transform is in place** and destroys the original array: copy if you need both.
