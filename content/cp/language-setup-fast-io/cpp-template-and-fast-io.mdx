## Intuition

Before algorithms, you need a **tool chain that gets out of your way**: an editor, a compiler with sensible flags, a template you trust, and input/output code that is fast enough that it is never the reason you fail. This lesson sets that up, with C++ as the main language and Python and Java equivalents.

Why does I/O speed matter? A problem with `2 * 10^5` numbers means roughly a megabyte of text. Naive reading in some languages (C++ `cin` with default settings, Python `input()` in a loop, Java `Scanner`) can take longer than your whole algorithm. A correct `O(n)` solution that times out because of reading is a very avoidable loss.

## Your local setup

- **Editor:** anything you can type quickly in (VS Code, CLion, Vim). Turn on a bracket matcher and syntax colours; avoid heavy autocomplete you do not control.
- **Compiler (C++):** `g++` with `-std=c++17 -O2` and, for development, warnings and sanitizers:

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -o sol sol.cpp
./sol < in.txt
```

- **Input redirection:** put the sample in `in.txt` and run with `< in.txt`. Never type samples by hand repeatedly.
- **Folder per contest:** `A.cpp`, `B.cpp`, ... plus `in.txt`. Keep a `template.cpp` you copy.

## A C++ template

Keep it small. Every line you do not understand is a future bug.

```cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;

int main() {
    ios::sync_with_stdio(false);   // do not sync C and C++ streams
    cin.tie(nullptr);              // do not flush cout before every cin

    int t = 1;
    // cin >> t;                   // uncomment for multi-test problems
    while (t--) {
        int n;
        cin >> n;
        vector<ll> a(n);
        for (auto &x : a) cin >> x;
        // solve
        ll s = 0;
        for (ll x : a) s += x;
        cout << s << '\n';         // '\n' is much faster than endl
    }
    return 0;
}
```

What each piece buys you:

| Line | Why |
| --- | --- |
| `#include <bits/stdc++.h>` | One include for the whole standard library (a GCC extension; fine on contest judges) |
| `using ll = long long;` | Short alias to make 64-bit the default habit |
| `sync_with_stdio(false)` | Makes `cin`/`cout` about as fast as `scanf`/`printf` |
| `cin.tie(nullptr)` | Avoids a flush on every read |
| `'\n'` not `endl` | `endl` flushes the buffer every line, which is slow for large output |

<Callout type="pitfall" title="After sync_with_stdio(false), never mix C and C++ I/O">
Do not use `scanf`/`printf` together with `cin`/`cout` in one program once synchronisation is off; the order of output can become scrambled. Also, `cout << flush` or `endl` is needed only for **interactive** problems.
</Callout>

import sys
data = sys.stdin.buffer.read().split()   # read everything once, as bytes
n = int(data[0])
s = 0
for i in range(n):
    s += int(data[1 + i])
sys.stdout.write(str(s) + "\n")

<Tab label="Java">

```java
import java.util.*;
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StreamTokenizer in = new StreamTokenizer(br);   // fast, but doubles: fine up to 2^53
        in.nextToken();
        int n = (int) in.nval;
        long s = 0;
        for (int i = 0; i < n; i++) { in.nextToken(); s += (long) in.nval; }
        PrintWriter out = new PrintWriter(new BufferedWriter(new OutputStreamWriter(System.out)));
        out.println(s);
        out.flush();   // never forget to flush
    }
}
```

</Tab>
</Tabs>

<Callout type="note" title="Java: tokenizer choice">
`StreamTokenizer` parses numbers as `double`, which is exact up to `2^53` (about `9 * 10^15`) but loses precision for 64-bit values near `10^18`. For those, read lines with `BufferedReader` and split with `StringTokenizer`, then `Long.parseLong`.
</Callout>

## Output speed: build once, print once

When you print many lines, collect them and write once.

<Tabs>
<Tab label="C++">

```cpp
// cout << x << '\n' in a loop is fine with sync off. For huge output:
string out;
for (int i = 0; i < n; i++) { out += to_string(res[i]); out += '\n'; }
cout << out;
```

</Tab>
<Tab label="Python">

```python
print("\n".join(map(str, results)))   # one write, not n prints
```

</Tab>
<Tab label="Java">

```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) sb.append(res[i]).append('\n');
System.out.print(sb);
```

</Tab>
</Tabs>

<Complexity time="O(total input size)" space="O(total input size)" note="reading everything at once costs memory equal to the input; usually fine for 10^6 tokens" />

## Pitfalls

- Using `int` for values that can exceed `2 * 10^9`: define `ll` and use it by default for sums, products and prefix arrays.
- Reading `n` and then fewer or more numbers than the format promises (the program silently continues with garbage).
- Forgetting to reset global arrays between test cases in multi-test problems.
- Forgetting `flush()` in Java's `PrintWriter` so nothing is printed.
- Printing floating point without fixing precision: `cout << fixed << setprecision(9) << x`.
