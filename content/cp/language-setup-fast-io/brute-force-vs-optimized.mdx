## Intuition

A brute force is a promise: *"I will examine every possibility, so I cannot miss the answer."* It is slow, but it is **trustworthy**. An optimised solution is a claim: *"I can skip most possibilities and still not miss the answer."* Optimising is the art of justifying that claim, and then **validating** it against the brute force.

This lesson gives a method to go from the first to the second without losing correctness.

## The method

1. **Write the brute force and name its cost** (`O(n^2)`, `O(2^n)`...).
2. **Find what is repeated.** Which sub-computation does the brute force perform again and again? That is the opportunity.
3. **Name an invariant or a reusable quantity** (a running sum, the best answer ending here, a sorted order, a map from value to last index).
4. **Derive the optimised algorithm** and argue why it covers every case the brute force did.
5. **Validate** with a stress test against the brute force, then time it at maximum size.

<Callout type="note">
Step 4 is a short *argument*, not a proof in the formal sense: "the best segment ending at `i` either extends the best one ending at `i-1` or starts at `i`" is already a complete justification for Kadane's algorithm.
</Callout>

## Worked example: maximum segment sum

**Problem.** Given `n` integers (possibly negative), find the maximum sum of a non-empty contiguous segment.

**Brute force.** Try every pair `(i, j)`; summing each from scratch is `O(n^3)`. Maintaining a running sum while extending `j` makes it `O(n^2)`.

**The repeated work.** For a fixed end `j`, the brute force looks at every start `i` again, even though the best start for `j` is closely related to the best start for `j - 1`.

**The reusable quantity.** Let `cur(j)` be the best sum of a segment **ending at `j`**. Then

`cur(j) = max(a[j], cur(j-1) + a[j])`

because a segment ending at `j` is either just `a[j]`, or a segment ending at `j-1` extended by `a[j]`. The answer is `max_j cur(j)`.

<CodeRunner language="python" code={`import random

def brute(a):
    best = a[0]
    for i in range(len(a)):
        s = 0
        for j in range(i, len(a)):
            s += a[j]
            best = max(best, s)
    return best

def kadane(a):
    cur = best = a[0]
    for x in a[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best

random.seed(5)
for _ in range(2000):
    n = random.randint(1, 9)
    a = [random.randint(-6, 6) for _ in range(n)]
    assert brute(a) == kadane(a), a
print("2000 random tests agree")

# operation counts for n = 3000
n = 3000
print("brute inner steps:", n * (n + 1) // 2)
print("kadane steps     :", n)

## How much faster is "faster"?

Count operations rather than guess. For `n = 2 * 10^5`:

| Algorithm | Steps | Approximate time at `10^8` steps/s |
| --- | --- | --- |
| `O(n^3)` brute force | `8 * 10^15` | about 80 million seconds |
| `O(n^2)` brute force | `2 * 10^10` | about 200 seconds |
| `O(n)` Kadane | `2 * 10^5` | 0.002 seconds |

An optimisation is only *needed* when the brute force exceeds the budget. If `n <= 1000`, `O(n^2)` is the better answer: simpler and safer.

## Validating an optimisation: a checklist

- **Equal on random small inputs** (stress test with `n` from 1 to 8 and small values including negatives).
- **Equal on handcrafted edge cases**: `n = 1`, all negative, all zero, alternating signs, single huge value.
- **Fast on the maximum input**: generate `n = 2 * 10^5` of the worst shape and time it; for `O(n^2)` vs `O(n)` the difference is dramatic.
- **No overflow at maximum values**: use the largest possible magnitudes in the generator once.

<Callout type="pitfall" title="Typical optimisation bugs">
- Initialising the best answer to `0`, which silently allows the empty segment (wrong when all values are negative).
- Using `int` when sums reach `n * 10^9`.
- An optimisation that is only correct under an assumption (sorted input, distinct values) that the brute force did not need.
- Forgetting that the optimised version has a different **tie-breaking** behaviour when the problem asks for a specific index.
</Callout>
