## Intuition

Guess a number between 1 and 1000. If each guess is answered "higher" or "lower", you never need more than 10 guesses, because every answer **throws away half** of what is left. Binary search is that game on data: whenever a question's answer flips from NO to YES exactly once as you move along an ordered range, you can find the flip point in `O(log n)` questions instead of `O(n)`.

## Formal idea: a monotone predicate

Let `P(i)` be a yes/no question about index (or value) `i`. If `P` is **monotone**, meaning it is false for a while and then true forever (`F F F T T T`), binary search finds the first `T`.

The most reliable template keeps a half-open range `[lo, hi)` and an **invariant**: *the first true index is always inside `[lo, hi]`*.

```python
def first_true(lo, hi, P):
    # P(i) is False for i < answer and True for i >= answer; answer may be hi
    while lo < hi:
        mid = (lo + hi) // 2
        if P(mid):
            hi = mid          # mid might be the answer, keep it
        else:
            lo = mid + 1      # mid is false, so the answer is after it
    return lo
```

Each iteration strictly shrinks the range (`lo = mid + 1` or `hi = mid` with `mid < hi`), so it always terminates, and it runs `⌈log2(hi − lo + 1)⌉` iterations.

## Searching a sorted array

"Does `x` occur?" and "how many items are `≤ x`?" are both first-true questions:

- first index with `a[i] >= x` is **lower_bound**
- first index with `a[i] > x` is **upper_bound**
- count of items `≤ x` equals `upper_bound(x)`

<Tabs>
<Tab label="C++">

```cpp
// count of elements <= x in sorted vector a
int cnt = upper_bound(a.begin(), a.end(), x) - a.begin();
```

</Tab>
<Tab label="Python">

```python
from bisect import bisect_right
cnt = bisect_right(a, x)
```

</Tab>
<Tab label="Java">

```java
// no built-in upper_bound for arrays; write the loop
int lo = 0, hi = a.length;
while (lo < hi) {
    int mid = (lo + hi) >>> 1;     // >>> avoids int overflow of lo + hi
    if (a[mid] <= x) lo = mid + 1; else hi = mid;
}
// lo is the count of elements <= x
```

</Tab>
</Tabs>

<Complexity time="O(log n) per query" space="O(1)" note="after the array is sorted: O(n log n) once" />

## Binary search on the answer

The same idea works when there is no array at all. If you can write a fast check `ok(v)` that is monotone in `v` ("is it possible with budget `v`?"), search the **value** range.

Example: the smallest integer `r` with `r * r >= n`. The predicate `r*r >= n` is `F…F T…T`, so:

<CodeRunner language="python" code={`n = int(input())
lo, hi = 0, n          # answer is in [0, n]
while lo < hi:
    mid = (lo + hi) // 2
    if mid * mid >= n:
        hi = mid
    else:
        lo = mid + 1
print(lo)
`} stdin={"50\n"} />

This pattern (monotone feasibility check plus binary search on the value) solves a huge family of "minimise the maximum" and "maximise the minimum" problems. For floating-point answers, loop a fixed number of times (about 60 to 100) instead of testing `lo < hi`.

<Callout type="pitfall" title="The three classic bugs">
1. **Infinite loop:** writing `lo = mid` together with `mid = (lo + hi) // 2` never advances when `hi = lo + 1`. Use the half-open template above, or round `mid` up when you set `lo = mid`.
2. **Overflow:** `(lo + hi)` can overflow 32-bit ints. Use `lo + (hi - lo) / 2` in C++ and `>>> 1` in Java.
3. **Non-monotone predicate:** if the answer is not `F…F T…T`, binary search silently returns garbage. Prove monotonicity first.
</Callout>
