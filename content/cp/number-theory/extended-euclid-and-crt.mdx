## Intuition

Euclid's algorithm tells you **how big** the gcd of two numbers is. The **extended** version also tells you **how to build it** from the two numbers: it finds integers `x` and `y` with

```text
a * x + b * y = gcd(a, b)
```

That single identity (Bezout's identity) is the key to most of number theory in contests:

- It gives **modular inverses for any modulus**, not only primes (Fermat's little theorem needs a prime).
- It solves **linear congruences** `a x = b (mod m)` and **linear Diophantine equations** `a x + b y = c`.
- It powers the **Chinese remainder theorem (CRT)**: combining congruences with different moduli into one, even when the moduli share factors.

Think of the stories: a robot visiting every 4 days and another every 6; when do they coincide? "What number leaves remainder 2 when divided by 3, 3 when divided by 5 and 2 when divided by 7?" (Sunzi, around the 3rd century, answer 23.) CRT is the general tool.

## Definition

**Bezout's identity.** For integers `a, b` (not both zero) there exist integers `x, y` with `a x + b y = gcd(a, b)`. All integers of the form `a x + b y` are exactly the multiples of the gcd.

**Extended Euclid.** Run Euclid's recursion and carry the coefficients back up. If `b = 0` then `gcd = a` with `(x, y) = (1, 0)`. Otherwise recurse on `(b, a mod b)` to get `(g, x1, y1)` with `b x1 + (a mod b) y1 = g`. Since `a mod b = a - floor(a / b) * b`:

```text
b*x1 + (a - floor(a/b)*b) * y1 = g
a*y1 + b*(x1 - floor(a/b)*y1)  = g          so   x = y1,   y = x1 - floor(a/b) * y1
```

It runs in `O(log min(a, b))` and the coefficients are bounded by `max(|a|, |b|)` in absolute value.

**Modular inverse.** If `gcd(a, m) = 1`, then `a x + m y = 1` gives `a x = 1 (mod m)`, so `x mod m` is the inverse of `a`. If `gcd(a, m) > 1` there is **no** inverse.

**Linear congruence** `a x = b (mod m)`. Let `g = gcd(a, m)`.

- If `g` does not divide `b`: no solution.
- Otherwise divide everything by `g`: `(a/g) x = (b/g) (mod m/g)`. Now `a/g` is invertible modulo `m/g`, so `x = (b/g) * inv(a/g) (mod m/g)`, and the full set of solutions modulo `m` is `x0, x0 + m/g, x0 + 2m/g, ...`: exactly `g` solutions.

**Linear Diophantine equation** `a x + b y = c`. Solvable iff `gcd(a, b)` divides `c`. If `(x0, y0) = (x, y) * (c / g)` from the extended Euclid, all solutions are `(x0 + k b/g, y0 - k a/g)` for integer `k`.

## The Chinese remainder theorem

**Coprime moduli.** If `m1, m2, ..., mk` are pairwise coprime, the system `x = r_i (mod m_i)` has a **unique** solution modulo `M = m1 m2 ... mk`. One way to build it: `x = sum of r_i * M_i * inv(M_i mod m_i)` where `M_i = M / m_i`.

**General moduli (merging).** Maintain `x` and `M` so that the solutions so far are exactly `x + M Z`. To add `x = r (mod m)`:

1. We need `t` with `x + M t = r (mod m)`, i.e. `M t = (r - x) (mod m)`: a linear congruence.
2. Let `g = gcd(M, m)`. No solution unless `g` divides `r - x`.
3. `t = ((r - x)/g) * inv(M/g, m/g) (mod m/g)`.
4. New state: `x = x + M t`, `M = lcm(M, m) = M/g * m`.

If any step fails, the whole system has no solution. When it succeeds, the result is the **smallest non-negative** solution and its period `lcm(m1..mk)`.

## Example, step by step

Sunzi's problem: `x = 2 (mod 3)`, `x = 3 (mod 5)`, `x = 2 (mod 7)`.

- Start `x = 0, M = 1`. Merge `(2, 3)`: `g = 1`, `t = 2 * inv(1, 3) = 2`, so `x = 2`, `M = 3`.
- Merge `(3, 5)`: need `3 t = 3 - 2 = 1 (mod 5)`. `inv(3) mod 5 = 2`, so `t = 2`, `x = 2 + 3*2 = 8`, `M = 15`. Check: `8 mod 3 = 2`, `8 mod 5 = 3`.
- Merge `(2, 7)`: need `15 t = 2 - 8 = -6 = 1 (mod 7)`. `15 mod 7 = 1`, `inv = 1`, so `t = 1`, `x = 8 + 15 = 23`, `M = 105`. The answer is **23**, repeating every 105.

A non-coprime example: `x = 2 (mod 6)` and `x = 4 (mod 10)`. `g = gcd(6, 10) = 2` divides `4 - 2 = 2`, so a solution exists: `t = (2/2) * inv(3, 5) = 2`, `x = 2 + 6*2 = 14`, `M = 30`. And `x = 0 (mod 2)`, `x = 1 (mod 4)` has no solution: `g = 2` does not divide `1`.

## Which tool for which problem

| question | tool |
| --- | --- |
| `a^{-1} mod p`, `p` prime | Fermat: `pow(a, p - 2, p)` |
| `a^{-1} mod m`, `m` any, `gcd(a, m) = 1` | extended Euclid |
| inverses of `1..n` modulo a prime | the linear recurrence `inv[i] = -(p / i) * inv[p mod i] mod p` |
| `a x = b (mod m)` | `g = gcd(a, m)`, check `g` divides `b`, reduce, invert |
| `a x + b y = c` in integers | extended Euclid, then shift by `(b/g, -a/g)` |
| combine `x = r_i (mod m_i)` | iterative merging (above) |
| huge answer beyond 64 bits | big integers, or 128-bit multiplication in the merge |
| nonnegative `x` smallest | reduce `x` modulo the current `lcm` after each step |

## Pitfalls

1. **Negative values after `%`.** In C++ and Java `(r - x) % m` can be negative. Normalise: `((v % m) + m) % m`.
2. **Using Fermat for a composite modulus.** `pow(a, m - 2, m)` is wrong when `m` is not prime. Use extended Euclid.
3. **Forgetting the divisibility test** `g | (r - x)`. Without it you return garbage for inconsistent systems.
4. **Overflow in `M * t` or `(r - x) * inv`.** Both factors can approach `10^9` or more. Reduce `t` modulo `m/g` first, and use `__int128`, `Math.multiplyHigh` or BigInteger when the lcm is large.
5. **Inverse modulo 1.** When `m/g = 1`, every integer is congruent to 0: return `t = 0` instead of dividing.
6. **Reducing before dividing by `g`.** Divide `(r - x)` by `g` while it is the exact multiple, then reduce modulo `m/g`.
7. **Assuming coprime moduli.** The textbook CRT formula breaks when moduli share factors; the merge method handles both cases.
8. **Recursion depth for huge Fibonacci-like inputs.** Extended Euclid depth is `O(log)`, so it is safe, but write it iteratively for hot loops.
