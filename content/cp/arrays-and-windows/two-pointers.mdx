## Intuition

You and a friend search a sorted bookshelf for two books whose page counts add up to 500. You start at opposite ends. If the sum is too small, the left book is too thin to pair with **anything** to its right (the right end was the thickest option), so you discard it. If the sum is too big, the right book is too thick for anything to its left. Each step throws away a book for good, so the search ends after one pass.

That is two pointers: two indices that only move in one direction, so the total movement is `O(n)`, while each move is justified by a **discard argument**.

## The three shapes

### 1. Opposite ends (sorted array)

`i = 0`, `j = n - 1`; move one of them inward depending on a comparison. Used for pair sums, container problems, palindromes, and "closest sum".

### 2. Same direction, reader and writer

Both start at 0; `j` scans, `i` marks where the next kept element goes. Used for deduplication, removing a value, partitioning.

### 3. Two sequences

One pointer per array: merging, intersection, union, and "is `s` a subsequence of `t`". (A sliding window is a same-direction variant; see [Sliding Window](/cp/arrays-and-windows/sliding-window/).)

## Pair sum in a sorted array

**Task.** Is there a pair `i < j` with `a[i] + a[j] = T` in a sorted array?

Correctness (the discard argument): suppose `a[i] + a[j] < T`. For any `j' <= j`, `a[i] + a[j'] <= a[i] + a[j] < T`, so `a[i]` cannot be part of any valid pair that uses a partner at or left of `j`. Partners right of `j` were already discarded earlier. So `a[i]` is useless and `i` can advance. The case `> T` is symmetric.

<CodeRunner language="python" code={`def has_pair(a, T):
    i, j = 0, len(a) - 1
    while i < j:
        s = a[i] + a[j]
        if s == T:
            return (i, j)
        if s < T:
            i += 1
        else:
            j -= 1
    return None

a = [1, 3, 4, 6, 8, 11]
print(has_pair(a, 10))   # (2, 3): 4 + 6
print(has_pair(a, 2))    # None
`} />

<Complexity time="O(n)" space="O(1)" note="after sorting, which is O(n log n) if the input is not sorted" />

### Counting pairs with duplicates

Counting all pairs with sum `T` needs care when values repeat. When `a[i] != a[j]`, count the block of copies of `a[i]` times the block of copies of `a[j]`, then skip both blocks. When `a[i] == a[j]` the whole remaining range is one value `v` with `2v = T`, giving `m(m-1)/2` pairs for a block of size `m`.

<CodeRunner language="python" code={`def count_pairs(a, T):
    i, j, cnt = 0, len(a) - 1, 0
    while i < j:
        s = a[i] + a[j]
        if s < T:
            i += 1
        elif s > T:
            j -= 1
        elif a[i] == a[j]:
            m = j - i + 1
            cnt += m * (m - 1) // 2
            break
        else:
            x, y = a[i], a[j]
            ci = cj = 0
            while a[i] == x:
                ci += 1
                i += 1
            while a[j] == y:
                cj += 1
                j -= 1
            cnt += ci * cj
    return cnt

print(count_pairs([1, 1, 2, 2, 3, 3], 4))   # (1,3):2*2 + (2,2):1 = 5
print(count_pairs([3, 3, 3, 3], 6))         # 6
`} />

## Merging two sorted arrays

Keep one pointer in each array; always take the smaller front element. This is the merge step of merge sort and also the engine behind "intersection of two sorted lists".

<CodeRunner language="python" code={`def merge(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:        # <= keeps the merge stable
            out.append(a[i]); i += 1
        else:
            out.append(b[j]); j += 1
    out.extend(a[i:])
    out.extend(b[j:])
    return out

print(merge([1, 4, 9], [2, 4, 10, 11]))
`} />

Cost is `O(n + m)`: each step advances one pointer.

## Partitioning

**Task.** Rearrange so all negatives come before all non-negatives, in `O(n)` time and `O(1)` space (order inside groups does not matter).

Opposite-ends version: advance `i` while `a[i] < 0`, retreat `j` while `a[j] >= 0`, swap, continue. Same-direction version: `w` is the next slot for a negative; scan with `r` and swap `a[r]` into `a[w]` when it is negative. The same idea, with three zones, is the Dutch national flag partition used inside quicksort.

<CodeRunner language="python" code={`a = [3, -1, 4, -5, 9, -2, 6]
w = 0
for r in range(len(a)):
    if a[r] < 0:
        a[w], a[r] = a[r], a[w]
        w += 1
print(a, "negatives:", w)
`} />

## When two pointers apply

You can use them when you can state, for each pointer move, a reason the skipped options are dead. Typically that is **monotonicity**: sorted input, positive values, or a predicate that only changes once as one pointer advances. If a move cannot be justified (for example the array is unsorted and has negatives), the technique silently gives wrong answers; use sorting or a hash map instead.

## Pitfalls

1. **Forgetting to sort** first. Two pointers on an unsorted array is wrong, not slow.
2. **`i < j` vs `i <= j`**: pairs need distinct positions.
3. **Duplicates**: moving only one pointer on equality either misses pairs or double counts. Decide the rule before coding.
4. **Overflow**: `a[i] + a[j]` of two values near `10^9` exceeds 32-bit. Use 64-bit.
5. **Inner `while` without bounds**: the block-skipping loops above stay in range only because of the surrounding structure; when in doubt add `i < n` and `j >= 0` guards.
