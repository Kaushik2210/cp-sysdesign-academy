## Intuition

An array is a row of numbered boxes. You can jump to box `i` instantly, but finding "the box that holds 42" means opening boxes one by one. Almost every technique in this module is a way to answer a question about a **range of boxes** without re-opening all of them: summing a range, applying an update to a range, finding the best window.

Strings behave the same way: a string is an array of characters, so `s[i]`, scanning left to right, and "count the letter `a`" are array problems in disguise.

## Definitions you must be exact about

- **Index range.** An array of length `n` has valid indices `0 .. n-1` in Python, JavaScript, C++ and Java. Many problem statements use **1-based** positions, so `a[l..r]` in the statement is `a[l-1 .. r-1]` in code. Mixing the two is the most common off-by-one source.
- **Subarray / substring.** A *contiguous* piece `a[l..r]`. A *subsequence* may skip elements. Contiguity is what makes the techniques in this module work.
- **Number of subarrays.** There are `n(n+1)/2` non-empty subarrays. Summing each one from scratch is `O(n^3)`, with a running sum `O(n^2)`. The goal of this module is `O(n)`.
- **Half-open ranges.** `[l, r)` includes `l` and excludes `r`, with length `r - l`. Using half-open ranges internally removes a lot of `+1` and `-1` noise.

## Core idioms

### Scan with a running value

Most array problems are one pass with a few variables that summarise what you have seen: a running sum, the largest value so far, the previous element.

### Frequency arrays

If values are small and bounded (letters, digits, values under about `10^6`), a **count array** replaces a hash map and is both simpler and faster:

<CodeRunner language="python" code={`s = input()
cnt = [0] * 26
for ch in s:
    cnt[ord(ch) - ord('a')] += 1
# print letters that appear, with their counts
print(" ".join(chr(97 + i) + "=" + str(c) for i, c in enumerate(cnt) if c))
`} stdin={"mississippi\n"} />

### Two indices walking toward each other

Reversal, palindromes and "compare from both ends" use `i` from the left and `n - 1 - i` from the right and stop at the middle. A palindrome check does only `n / 2` comparisons:

<CodeRunner language="python" code={`def is_pal(s):
    return all(s[i] == s[len(s) - 1 - i] for i in range(len(s) // 2))

for w in ["racecar", "abca", "", "x"]:
    print(repr(w), is_pal(w))
`} />

### In-place compaction

To delete all zeros while keeping order in `O(n)` time and `O(1)` extra memory, keep a write index `w` and copy only the elements you keep:

<CodeRunner language="python" code={`a = [0, 3, 0, 0, 5, 7, 0]
w = 0
for x in a:
    if x != 0:
        a[w] = x
        w += 1
print(a[:w])
`} />

This reader/writer pair is the seed of the two-pointer technique.

## Kadane's algorithm: the best streak

**Problem.** Find the maximum sum of a non-empty contiguous subarray.

**Idea.** Let `cur` be the best sum of a subarray that **ends at the current element**. Either it starts fresh at this element, or it extends the best one ending at the previous element:

`cur = max(x, cur + x)`

and the answer is the largest `cur` ever seen. Extending is only worth it when the previous `cur` is positive: a negative running total can only hurt, so we "forget" it.

**Worked example.** `a = [3, -4, 5, -1, 2, -6]`

| x | cur (best ending here) | best so far |
|---|---|---|
| 3 | 3 | 3 |
| -4 | max(-4, -1) = -1 | 3 |
| 5 | max(5, 4) = 5 | 5 |
| -1 | max(-1, 4) = 4 | 5 |
| 2 | max(2, 6) = 6 | 6 |
| -6 | max(-6, 0) = 0 | 6 |

Answer 6, the streak `5, -1, 2`.

<CodeRunner language="python" code={`n = int(input())
a = list(map(int, input().split()))
best = cur = a[0]          # start from the first element, NOT from 0
for x in a[1:]:
    cur = max(x, cur + x)
    best = max(best, cur)
print(best)
`} stdin={"6\n3 -4 5 -1 2 -6\n"} />

<Complexity time="O(n)" space="O(1)" note="versus O(n^2) with prefix sums or O(n^3) brute force" />

<Callout type="pitfall" title="Initialising to zero">
If every number is negative the answer is the **largest (least negative) single element**, not 0. Starting `best = 0` silently allows the empty subarray. If the statement allows an empty subarray, then `0` is correct. Read the statement.
</Callout>

## Integer overflow and input handling

- A sum of `2·10^5` values of size `10^9` is `2·10^14`. That overflows 32-bit `int` in C++ and Java: use `long long` / `long`. Python integers never overflow; plain JavaScript numbers are exact only up to `2^53`, about `9·10^15`.
- Read input in bulk: `sys.stdin.read().split()` in Python, `scanf` or `cin` with `sync_with_stdio(false)` in C++, a buffered reader in Java.
- Print once, with a joined string, rather than thousands of separate prints.

## Pitfalls

1. **Off-by-one** between 1-based statement positions and 0-based arrays.
2. **Overwriting the input** while later queries still need the original values.
3. **Mutable aliasing** in Python: `grid = [[0] * m] * n` makes all rows the same list. Use `[[0] * m for _ in range(n)]`.
4. **Slicing cost**: `a[i:j]` copies, so it costs `O(j - i)`. Slicing inside a loop quietly makes a linear algorithm quadratic.
5. **Quadratic string building**: repeated `s += c` can be quadratic in some languages. Collect pieces and `join` (or use `StringBuilder`).
