## Intuition

The [segment tree](/cp/range-queries/segment-trees/) answers "sum of a range" and handles point updates. A **Fenwick tree** does the same job for prefix sums with about ten lines of code and half the memory, using one trick: the **lowest set bit** of an index decides how much of the array that index is responsible for.

Position `12` is `1100` in binary. Its lowest set bit is `4`, so it stores the sum of the `4` elements ending at `12`, which are positions `9..12`. Position `8` (`1000`) covers `8` elements, `1..8`. Odd positions cover just themselves.

## Definition

Use **1-based** indexes. Let `lowbit(i) = i & -i`. The array `bit[i]` stores the sum of `a[i - lowbit(i) + 1 .. i]`.

- **Prefix sum** `sum(x)`: add `bit[x]`, then remove the lowest set bit (`x -= lowbit(x)`), until `x` is `0`. Each step clears a bit, so there are at most `log n` steps.
- **Point add** `add(x, d)`: add `d` to `bit[x]`, then move to the next node that covers `x` (`x += lowbit(x)`), until you pass `n`.
- **Range sum** `[l, r]`: `sum(r) - sum(l - 1)`.

Everything is `O(log n)` and memory is `n + 1` numbers.

| index | binary | covers |
| --- | --- | --- |
| 1 | `0001` | 1 |
| 2 | `0010` | 1..2 |
| 3 | `0011` | 3 |
| 4 | `0100` | 1..4 |
| 6 | `0110` | 5..6 |
| 8 | `1000` | 1..8 |

For example `sum(7)` adds `bit[7]` (position 7), `bit[6]` (positions 5..6) and `bit[4]` (positions 1..4): three nodes that exactly tile `1..7`.

## Code

<Tab label="Python">

```python
bit = [0] * (n + 1)

def add(x, d):                      # a[x] += d, 1-based
    while x <= n:
        bit[x] += d
        x += x & -x

def prefix(x):                      # sum of a[1..x]
    s = 0
    while x > 0:
        s += bit[x]
        x -= x & -x
    return s

def range_sum(l, r):                # sum of a[l..r]
    return prefix(r) - prefix(l - 1)
```

## When to choose a Fenwick tree

| need | choice |
| --- | --- |
| prefix or range sums with point updates | Fenwick: shortest code, fastest constants |
| range min or max | segment tree (min and max have no inverse) |
| range update with range query | two Fenwick trees, or a segment tree with lazy propagation |
| counting elements below a value, inversions | Fenwick over compressed values |
| anything with a custom merge | segment tree |

<Callout type="tip" title="Order statistics by rank">
To count elements `<= x` in a growing multiset, keep a Fenwick tree over the value range with `1` per inserted element. With values up to `10^9`, first compress them to ranks `1..n` (sort and deduplicate, see [coordinate mapping](/cp/hashing/coordinate-mapping-grouping/)).
</Callout>

## Pitfalls

1. **0-based indexes.** `x & -x` is `0` for `x = 0`, so `add(0, d)` loops forever. Shift every index up by one.
2. **Range sum off by one.** `prefix(r) - prefix(l - 1)`, not `prefix(r) - prefix(l)`.
3. **Using it for min or max.** The prefix trick needs an inverse operation; you cannot "subtract" a minimum.
4. **Rebuilding on updates.** An update changes only `log n` nodes; do not recompute.
5. **Overflow.** Sums of many large values need 64-bit integers.
6. **Setting a value instead of adding.** The tree supports `add`. To assign, add the *difference* `new - old` (keep a plain array alongside).
