## Intuition

The array never changes, and you are asked "what is the smallest value between positions `l` and `r`?" many times. A [segment tree](/cp/range-queries/segment-trees/) answers in `O(log n)`, but because the array is **static** we can do better: precompute enough to answer in `O(1)`.

The idea: for a minimum, **overlap is harmless**. The minimum of `[2, 7]` equals the minimum of `[2, 5]` and `[4, 7]` taken together, even though positions 4 and 5 are counted twice. So any range can be covered by **just two** blocks whose length is a power of two, as long as the table already holds the answer for every block of those lengths.

## Definition

Let `sp[k][i]` be the minimum of `a[i .. i + 2^k - 1]` (the block of length `2^k` starting at `i`).

```text
sp[0][i] = a[i]
sp[k][i] = min( sp[k-1][i], sp[k-1][i + 2^(k-1)] )       two halves
```

There are about `log2(n)` levels with up to `n` entries each: time and memory `O(n log n)`.

**Query** `[l, r]` (0-based, inclusive): let `k` be the largest integer with `2^k <= r - l + 1`, that is `k = (r - l + 1).bit_length() - 1`. Then

```text
answer = min( sp[k][l], sp[k][r - 2^k + 1] )
```

The first block starts at the left end, the second ends at the right end, both have length `2^k`, together they cover `[l, r]`, and they may overlap. Each query is `O(1)`.

## Idempotent operations only

An operation `f` is **idempotent** when `f(x, x) = x`. Minimum, maximum, gcd, bitwise AND and OR are. **Sum is not**: counting the overlap twice gives the wrong total.

| operation | sparse table with overlap trick? |
| --- | --- |
| min, max | yes |
| gcd, AND, OR | yes |
| sum, product, xor | no, use a prefix array or split the range into disjoint power-of-two blocks (`O(log n)` per query) |
| anything with updates | no, use a segment tree |

## Choosing between the range structures

| structure | build | query | update | supports |
| --- | --- | --- | --- | --- |
| prefix sums | `O(n)` | `O(1)` | none | sums (any invertible operation) |
| sparse table | `O(n log n)` | `O(1)` | none | min, max, gcd and other idempotent operations |
| Fenwick tree | `O(n)` | `O(log n)` | `O(log n)` | sums and other invertible operations |
| segment tree | `O(n)` | `O(log n)` | `O(log n)` | any associative operation |

A sparse table is also the engine behind `O(1)` **LCA**: take the Euler tour of the tree and answer "minimum depth between two visits" as a range-minimum query.

## Pitfalls

1. **Using it for sums.** The overlap double counts; use prefix sums instead.
2. **Updates after the build.** A change invalidates `O(n log n)` entries, so use a segment tree when the array changes.
3. **Wrong `k`.** `k` is the largest power with `2^k <= length`, i.e. `bit_length - 1`, not `bit_length`.
4. **Wrong second block start.** It is `r - 2^k + 1`, so the block *ends* at `r`.
5. **Level sizes.** Level `k` has `n - 2^k + 1` entries, not `n`; indexing beyond that is out of range.
6. **Memory.** `n log n` numbers: `2·10^5 * 18` is 3.6 million, fine in compiled languages but heavy for Python lists, so consider `array` or NumPy.
