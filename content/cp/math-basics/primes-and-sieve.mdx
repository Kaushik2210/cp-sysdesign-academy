## Intuition

A prime is a number greater than 1 whose only divisors are 1 and itself. Primes are the atoms of the integers: every number greater than 1 is a product of primes in exactly one way (up to order). Contest problems lean on this to count divisors, simplify fractions, find gcds of huge products and more.

There are two basic questions: *is this one number prime?* and *give me all primes up to N*. The first is answered by trial division; the second by a beautiful trick that crosses off multiples.

## Primality by trial division

If `n = a * b` with `1 < a <= b`, then `a * a <= a * b = n`, so the smaller factor is at most `sqrt(n)`. It is therefore enough to try divisors up to `sqrt(n)`:

```python
def is_prime(n):
    if n < 2:
        return False
    i = 2
    while i * i <= n:        # i <= sqrt(n), without floating point
        if n % i == 0:
            return False
        i += 1
    return True
```

Cost: `O(sqrt n)`. For `n = 10^12` that is `10^6` divisions: fine for one number, too slow for `10^5` queries. Use `i * i <= n` rather than `i <= sqrt(n)` to dodge floating-point rounding, but note that `i * i` overflows a 32-bit `int` once `n` is near `2^31`; use `long long`.

The same loop factorises a number: whenever `i` divides `n`, divide it out repeatedly and record the exponent; at the end, whatever `> 1` remains is a prime factor.

## The sieve of Eratosthenes

To list every prime up to `N`, do not test numbers one by one. Instead: write `2..N`; take the first unmarked number `p` (it must be prime), cross off its multiples, and repeat.

Two observations make it fast:

1. **Start at `p * p`.** A smaller multiple `p * k` with `k < p` has a smaller prime factor and was already crossed off.
2. **Stop at `sqrt(N)`.** Any composite `<= N` has a prime factor `<= sqrt(N)`.

<Tabs>

```cpp
vector<bool> is_comp(N + 1, false);
is_comp[0] = is_comp[1] = true;
for (long long i = 2; i * i <= N; i++)

        for (long long j = i * i; j <= N; j += i)

```

### Complexity

Prime `p` crosses off about `N / p` numbers, so the total is `N * (1/2 + 1/3 + 1/5 + ...)` over primes up to `sqrt N`, which is `N * ln ln N` up to constants (Mertens). In practice `ln ln 10^7` is about 2.8, so the sieve is essentially linear. Memory is `O(N)`, one byte (or bit) per number.

<Complexity time="O(n log log n)" space="O(n)" note="n = sieve limit; N = 10^7 runs in well under a second in C++" />

### Smallest prime factor sieve

Store, for each `x`, its smallest prime factor `spf[x]`. Then factorising any `x <= N` takes `O(log x)` steps by repeatedly dividing by `spf[x]`:

<CodeRunner snippets={{ python: `N = 100
spf = list(range(N + 1))
for i in range(2, int(N ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, N + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor(x):
    out = []
    while x > 1:
        out.append(spf[x])
        x //= spf[x]
    return out

print(factor(84), factor(97), factor(96))
`, javascript: `const N = 100;
const spf = Array.from({ length: N + 1 }, (_, i) => i);
for (let i = 2; i * i <= N; i++)
  if (spf[i] === i)
    for (let j = i * i; j <= N; j += i) if (spf[j] === j) spf[j] = i;
function factor(x) {
  const out = [];
  while (x > 1) { out.push(spf[x]); x = x / spf[x]; }
  return out;
}
console.log(factor(84), factor(97), factor(96));

## Which tool when?

| Need | Tool | Cost |
| --- | --- | --- |
| Is one `n` prime, `n <= 10^12` | trial division | `O(sqrt n)` |
| All primes `<= N`, `N <= ~10^7` | sieve of Eratosthenes | `O(N log log N)` |
| Factorise many numbers `<= N` | smallest-prime-factor sieve | `O(N)` preprocess, `O(log x)` each |
| Primes in `[L, R]` with `R` huge but `R - L` small | segmented sieve (sieve with primes up to `sqrt R`) | `O((R-L) log log R + sqrt R)` |
| Is a 64-bit number prime, many queries | Miller-Rabin (later in the course) | `O(log n)` multiplications |

Counts worth knowing: there are 78 498 primes below `10^6`, 664 579 below `10^7`, and roughly `N / ln N` below `N` in general (prime number theorem).

## Pitfalls

1. **`1` is not prime**, and `0` and negatives are not either. Seed the table accordingly.
2. **Inner loop start.** Starting at `2 * p` is correct but wasteful; starting at `p * p` with an `int` index overflows when `p` is near `46341` and `int` is 32 bits. Use `long long` for `i * i`.
3. **Sieve limit.** The sieve must include the largest query, not just `sqrt`. Off-by-one: array size `N + 1`.
4. **Memory.** `vector<bool>`/bitset for `N = 10^8`; a plain `int` array at that size is 400 MB.
5. **Trial division loop bound.** Re-evaluate `i * i <= n` after dividing `n` when factorising, so the loop stops as early as possible.
