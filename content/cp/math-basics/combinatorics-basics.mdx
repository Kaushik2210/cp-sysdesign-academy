## Intuition

Counting problems ask "in how many ways?". Almost all of them reduce to two moves: **choose** (an unordered group of items) and **arrange** (an ordered line of items). The binomial coefficient `C(n, r)`, read "n choose r", counts how many ways to pick `r` items out of `n` when order does not matter.

The answers explode: `C(100, 50)` has 30 digits. So these problems are nearly always posed modulo a prime, and the real lesson is *how to compute `C(n, r)` mod `p` fast*.

## Counting rules

- **Sum rule.** If task A can be done in `x` ways and task B in `y` ways, and they are mutually exclusive, there are `x + y` ways to do "A or B".
- **Product rule.** If a choice has `x` options and, for each, another has `y` options, there are `x * y` combined ways.
- **Permutations.** Lines of `n` distinct items: `n! = n * (n-1) * ... * 1`. Lines of `r` items picked from `n`: `n! / (n - r)!`.
- **Combinations.** Dividing the ordered count by the `r!` orderings of the chosen group:

```text
C(n, r) = n! / (r! * (n - r)!)
```

Useful identities:

```text
C(n, r) = C(n, n - r)                    symmetry
C(n, r) = C(n-1, r-1) + C(n-1, r)        Pascal: item n is in the group or not
sum over r of C(n, r) = 2^n              every subset
```

**Stars and bars.** The number of non-negative integer solutions of `x_1 + ... + x_k = n` is `C(n + k - 1, k - 1)`. The number of monotone lattice paths from `(0, 0)` to `(a, b)` is `C(a + b, a)`.

## Method 1: Pascal's triangle, O(n^2)

Build rows with the identity above. No division needed, so it works for **any** modulus, but time and memory are `O(n * r)`: fine for `n <= ~5000`.

## Method 2: factorials and inverses, O(n + log p)

For huge `n` (up to `10^6` or `10^7`), precompute `fact[i] = i! mod p` once. Then

```text
C(n, r) = fact[n] * inv(fact[r]) * inv(fact[n - r])  (mod p)
```

where `inv(x)` is the modular inverse. Because `p` is prime, `inv(x) = x^(p-2) mod p` by Fermat (see [fast exponentiation](/cp/math-basics/fast-exponentiation/)). Computing three inverses per query costs about 90 multiplications each; better is to compute `inv_fact[N]` once and derive the rest downwards:

```text
inv_fact[i - 1] = inv_fact[i] * i
```

because `1/(i-1)! = i / i!`.

<Tabs>
<Tab label="C++">

```cpp
const long long MOD = 1000000007;
vector<long long> fact(N + 1), inv_fact(N + 1);

long long power(long long a, long long b) {
    long long r = 1; a %= MOD;
    while (b) { if (b & 1) r = r * a % MOD; a = a * a % MOD; b >>= 1; }
    return r;
}

void init() {
    fact[0] = 1;
    for (int i = 1; i <= N; i++) fact[i] = fact[i - 1] * i % MOD;
    inv_fact[N] = power(fact[N], MOD - 2);
    for (int i = N; i >= 1; i--) inv_fact[i - 1] = inv_fact[i] * i % MOD;
}

long long C(int n, int r) {
    if (r < 0 || r > n) return 0;
    return fact[n] * inv_fact[r] % MOD * inv_fact[n - r] % MOD;
}
```

## Which method?

<TradeOffs caption="Computing C(n, r) modulo a number" rows={[
  { option: "Pascal's triangle", pros: "No division, works for any modulus, trivial to code", cons: "O(n^2) time and memory", chooseWhen: "n up to a few thousand or the modulus is composite" },
  { option: "Factorials + Fermat inverses", pros: "O(n) precompute, O(1) per query", cons: "Needs a prime modulus larger than n", chooseWhen: "n up to 10^6 or 10^7 and prime modulus such as 10^9+7" },
  { option: "Multiplicative formula", pros: "O(r) with no tables: prod (n-i+1)/i", cons: "Needs inverses per step or exact big integers", chooseWhen: "A single small-r query, or exact answers in Python" }
]} />

## Pitfalls

1. **`r > n` or `r < 0`** must give `0`, not an out-of-range index.
2. **Modulus not prime, or `n >= p`.** Then `n!` is divisible by `p`, the inverse does not exist and the factorial method silently returns garbage. Use Pascal's triangle, Lucas' theorem (prime `p`, small), or prime-power factorisation.
3. **Integer overflow.** `fact[n] * inv_fact[r]` must be computed in 64 bits and reduced before the next multiplication.
4. **Ordered vs unordered.** Re-read the statement: do two selections that differ only by order count once or many times? Dividing by the wrong factorial is the most common bug.
5. **Computing `C` without modulus in 64-bit.** `C(67, 33)` already exceeds a signed 64-bit integer.
