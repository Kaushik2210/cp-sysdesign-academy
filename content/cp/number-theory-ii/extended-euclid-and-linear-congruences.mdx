## Intuition

Euclid's algorithm finds `gcd(a, b)` by repeatedly replacing `(a, b)` with `(b, a mod b)`. It does more than find the gcd: every remainder it produces is a **combination** of the two original numbers. Track that combination while you run it and you get **Bézout's identity**:

```text
a * x + b * y = gcd(a, b)        for some integers x and y (one of them is usually negative)
```

That one fact solves several problems that look different:

- **Modular inverse for any modulus**, not only primes. If `gcd(a, m) = 1` then `a * x + m * y = 1`, so `a * x ≡ 1 (mod m)` and `x` is the inverse of `a`. Fermat's little theorem (`a^(p-2)`) needs a prime modulus; this does not.
- **Linear congruences** `a * x ≡ b (mod m)`, including the case where `a` and `m` share factors.
- **Linear Diophantine equations** `a * x + b * y = c` in integers (how to pay `c` with coins worth `a` and `b`, or fill a jug).
- Combining several congruences (next lesson).

## Definition

### The extended algorithm

Run Euclid and keep, for the current pair `(a, b)`, the coefficients that express each as a combination of the original `(a0, b0)`:

```text
start:  a = a0 = 1*a0 + 0*b0      b = b0 = 0*a0 + 1*b0
step:   q = a // b;  (a, b) = (b, a - q*b)   and update the coefficients the same way
end:    b = 0, a = gcd, with its coefficients (x, y)
```

Iteratively: keep `(x0, y0)` for `a` and `(x1, y1)` for `b`; after computing `q`, set `a, b = b, a - q*b`, `x0, x1 = x1, x0 - q*x1` and `y0, y1 = y1, y0 - q*y1`.

The number of steps is the same as for Euclid's algorithm: **`O(log min(a, b))`**. The worst case is two consecutive Fibonacci numbers; the first such pair above `10^9` (701,408,733 and 1,134,903,170) takes 43 steps, while random pairs near `10^9` average about 17.6 steps (see the experiment below).

```python
def ext_gcd(a, b):
    """Return (g, x, y) with a*x + b*y = g = gcd(a, b)."""
    x0, y0, x1, y1 = 1, 0, 0, 1
    while b:
        q = a // b
        a, b = b, a - q * b
        x0, x1 = x1, x0 - q * x1
        y0, y1 = y1, y0 - q * y1
    return a, x0, y0
```

```cpp
long long extGcd(long long a, long long b, long long &x, long long &y) {

    y = x1 - (a / b) * y1;
```

```java
static long x;                                   // Bezout coefficient of a
static long extGcd(long a, long b) {
    long x0 = 1, x1 = 0;
    while (b != 0) {
        long q = a / b;
        long t = a - q * b; a = b; b = t;
        t = x0 - q * x1; x0 = x1; x1 = t;
    }
    x = x0;
    return a;
}
```

### Modular inverse

If `gcd(a, m) = 1`, call `ext_gcd(a, m)` and take `x mod m` (the result of `%` can be negative in C++ and Java; fix it with `((x % m) + m) % m`). If `gcd(a, m) > 1`, **no inverse exists**.

### Linear congruences `a * x ≡ b (mod m)`

Let `g = gcd(a, m)`.

1. If `g` does **not** divide `b`, there is **no solution**: the left side is always a multiple of `g` (since `g` divides both `a` and `m`), so `a * x - b` cannot be a multiple of `m`.
2. Otherwise divide everything by `g`: `(a/g) * x ≡ (b/g) (mod m/g)`. Now `a/g` and `m/g` are **coprime**, so `a/g` has an inverse modulo `m/g`.
3. The solutions are `x ≡ (b/g) * inverse(a/g mod m/g) (mod m/g)`. Modulo the original `m` there are exactly **`g` distinct solutions**: `x0, x0 + m/g, x0 + 2m/g, ...`. The smallest non-negative one is `x0` itself, in the range `0 .. m/g - 1`.

Using the coefficient `x` from `ext_gcd(a mod m, m)` (which satisfies `a*x + m*y = g`) gives `x0 = (x * (b/g)) mod (m/g)` directly.

### Linear Diophantine equations `a * x + b * y = c`

Solvable in integers exactly when `gcd(a, b)` divides `c`. One solution is `(x * c/g, y * c/g)` from `ext_gcd`; all solutions are `x + k * (b/g)`, `y - k * (a/g)` for integer `k`. Adding the constraint `x ≥ 0, y ≥ 0` turns finding a solution into choosing `k` in a range.

## Pitfalls

1. **Using Fermat's `a^(m-2)` with a composite modulus.** It only works for prime `m`. For a general modulus use extended Euclid, and check `gcd(a, m) = 1` first.
2. **Negative coefficients.** `x` and `y` can be negative; reduce with `((x % m) + m) % m` in languages whose `%` keeps the sign of the dividend.
3. **`a` or `b` equal to zero.** `ext_gcd(0, m)` returns `g = m`; for the congruence this means `m` must divide `b` and the smallest solution is `0`. Reduce `a mod m` before calling.
4. **Forgetting that there may be many solutions.** When `g > 1` there are `g` solutions modulo `m`; decide which one the problem wants (usually the smallest non-negative).
5. **Dividing by `g` only on one side.** `a`, `b` and `m` all divide by `g` (only possible when `g | b`).
6. **Overflow.** Intermediate products like `x * (b/g)` reach `10^18` for moduli near `10^9`: use 64-bit integers, and BigInt in JavaScript.
7. **Recursive implementation depth.** The recursive form is fine here (depth is about 45 for numbers near `10^9`), but the iterative form avoids any doubt.
