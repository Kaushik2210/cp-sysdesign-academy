## Intuition

`C(n, k)`, "n choose k", counts the ways to pick `k` items from `n`. These numbers get huge very quickly: `C(200000, 100000)` has about 60,000 digits. Contest problems therefore ask for the answer **modulo a prime**, usually `10^9 + 7` or `998244353`, and often ask **many** such queries.

The formula `C(n, k) = n! / (k! * (n - k)!)` is the key, but a *division* appears, and you cannot divide ordinary remainders. Division modulo a prime means multiplying by a **modular inverse**. So:

1. precompute all factorials modulo the prime **once**,
2. precompute all inverse factorials **once**,
3. answer each query with **two multiplications**.

After an `O(n)` preparation every query costs `O(1)`.

## Definition

Let `p` be a prime and `n < p`.

```text
fact[i]      = i! mod p                 fact[i] = fact[i-1] * i
inv_fact[i]  = (i!)^(-1) mod p
C(n, k)      = fact[n] * inv_fact[k] * inv_fact[n - k]  mod p       (0 when k > n)
```

### Computing inverse factorials cheaply

Fermat's little theorem says `a^(p-1) ≡ 1 (mod p)`, so `a^(p-2)` is the inverse of `a` (for `a` not divisible by `p`). Computing that for every factorial would cost `O(log p)` each. Instead compute it **once**, for the largest factorial, then go downwards, using

```text
1/(i-1)! = i * (1/i!)       so       inv_fact[i-1] = inv_fact[i] * i
```

Total preparation: `O(N + log p)` for `N` the largest `n` you will ask about. (Alternatively, extended Euclid from the previous lesson computes inverses when the modulus is not prime, but then `n!` may share factors with the modulus.)

### Other ways to compute them

| method | cost | when |
| --- | --- | --- |
| **Pascal's rule** `C(n, k) = C(n-1, k-1) + C(n-1, k)` | `O(n^2)` memory and time for all values up to `n` | small `n` (a few thousand), works for **any modulus** (only additions) |
| **Factorials and inverse factorials** | `O(N)` once, `O(1)` per query | prime modulus larger than `n`: the standard |
| **Multiplicative formula** `C(n, k) = prod (n - i + 1) / i` | `O(k)` per query | a few queries, or when only `k` is small |
| **Lucas' theorem** | `O(p + log_p n)` | **small prime** modulus where `n` can exceed `p` |
| **Prime-power moduli and CRT** | combine | composite modulus (factor it, solve each prime power, merge with CRT) |

### Lucas' theorem

When the modulus `p` is a **small prime** and `n` can be larger than `p`, `n!` is divisible by `p` and the factorial method fails (you cannot divide by zero). **Lucas' theorem** writes `n` and `k` in base `p` and multiplies the binomials of the digits:

```text
C(n, k) ≡ product over digit positions of C(n_i, k_i)   (mod p),     and the result is 0 if any k_i > n_i
```

Each digit is below `p`, so small binomials (a precomputed table or the factorial method up to `p - 1`) suffice.

## Counting formulas worth knowing

- **Stars and bars:** the number of ways to distribute `n` identical items among `k` people is `C(n + k - 1, k - 1)`; if each person must get at least one, `C(n - 1, k - 1)`.
- **Catalan numbers:** `Cat(n) = C(2n, n) / (n + 1)` counts balanced bracket sequences of length `2n`, binary trees with `n` nodes, monotone lattice paths that stay on one side of the diagonal, and more. Compute it as `fact[2n] * inv_fact[n] * inv_fact[n + 1]`.
- **Multinomial coefficients:** arrangements of a multiset, `n! / (c1! * c2! * ...)`, also two multiplications per factor with the tables.
- **Paths in a grid:** the number of monotone paths from the top-left corner to a cell `r` rows down and `c` columns right is `C(r + c, r)`. Obstacles are handled by subtracting paths through them (inclusion-exclusion over sorted obstacles).
- **Hockey stick and Vandermonde identities** turn sums of binomials into a single one.

## Experiment

The program compares the factorial method with Python's exact `math.comb`, counts the work of Pascal's rule, checks Lucas' theorem for the prime 13, and prints Catalan numbers and two stars-and-bars counts.

<CodeRunner language="python" timeoutMs={60000} code={`import math
import random


MOD = 10**9 + 7


def build_tables(top):
    fact = [1] * (top + 1)
    for i in range(1, top + 1):
        fact[i] = fact[i - 1] * i % MOD
    inv = [1] * (top + 1)
    inv[top] = pow(fact[top], MOD - 2, MOD)
    for i in range(top, 0, -1):
        inv[i - 1] = inv[i] * i % MOD
    return fact, inv


def lucas(n, k, p):
    """C(n, k) mod a SMALL prime p, as a product over the base-p digits of n and k."""
    result = 1
    while n or k:
        a, b = n % p, k % p
        if b > a:
            return 0
        result = result * math.comb(a, b) % p
        n //= p
        k //= p
    return result


def catalan(n, fact, inv):
    return fact[2 * n] * inv[n] % MOD * inv[n + 1] % MOD

What it shows:

- On 300 random queries with `n` up to **200,000** (and `k` up to 300 so that the exact comparison is quick), and on three very large values (`C(200000, 100000)`, `C(199999, 99999)`, `C(150000, 60000)`, numbers of tens of thousands of digits), the factorial method agrees with the exact `math.comb` modulo `10^9 + 7`.
- **Pascal's rule** needs **500,500 additions** just for the rows up to 1,000 and yields only those rows, while the factorial tables cost **400,000 multiplications** once for `n` up to 200,000 and then two per query. At row 1,000 the two methods give the same value.
- **Lucas' theorem** matches `math.comb` modulo 13 for every `n` below 400 and every `k` that is a multiple of 7. For example `C(100, 40) mod 13 = 3`, a case where `n!` is divisible by 13 and the factorial method cannot be used.
- The **Catalan numbers** come out as **1, 1, 2, 5, 14, 42, 132, 429, 1430, 4862, 16796, 58786**.
- **Stars and bars:** 20 identical sweets among 5 children: `C(24, 4) = 10,626` ways; with every child receiving at least one sweet, `C(19, 4) = 3,876`.

The agreement checks are the correctness evidence; the operation counts are exact for the stated sizes.

## Pitfalls

1. **Using the factorial method when `n >= p`.** Then `n!` is `0` modulo `p` and inverse factorials do not exist. Use Lucas' theorem or a different approach.
2. **A non-prime modulus.** Fermat's inverse needs a prime; for a composite modulus use extended Euclid where it is invertible, or factor the modulus and combine with CRT.
3. **Forgetting `k > n` and negative `k`.** Return `0`.
4. **Overflow.** Products of two residues below `10^9 + 7` reach `10^18`: 64-bit integers are enough, JavaScript needs BigInt, and `int` overflows.
5. **Reducing mod `p` after each multiplication**, not after chaining three. `a * b * c % MOD` overflows in 64-bit; write `a * b % MOD * c % MOD`.
6. **Building tables up to the wrong size.** The largest argument of any factorial you read must be within the tables (`2n` for Catalan, `n + k - 1` for stars and bars).
7. **Recomputing inverses per query** with fast exponentiation (`O(log p)` each) when one inverse and a downward loop are enough.
8. **Assuming `C(n, k)` modulo a prime is zero only when `k > n`.** With a small prime and large `n` it can be zero for other reasons (Lucas: a digit of `k` exceeds the digit of `n`).
