## Intuition

A **Hamiltonian path** visits every **vertex** once and is NP-hard to find. An **Euler path** uses every **edge** exactly once, and it is easy: there is a clean degree test and a linear-time algorithm. The story goes back to the bridges of Konigsberg: can you cross all seven bridges exactly once? Euler proved in 1736 that you cannot, and in doing so started graph theory.

Every time a walk passes **through** a vertex it uses one edge to enter and one to leave. So apart from the start and the end, every vertex needs an even number of incident edges (undirected) or equally many in and out edges (directed). That is the whole theory.

## Definition

An **Euler path** uses every edge exactly once; an **Euler circuit** is an Euler path that returns to its start. Assume all edges lie in one connected piece (isolated vertices do not matter).

| graph | Euler circuit exists when | Euler path (not a circuit) exists when |
| --- | --- | --- |
| undirected | every degree is even | exactly two vertices have odd degree (the path starts at one and ends at the other) |
| directed | in-degree equals out-degree everywhere | one vertex has out minus in equal to 1 (the start), one has in minus out equal to 1 (the end), the rest balanced |

The degree condition is necessary; together with connectivity of the edges it is also sufficient. In code you do not need a separate connectivity check: run the construction and verify that the path found has all `m + 1` vertex slots.

### Hierholzer's algorithm

Consider two disconnected triangles on vertices `A, B, C` and `D, E, F`. Try the degree test first, then check whether one traversal consumed every edge.

Walk along unused edges from the start until you are stuck. In a graph that passes the degree test you can only get stuck at the start (circuit) or at the designated end. The walk may have missed edges, which hang off vertices on the walk as unused **sub-circuits**. Hierholzer splices them in. The neat implementation is a depth-first search that records a vertex **when it is finished**:

```text
stack = [start]
while stack not empty:
    v = top of stack
    if v has an unused edge (v, w): mark it used, push w
    else: pop v and append it to path
reverse path
```

Each edge is pushed once and each vertex entry popped once, so the running time is `O(n + m)`. The reversal matters: vertices come out in the **reverse** of the visiting order.

### Lexicographically smallest path

If the problem wants the smallest sequence of vertices, take the **smallest** neighbour first. With a stack you pop from the end of a list, so store each adjacency list sorted in **descending** order and `pop()` the smallest. The finished-order construction then yields the lexicographically smallest Euler path: when a detour is forced, the branch with the larger choice is finished first and ends up last.

def euler_path(n, edges, s):
    """Smallest Euler path from s in a directed multigraph, or None. Returns the path and the number of stack operations."""
    adj = [[] for _ in range(n + 1)]
    diff = [0] * (n + 1)
    for u, v in edges:
        adj[u].append(v)
        diff[u] += 1
        diff[v] -= 1
    plus = [v for v in range(1, n + 1) if diff[v] == 1]
    minus = [v for v in range(1, n + 1) if diff[v] == -1]
    if any(d not in (-1, 0, 1) for d in diff[1:]) or ((plus or minus) and not (len(plus) == 1 and len(minus) == 1 and plus[0] == s)):
        return None, 0
    for lst in adj:
        lst.sort(reverse=True)
    stack, path, ops = [s], [], 0
    while stack:
        v = stack[-1]
        if adj[v]:
            stack.append(adj[v].pop())
        else:
            path.append(stack.pop())
        ops += 1
    path.reverse()
    return (path if len(path) == len(edges) + 1 else None), ops


def brute_smallest(n, edges, s):
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)

What it shows:

- On **600 random small directed multigraphs** (466 had an Euler path, 134 had none) the sorted Hierholzer returns **exactly** the lexicographically smallest path that exhaustive search finds, and reports none exactly when none exists.
- On a closed walk of **20,000 roads** over 300 towns it uses **40,001 stack operations**, which is `2m + 1`: every edge is pushed once and every vertex entry popped once. The path is valid: every road is used exactly once and consecutive towns are joined.
- Konigsberg: the four land masses have degrees 5, 3, 3, 3. **All four are odd**, more than two, so no walk crosses every bridge exactly once.

## Typical uses

- **Reconstruct an itinerary** from tickets (smallest lexicographic order).
- **De Bruijn sequences**: an Euler circuit in the graph whose vertices are strings of length `k - 1` gives a shortest string containing every length `k` string.
- **Drawing a figure without lifting the pen**, and **DNA fragment assembly** (an Euler path through a k-mer graph).
- **Chinese postman**: if odd vertices exist, pair them up with shortest paths and duplicate those edges (a min-cost matching, see the matching module).

## Pitfalls

1. **Forgetting the degree check.** Without it Hierholzer still returns something, but the path is not an Euler path. Test degrees first or confirm the path has `m + 1` vertices afterwards (this also catches disconnected edges).
2. **Not reversing** the finished-order path.
3. **Picking the wrong start.** For a directed path the start is the vertex with out minus in equal to 1. For an undirected path start at an odd-degree vertex. For a circuit any vertex with an edge works.
4. **Undirected edges must be removed from both ends.** Mark edges by id or delete the reverse copy; otherwise you traverse an edge twice.
5. **Recursion depth.** The recursive version recurses `m` deep. Use the explicit stack when `m` is near `10^5` or more.
6. **Lexicographic order with a stack.** Sorting ascending and popping from the end gives the **largest** neighbour first. Sort descending, or advance a pointer from the front.
7. **Multi-edges and self loops** are fine for Euler paths; a self loop adds 1 to in and out, and 2 to an undirected degree. Do not deduplicate them.
8. **Confusing it with a Hamiltonian path.** Visiting every vertex once is a different, NP-hard problem.
