## Intuition

Dijkstra and Bellman-Ford answer "shortest paths from one source". Sometimes you need **every pair**: a table of distances between all `n` stations, a transitive closure, the graph's diameter. When `n` is a few hundred, three nested loops do it in a dozen lines.

The trick is a good order of thinking. Let `d_k[i][j]` be the shortest distance from `i` to `j` that only uses **intermediate** vertices from `{0, ..., k-1}`. Going from `k` to `k + 1` allows one new intermediate vertex, and the new shortest path either avoids it (old value) or goes through it once: `d[i][k] + d[k][j]`.

## Definition

**Floyd-Warshall** (`O(n^3)` time, `O(n^2)` memory):

```text
d = weight matrix, d[i][i] = 0, missing edges = infinity
for k in 0..n-1:
    for i in 0..n-1:
        for j in 0..n-1:
            d[i][j] = min(d[i][j], d[i][k] + d[k][j])
```

The loop **order** matters: `k` must be the outermost loop. It can be done **in place** (one table), because row `k` and column `k` do not change during round `k` when there is no negative cycle.

Variants and facts:

- **Path reconstruction**: keep `next[i][j]`, the first step on the best path. On improvement set `next[i][j] = next[i][k]`. Follow `next` from `i` until `j`.
- **Transitive closure**: replace `min` and `+` by `or` and `and`. Same three loops, a boolean table.
- **Negative cycles**: a negative diagonal `d[i][i]` certifies a negative closed walk through `i`. For any source that can reach `i` and any target reachable from `i`, the walk cost is unbounded below.
- Negative edges are fine as long as there is no negative cycle.
- It is worth it when the graph is dense or `n` is small (`n` up to about 400). For sparse graphs with non-negative weights, `n` runs of Dijkstra cost `O(n m log n)`, which is better when `m` is much smaller than `n^2`.

### Shortest walks with exactly k edges

Now a different question: the cheapest **walk** (repeats allowed) using **exactly** `k` edges, with `k` up to `10^9`. Define the **(min, +) product** of two matrices

```text
(A * B)[i][j] = min over t of ( A[i][t] + B[t][j] )
```

Then `W^k` (the `k`-th power of the weight matrix under this product) holds the cheapest walks with exactly `k` edges. This product is **associative** and has an identity (`0` on the diagonal, infinity elsewhere), so **fast exponentiation** works: `O(n^3 log k)` instead of `O(n^3 k)` for multiplying step by step. Over ordinary `+` and `*` the same idea counts the walks of length `k`.

Two details:

1. Use a safe **infinity** (for example `4 * 10^18` with a guard, or skip infinite entries) so that `inf + inf` does not overflow.
2. This is for **walks**, not paths: a cheap edge may be reused as often as you like.

```python
INF = float("inf")


def minplus(a, b, n):
    c = [[INF] * n for _ in range(n)]
    for i in range(n):
        for t in range(n):
            if a[i][t] == INF:
                continue
            for j in range(n):
                v = a[i][t] + b[t][j]
                if v < c[i][j]:
                    c[i][j] = v
    return c


def walks_exact(n, w, k):
    result = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    base = [row[:] for row in w]
    while k:
        if k & 1:
            result = minplus(result, base, n)
        base = minplus(base, base, n)
        k >>= 1
    return result
```

```cpp
using Mat = vector<vector<long long>>;
const long long INF = (long long)4e18;
Mat mul(const Mat& a, const Mat& b, int n) {
    Mat c(n, vector<long long>(n, INF));
    for (int i = 0; i < n; i++)
        for (int t = 0; t < n; t++) {
            if (a[i][t] == INF) continue;
            for (int j = 0; j < n; j++)
                if (b[t][j] != INF) c[i][j] = min(c[i][j], a[i][t] + b[t][j]);
        }
    return c;
}
Mat power(Mat base, long long k, int n) {
    Mat res(n, vector<long long>(n, INF));
    for (int i = 0; i < n; i++) res[i][i] = 0;
    for (; k > 0; k >>= 1) {
        if (k & 1) res = mul(res, base, n);
        base = mul(base, base, n);
    }
    return res;
}
```

## Pitfalls

A negative cycle only changes answers for pairs that can reach it and then leave it for the requested destination. Trace both reachability checks.

1. **Wrong loop order.** `k` outermost. Putting `k` innermost computes something different and wrong.
2. **Infinity overflow.** `INF + INF` wraps around in fixed-width integers. Guard with `if d[i][k] < INF and d[k][j] < INF`, or pick an infinity that cannot overflow when added twice.
3. **Forgetting `d[i][i] = 0`** at the start (and getting positive "distances" to yourself). For shortest-cycle problems keep a separate matrix.
4. **Parallel edges.** Keep the cheapest when reading the input.
5. **Negative cycles** make the table meaningless for affected pairs. Check the diagonal before trusting it.
6. **Treating the min-plus power as a path problem.** It gives walks of **exactly** `k` edges. For "at most `k`" add a zero self loop at every vertex, or take the minimum over the powers.
7. **Neutral element.** The identity of the (min, +) product has 0 on the diagonal and infinity elsewhere, not the usual identity matrix.
8. **Time.** `n = 30`, `k = 10^9` needs about 43 products of 27,000 steps each, trivial. `n = 500` with a power is `500^3` times 43, far too slow. Check `n^3 log k`.
