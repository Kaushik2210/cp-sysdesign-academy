## Intuition

You stand in the top-left corner of a grid and may only step **right** or **down**. How many different routes lead to the bottom-right corner? Some cells are blocked.

Counting routes one by one is hopeless (a `300 x 300` grid has more routes than there are atoms in the universe). But every route to a cell arrives from exactly **two** places: the cell above or the cell to the left. So

> routes to a cell = routes to the cell above + routes to the cell on the left.

Each cell's answer depends only on two earlier cells. That is dynamic programming in its simplest form.

## Definition

Let `dp[i][j]` be the number of routes from `(0, 0)` to `(i, j)` using only right and down moves.

```text
dp[0][0] = 1                                   (if the start is free)
dp[i][j] = 0                                   if (i, j) is blocked
dp[i][j] = dp[i-1][j] + dp[i][j-1]             otherwise (missing neighbours count as 0)
```

The answer is `dp[h-1][w-1]`. Fill the table row by row; time and memory `O(hw)`. Since a row needs only the row above, one row of memory is enough.

The counts explode, so problems ask for the answer **modulo** a prime such as `10^9 + 7`. Reduce after every addition, which is valid because addition respects remainders:

```text
(a + b) mod p == ((a mod p) + (b mod p)) mod p
```

def routes(grid):

## The closed form for free grids

With no obstacles, every route has exactly `h - 1` down moves and `w - 1` right moves in some order, so the count is `C(h + w - 2, h - 1)`. Obstacles break the formula, which is why the table is needed. With few obstacles you can also count by **inclusion-exclusion over the blocked cells**, sorted by position, but that is a separate technique.

## Variations

| twist | change |
| --- | --- |
| minimum cost path | `dp[i][j] = cost[i][j] + min(dp[i-1][j], dp[i][j-1])` |
| maximum value collected | same shape with `max` |
| moves allowed in more directions | the table order must still respect dependencies; with cycles use BFS or Dijkstra instead |
| must pass through a given cell | multiply the counts of two separate runs |
| count paths with exactly `k` turns | add a state dimension |
| huge grid, few obstacles | inclusion-exclusion with binomials |

<Callout type="pitfall" title="Down and right only">
The DP is valid because the moves go in one direction, so every cell's dependencies are filled earlier. If you may also move up or left, a route can loop and there can be infinitely many; the question changes into a shortest-path problem.
</Callout>

## Pitfalls

1. **Seeding `dp[0][0] = 1` when the start is blocked.** Check the start cell first.
2. **Forgetting the modulus**, or reducing only at the end, which overflows fixed-width integers.
3. **Letting a blocked cell keep a nonzero value** from an earlier assignment. Reset blocked cells to `0`.
4. **Reading `dp[i-1][j]` for `i = 0`.** In Python a negative index silently wraps to the last row; guard it.
5. **Allocating the table the wrong way round.** Rows are `h`, columns are `w`; mixing them breaks non-square grids.
6. **Using recursion without memoisation.** The plain recursion is exponential.
