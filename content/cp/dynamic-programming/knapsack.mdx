## Intuition

You have a budget `W` and `n` items, each with a cost and a value, and you may take each item at most once. Which items maximise the total value?

Greedy fails. With `W = 50` and items `(cost, value) = (10, 60), (20, 100), (30, 120)`, taking the best ratio first picks the first two (value 160), but the best is the last two (value 220).

The brute force tries all `2^n` subsets. The saving comes from noticing that many subsets lead to the **same situation**: the same items left to consider and the same money left. Remember the best answer for each such situation instead of recomputing it. That is dynamic programming.

## Definition

Let `dp[i][c]` be the best total value using only the **first `i` items** with total cost at most `c`.

For item `i` with cost `w` and value `v`, there are two choices:

```text
skip it:  dp[i-1][c]
take it:  dp[i-1][c - w] + v        (only if w <= c)

dp[i][c] = max(skip, take)
dp[0][c] = 0 for every c
```

The answer is `dp[n][W]`. There are `n * (W + 1)` states and each costs `O(1)`, so the time is `O(nW)`.

This is **pseudo-polynomial**: the running time depends on the *value* of `W`, not on how many digits it has. With `W = 10^18` the table cannot exist.

## Code

The row for item `i` only reads the row for item `i - 1`, so one array is enough, provided you update it **from high capacity to low**. Going downwards guarantees `dp[c - w]` has not yet been changed by the current item.

<Tabs>
<Tab label="Python">

```python
dp = [0] * (W + 1)
for w, v in items:
    for c in range(W, w - 1, -1):      # downwards: each item once
        dp[c] = max(dp[c], dp[c - w] + v)
print(dp[W])
```

</Tab>
<Tab label="C++">

```cpp
vector<long long> dp(W + 1, 0);
for (auto [w, v] : items)
    for (int c = W; c >= w; c--)       // downwards: each item once

cout << dp[W];
```

</Tab>

<CodeRunner language="python" code={`from itertools import combinations

items = [(10, 60), (20, 100), (30, 120)]   # (cost, value)
W = 50

def knapsack(items, W, upwards=False):
    dp = [0] * (W + 1)
    for w, v in items:
        order = range(w, W + 1) if upwards else range(W, w - 1, -1)
        for c in order:
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[W]

def brute(items, W):
    best = 0
    for k in range(len(items) + 1):
        for comb in combinations(items, k):
            if sum(w for w, _ in comb) <= W:
                best = max(best, sum(v for _, v in comb))
    return best

print("dp (downwards):", knapsack(items, W))
print("brute force:   ", brute(items, W))
print("loop upwards:  ", knapsack([(10, 60)], 50, upwards=True), "(one item reused 5 times)")
`} />

The upwards loop is not a bug in the code; it solves a different problem, the **unbounded knapsack**, where every item has unlimited copies.

### Recovering which items you took

Keep the full 2D table `dp[i][c]`. Start at `(n, W)`. If `dp[i][c] != dp[i-1][c]` then item `i` was taken: record it and move to `(i-1, c - w)`. Otherwise move to `(i-1, c)`. The 1D trick saves memory but loses this information.

## Related problems

| twist | change |
| --- | --- |
| cost is huge but values are small | swap roles: `dp[value] = min cost` |
| can the exact budget be filled? | boolean `dp[c]`, or a `bitset` shifted by `w` |
| unlimited copies | loop capacities upwards |
| at most `k` copies | binary-split the count into powers of two |
| value is the same as cost | subset sum |

## Pitfalls

1. **Looping upwards in the 1D array**, which silently reuses items.
2. **Greedy by value/cost ratio.** It is optimal only for the fractional knapsack.
3. **`dp[c - w]` with `c < w`.** The loop bound `c >= w` prevents a negative index (in Python, a negative index would silently wrap).
4. **Overflow.** Values up to `10^9` summed over many items need 64-bit integers.
5. **Initialising with `-INF` versus `0`.** `dp[c] = 0` means "weight at most `c`". Use `-INF` for all but `dp[0]` only if you need weight *exactly* `c`.
6. **Treating `W` as small when it is not.** If `W` can be `10^9`, this DP is unusable; look for the other dimension (values) or a different method.
