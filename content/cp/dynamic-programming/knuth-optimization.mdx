## Intuition

In the [interval DP](/cp/dynamic-programming/interval-dp/) lesson you saw recurrences like

```text
dp[i][j] = min over k in [i, j) of ( dp[i][k] + dp[k+1][j] ) + cost(i, j)
```

There are `O(n²)` intervals and `O(n)` split points each: `O(n³)`. For `n = 1000` that is a billion steps.

The [divide and conquer DP](/cp/dynamic-programming/divide-and-conquer-dp/) lesson exploited a *monotone best split*: as the right end moves right, the best split never moves left. Intervals have two ends, so there is an even stronger statement. The best split for `[i, j]` sits **between** the best splits of the two neighbouring intervals that are one element shorter:

```text
opt[i][j-1]  <=  opt[i][j]  <=  opt[i+1][j]
```

Shrinking the interval from the right (`[i, j-1]`) or from the left (`[i+1, j]`) can only pull the best split towards the smaller side. So when computing `dp[i][j]` you only need to try splits in that narrow window. Remarkably, the windows are so small on average that the **total work becomes `O(n²)`**. This is **Knuth's optimization**.

## The classic example: optimal binary search tree

Keys `1..n` are looked up with frequencies `f[i]`. Choose the tree shape minimising `Σ f[i] · depth(i)`. If key `r` is the root of the range `[i, j]`, the left subtree covers `i..r−1` and the right subtree `r+1..j`, and every key in the range sits one level deeper than inside its subtree:

```text
dp[i][j] = min over r in [i, j] of ( dp[i][r-1] + dp[r+1][j] ) + (f[i] + ... + f[j])
```

Naively `O(n³)`. With `opt[i][j]` the best root, Knuth's bounds let you loop `r` only from `opt[i][j-1]` to `opt[i+1][j]`.

## When does it apply?

Write the recurrence as `dp[i][j] = min_k ( dp[i][k] + dp[k+1][j] ) + w(i, j)` (the root version is the same with the split index shifted). Knuth's optimization is valid when the extra cost `w` satisfies two conditions for all `a ≤ b ≤ c ≤ d`:

| condition | statement |
| --- | --- |
| **quadrangle inequality** | `w(a, c) + w(b, d) ≤ w(a, d) + w(b, c)` |
| **monotone on inclusion** | `w(b, c) ≤ w(a, d)` (a sub-interval is never more expensive than an interval containing it) |

A range-sum cost `w(i, j) = pre[j] − pre[i−1]` with non-negative entries satisfies both with equality in the first, which is why it works for optimal BSTs, for merging piles, and for cutting a stick (cost = length of the stick being cut). Intuitively: the cost of an interval grows smoothly and "nests", so nothing can pull the best split in the wrong direction.

If you cannot prove the conditions, **test**: compare against the `O(n³)` DP on random small inputs, as in the demo below.

## Why is the total O(n²)?

Process intervals by increasing length `L = j − i + 1`. For a fixed `L`, the work for interval `[i, j]` is `opt[i+1][j] − opt[i][j−1] + 1`. Summing over `i` (with `j = i + L − 1`):

```text
Σ_i ( opt[i+1][i+L-1] - opt[i][i+L-2] + 1 )
```

Consecutive terms **telescope**: the upper bound of one interval cancels the lower bound of the next, leaving about `n + L`. Over all lengths the total is `O(n²)`.

```python
def optimal_bst(f):                              # f[0..n-1]; returns the minimum total cost
    n = len(f)
    pre = [0] * (n + 1)
    for i in range(1, n + 1): pre[i] = pre[i - 1] + f[i - 1]
    INF = 1 << 60
    dp = [[0] * (n + 2) for _ in range(n + 2)]   # dp[i][j] on keys i..j (1-based); empty range = 0
    opt = [[0] * (n + 2) for _ in range(n + 2)]
    for i in range(1, n + 1):
        dp[i][i] = f[i - 1]; opt[i][i] = i
    for length in range(2, n + 1):
        for i in range(1, n - length + 2):
            j = i + length - 1
            best, bk = INF, i
            for r in range(opt[i][j - 1], opt[i + 1][j] + 1):     # Knuth's window
                v = dp[i][r - 1] + dp[r + 1][j]
                if v < best: best, bk = v, r
            dp[i][j] = best + pre[j] - pre[i - 1]
            opt[i][j] = bk
    return dp[1][n]
```

ll optimalBST(const vector<ll>& f) {             // f[1..n]
    int n = f.size() - 1;
    vector<ll> pre(n + 1, 0);
    for (int i = 1; i <= n; i++) pre[i] = pre[i - 1] + f[i];
    vector<vector<ll>> dp(n + 2, vector<ll>(n + 2, 0));

## Knuth, divide and conquer, or convex hull?

| technique | recurrence shape | requirement | total time |
| --- | --- | --- | --- |
| **Knuth** | interval: `dp[i][j]` from `dp[i][k]`, `dp[k+1][j]` | quadrangle inequality + monotone cost | `O(n²)` instead of `O(n³)` |
| **Divide and conquer** | layered: `dp[g][i]` from `dp[g-1][j]` | monotone `opt` (e.g. quadrangle inequality) | `O(k n log n)` |
| **Convex hull trick** | `dp[i] = min_j (m_j x_i + c_j)` | cost splits into a product of an `i`-part and a `j`-part | `O(n)` or `O(n log n)` |
| **Aliens trick** | answer convex in the number of groups `k` | convexity | one cheaper DP per penalty guess |

Knuth also has a layered form (`opt[g−1][i] ≤ opt[g][i] ≤ opt[g][i+1]`) that gives `O(n²)` for splitting into `k` groups, instead of `O(k n²)`.

## Pitfalls

1. **Applying it without the conditions.** If the cost does not satisfy the quadrangle inequality, the narrowed window can miss the true optimum and the DP is silently wrong. Always cross-check on small random inputs.
2. **Window bounds.** Use `opt[i][j-1]` as the lower and `opt[i+1][j]` as the upper bound, and make sure both are already computed: process intervals by **increasing length**.
3. **Mixing the two conventions.** The root form (`r` in `[i, j]`, empty ranges cost 0) and the split form (`k` in `[i, j-1]`, two non-empty parts) have different window clamps; for the split form clamp the upper end to `j − 1`.
4. **Initialising `opt` for length 1.** Set `opt[i][i] = i`; otherwise the first lengths use garbage windows.
5. **Ties.** Choose the smallest (or largest) best split consistently, using strict `<`, so the monotonicity argument holds.
6. **Memory.** `dp` and `opt` are both `n²` tables; for `n = 5000` that is 25 million entries each, so use 32-bit `opt` and compact `dp` where possible.
7. **Overflow.** Costs reach about `n² · max f`; use 64-bit integers.
