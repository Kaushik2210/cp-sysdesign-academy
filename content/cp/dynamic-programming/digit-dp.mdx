## Intuition

"How many integers between `L` and `R` have digit sum 10?" With `R` up to `10^15` you cannot loop. But the answer has structure: a number is built **digit by digit**, and what matters about the digits chosen so far is tiny (their sum), not the digits themselves.

Two tricks combine. First, count in a **prefix**: let `f(N)` be the count for `0..N`; then the answer is `f(R) - f(L-1)`. Second, count `f(N)` by asking **where a number first differs from `N`**. A number `x <= N` either equals `N`, or agrees with `N` for a while and then has a **smaller digit** at some position. After that position its remaining digits are completely unconstrained, so we only need to know *how many free strings of a given length have a given digit sum*, and that is a small table.

## Definition

Let `cnt[k][s]` be the number of strings of `k` digits (leading zeros allowed) whose digits sum to `s`:

```text
cnt[0][0] = 1
cnt[k][s] = sum over d in 0..9 of cnt[k-1][s-d]          # choose the first digit d
```

Write `N` as digits `N[0..L-1]`. Let `pre` be the digit sum of the part of `N` already read. For each position `i` and each digit `c < N[i]`, the numbers that copy `N[0..i-1]`, place `c` at `i` and then fill the other `L-i-1` positions freely number

```text
cnt[ L-i-1 ][ S - pre - c ]          (zero if the index is negative)
```

Add them all up, then add 1 if `N` itself has digit sum `S`.

```text
f(N, S):
    pre = 0; total = 0
    for i in 0..L-1:
        for c in 0..N[i]-1:
            total += cnt[L-i-1][S - pre - c]
        pre += N[i]
    total += (pre == S)
```

Per query this is about `10 * L` steps. The table costs `O(L * S * 10)` once.

This is **digit DP** in its "walk the prefix" form. The general form is a memoised recursion over the state `(position, remembered info, tight)`, where *tight* means "the prefix equals `N` so far, so the next digit is bounded by `N[i]`". Walking the prefix is the same thing with the tight branch unrolled into a loop.

## Example, step by step

Count `x` in `[0, 234]` with digit sum `S = 5`. Digits of `N`: `2, 3, 4`.

| position `i` | digit | smaller digits `c` | free length | counted | running total |
| --- | --- | --- | --- | --- | --- |
| 0 | 2 | `c = 0`: `cnt[2][5] = 6`; `c = 1`: `cnt[2][4] = 5` | 2 | 11 | 11 |
| 1 | 3 (`pre = 2`) | `c = 0, 1, 2` need 3, 2, 1: each `cnt[1][·] = 1` | 1 | 3 | 14 |
| 2 | 4 (`pre = 5`) | `c = 0` needs 0: `cnt[0][0] = 1`; `c = 1..3` need negative sums | 0 | 1 | 15 |
| end | `N` has digit sum 9 | not 5, so +0 | | | **15** |

For `c = 0` in the first row, the six free suffixes are `05, 14, 23, 32, 41, 50`, which are the numbers 5, 14, 23, 32, 41 and 50 (all below 200, so they first differ from `234` at the hundreds digit). Every other row reads the same way. The brute-force check below confirms 15.

```python
MAXS = 160
cnt = [[0] * (MAXS + 1) for _ in range(18)]
cnt[0][0] = 1
for k in range(1, 18):
    for s in range(MAXS + 1):
        cnt[k][s] = sum(cnt[k - 1][s - d] for d in range(10) if s - d >= 0)

def f(n, S):                         # how many x in [0, n] have digit sum S
    if n < 0:
        return 0
    digs = [int(ch) for ch in str(n)]
    pre = total = 0
    for i, d in enumerate(digs):
        rem = len(digs) - i - 1
        for c in range(d):
            need = S - pre - c
            if 0 <= need <= MAXS:
                total += cnt[rem][need]
        pre += d
    return total + (1 if pre == S else 0)

# answer for [L, R]:  f(R, S) - f(L - 1, S)
```

```java
static final int MAXS = 160;
static long[][] cnt = new long[18][MAXS + 1];

static long f(long n, int S) {       // how many x in [0, n] have digit sum S
    if (n < 0) return 0;

            if (need >= 0 && need <= MAXS) total += cnt[rem][need];
        }
        pre += d;
    }
    return total + (pre == S ? 1 : 0);
}
```

## When the state needs more than a sum

Replace "digit sum so far" by whatever the constraint needs, and keep the same skeleton:

| question | state to remember | free-part table |
| --- | --- | --- |
| digit sum equals or is a multiple of `S` | sum (or sum mod `S`) | `cnt[k][s]` |
| no two adjacent equal digits | last digit | `cnt[k][last]` |
| count of a particular digit (say 7) | how many so far | `cnt[k][c]` |
| number divisible by `m` | value mod `m` | `cnt[k][r]` |
| numbers whose digits are all from a set | nothing | `|set|^k` |

For constraints involving the **leading zeros** (for example "no repeated digit" must ignore padding), add a state bit "has the number started yet".

When a table is awkward, write the recursion `go(pos, state, tight, started)` with memoisation only for `tight = false` states: the tight path is a single chain, so only the non-tight states repeat.

## Pitfalls

1. **Forgetting `L - 1`.** The prefix trick needs `f(R) - f(L-1)`. With `L = 1` that is `f(0)`, which must handle `N = 0` (one digit, the number zero).
2. **Counting `N` itself.** The loop only counts numbers that are *strictly smaller* at some position; add 1 separately if `N` qualifies.
3. **Leading zeros.** `cnt[k][s]` counts strings with leading zeros, which is right for digit sums (zeros add nothing) but wrong for "no repeated digit" or "number of digits".
4. **Negative indexes.** `S - pre - c` can go below zero; guard it, or the table lookup wraps around in Python or reads garbage in C++.
5. **Overflow and parsing.** Counts reach about `10^15` to `10^18`, so use 64-bit integers; in JavaScript use `BigInt` beyond `2^53`.
6. **Table size.** `cnt` needs one more row than the number of digits of the biggest `N` you will see (for `10^18` that is 19 digits).
