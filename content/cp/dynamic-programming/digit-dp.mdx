## Intuition

"How many integers between `L` and `R` have property `P`?" with `R` up to `10^18` cannot be answered by trying them. But a number is just a **string of digits**, and many properties are decided by looking at the digits one at a time with a tiny amount of memory: the digit sum so far, the last digit, whether we have seen a 4. If you can describe the property as "scan the digits left to right with a small state", you can count **all** numbers with that property by running the scan on *every* number at once, merging the numbers that reach the same state. That is **digit DP**.

The second trick is to handle the upper bound. Counting up to `N` means counting digit strings that are **at most** `N`. You walk along `N`'s digits and track one extra bit: "so far, am I still exactly equal to `N`'s prefix?" While equal (**tight**), the next digit may not exceed `N`'s digit; once you place a smaller digit you are **free** and any digit goes.

## Definition

To answer a query over `[L, R]`, compute `count(N)` for "the number of valid integers in `[0, N]` or `[1, N]`" and return

```text
answer = count(R) - count(L - 1)
```

Write `N` as digits `d[0..len-1]`, most significant first. Place digits from left to right. The state of the recursion is

```text
go(pos, <property state>, tight, started)
```

- `pos`: how many digits are already placed.
- `<property state>`: whatever the property needs, for example `digit sum mod k`, `last digit`, `count of 4s`, `a bitmask of used digits`.
- `tight`: `true` if the digits placed so far equal `d[0..pos-1]`. Then the next digit ranges over `0..d[pos]`; otherwise `0..9`.
- `started`: `true` once a non-zero digit has been placed. Leading zeros are not real digits: they must not count toward the digit sum, the "last digit" or "no equal neighbours".

```text
go(pos, state, tight, started):
    if pos == len:  return 1 if the number is valid else 0
    limit = d[pos] if tight else 9
    total = 0
    for digit in 0..limit:
        next_tight   = tight and digit == limit
        if not started and digit == 0:  total += go(pos+1, same state, next_tight, False)
        else:                           total += go(pos+1, update(state, digit), next_tight, True)
    return total
```

**Memoise on the whole tuple.** The number of states is `len × |property states| × 2 × 2`, with `len <= 19`. The tight chain is one single path; every state off that path is shared by many numbers, which is where the saving comes from.

## Example, step by step

Count `x` in `[0, 25]` with digit sum equal to `5` (just to see the shape). `N = 25`, digits `[2, 5]`.

- Position 0, tight: digit may be `0, 1, 2`.
  - Digit `0` or `1`: no longer tight. The second digit is free `0..9`; we need the remaining digit to bring the sum to 5: for first digit 0 the second must be 5 (number 5), for first digit 1 it must be 4 (number 14). Two numbers.
  - Digit `2`: still tight. The second digit ranges over `0..5`; it must be 3 (number 23). One number.
- Total: `5, 14, 23`: three numbers.

The same logic, with a table memoising the non-tight cases, is what the code below does for any property.

import sys
from functools import lru_cache
sys.setrecursionlimit(10000)

def count_upto(n, k):
    """Valid integers in [1, n]: digit sum divisible by k, no two equal neighbours."""
    if n <= 0:
        return 0
    digits = [int(c) for c in str(n)]

    @lru_cache(maxsize=None)
    def go(pos, mod, last, tight, started):
        if pos == len(digits):
            return 1 if started and mod == 0 else 0
        limit = digits[pos] if tight else 9
        total = 0
        for d in range(limit + 1):
            nt = tight and d == limit
            if not started and d == 0:
                total += go(pos + 1, 0, 10, nt, False)
            elif started and d == last:
                continue
            else:
                total += go(pos + 1, (mod + d) % k, d, nt, True)
        return total

    return go(0, 0, 10, True, False)

long long memo[20][100][11][2][2];

long long go(int pos, int mod, int last, int tight, int started) {
    if (pos == (int)digits.size()) return (started && mod == 0) ? 1 : 0;
    long long& res = memo[pos][mod][last][tight][started];
    if (res >= 0) return res;
    int limit = tight ? digits[pos] : 9;
    long long total = 0;
    for (int d = 0; d <= limit; d++) {

        if (!started && d == 0) total += go(pos + 1, 0, 10, nt, 0);
        else if (started && d == last) continue;
        else total += go(pos + 1, (mod + d) % k, d, nt, 1);
    }
    return res = total;

long long count_upto(long long n) {
    if (n <= 0) return 0;
    string s = to_string(n);
    digits.clear();
    for (char c : s) digits.push_back(c - '0');
    memset(memo, -1, sizeof(memo));           // reset for each bound
    return go(0, 0, 10, 1, 0);

## Common variants

| question | extra state beyond `(pos, tight, started)` |
| --- | --- |
| digit sum equals or is divisible by something | `sum` or `sum mod k` |
| no two equal (or consecutive) adjacent digits | `last` digit |
| contains / avoids a digit | a boolean `seen` |
| count how many times digit `d` appears across all numbers | carry the count and the total of numbers; or add a `count` state and sum `count × ways` |
| every digit allowed from a set | no extra state, restrict the loop |
| divisible by the number itself's digits (Beautiful numbers) | `value mod lcm(1..9)` and `lcm` of used digits |
| property of the binary representation (popcount, XOR) | same idea with base 2 and `tight` over bits |
| count numbers in `[L, R]` with property in base `b` | change `10` to `b` and `9` to `b - 1` |
| k-th number with the property | count with a prefix fixed, then choose digits greedily or binary search on `N` |

## Pitfalls

1. **Treating leading zeros as digits.** Without `started`, `0042` has "two equal neighbours" and `last` is wrong. Always ask: do leading zeros change the state?
2. **Forgetting to subtract `count(L - 1)`** or evaluating `count(0)` incorrectly. Handle `N <= 0` explicitly, and decide whether `0` itself belongs to the answer.
3. **Sharing a memo table across different bounds** when the memo includes the `tight` flag. Either reset it for each `N`, or memoise only non-tight states (they do not depend on `N`) and keep it across calls.
4. **Wrong limit in the loop**: `limit = d[pos]` only when tight. A free position goes up to `9`.
5. **`next_tight`**: it is `tight and digit == limit`, not `digit == d[pos]` when you are already free.
6. **Overflow.** Counts reach `10^18`. Use 64-bit integers; JavaScript needs `BigInt` for both the input and the counts.
7. **State blow-up.** Adding a mask of used digits (1024 states) or a large modulus is fine; adding anything that grows with the value of `N` is not.
8. **Using plain recursion without memoisation** over `10^18` digits' worth of states is exponential in the length, `10^19`.
