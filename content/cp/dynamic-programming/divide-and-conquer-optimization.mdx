## Intuition

A classic family of DPs **partitions a sequence into `k` consecutive groups**: split a row of crates into `k` loads, cut an array into `k` segments, place `k` mailboxes along a street. The state is `dp[j][i]`, the best cost for the first `i` items in `j` groups:

```text
dp[j][i] = min over p < i of ( dp[j-1][p] + cost(p, i) )
```

That is `O(k n^2)`. But often the best split point behaves in an orderly way: when `i` grows, the best `p` never moves left. If you know the best `p` for the **middle** `i`, then the best `p` for every smaller `i` is at or before it, and for every larger `i` at or after it. That lets a divide and conquer fill a whole layer in `O(n log n)`.

## Definition

Let `opt[j][i]` be a split point `p` that achieves the minimum for `dp[j][i]`. The optimisation applies when

```text
opt[j][i]  <=  opt[j][i+1]            (monotone optimal split)
```

A sufficient condition is the **quadrangle inequality** on the cost: for `a <= b <= c <= d`,

```text
cost(a, c) + cost(b, d)  <=  cost(a, d) + cost(b, c)
```

("crossing intervals cost no more than nested ones"). For `cost(p, i) = (S[i] - S[p])^2` with non-decreasing prefix sums `S` this is true: the difference of the two sides is `2 (S[d] - S[c]) (S[b] - S[a]) >= 0`. That is why the practice problem needs non-negative weights.

**Algorithm for one layer.**

```text
compute(lo, hi, optlo, opthi):          # fill dp[j][lo..hi]; best p lies in [optlo, opthi]
    if lo > hi: return
    mid = (lo + hi) / 2
    best p = argmin over p in [optlo, min(mid - 1, opthi)] of dp[j-1][p] + cost(p, mid)
    dp[j][mid] = that minimum
    compute(lo, mid - 1, optlo, bestp)
    compute(mid + 1, hi, bestp, opthi)
```

At each depth of the recursion the scanned ranges `[optlo, opthi]` overlap in at most one point, so a depth costs `O(n)` in total. There are `O(log n)` depths, so one layer costs `O(n log n)` and the whole DP `O(k n log n)`. The recursion is only `log n` deep, which is safe in every language.

## Example, step by step

Crates `4 1 1 4`, `k = 2` loads. Prefix sums `S = [0, 4, 5, 6, 10]`.

Layer 1 (one load): `dp1[i] = S[i]^2 = [0, 16, 25, 36, 100]`.

Layer 2, the best last split `p` for each `i`:

| `i` | candidates `p` and cost `dp1[p] + (S[i] - S[p])^2` | best | `opt` |
| --- | --- | --- | --- |
| 2 | `p = 1`: `16 + 1 = 17` | 17 | 1 |
| 3 | `p = 1`: `16 + 4 = 20`; `p = 2`: `25 + 1 = 26` | 20 | 1 |
| 4 | `p = 1`: `16 + 36 = 52`; `p = 2`: `25 + 25 = 50`; `p = 3`: `36 + 16 = 52` | **50** | 2 |

`opt = 1, 1, 2` never decreases. With D&C, computing `i = 3` first (the middle of `2..4`) finds `opt = 1`; then `i = 2` only looks at `p <= 1` and `i = 4` only at `p >= 1`, skipping nothing it needs. The answer is **50**: loads `4 1 | 1 4` cost `5^2 + 5^2`.

## Choosing among DP optimisations

| optimisation | needs | time | typical shape |
| --- | --- | --- | --- |
| **divide and conquer** (this lesson) | monotone `opt` (quadrangle inequality); layers `dp[j][...]` | `O(k n log n)` | partition into `k` groups |
| **Knuth** | quadrangle inequality plus monotone `opt[i][j-1] <= opt[i][j] <= opt[i+1][j]` | `O(n^2)` instead of `O(n^3)` | interval DP such as optimal merging or optimal BST |
| **convex hull trick** | cost splits into a product of a `j` part and an `i` part | `O(n)` or `O(n log n)` | `dp[i] = min dp[j] + b[j] a[i]` |
| **Aliens trick** (lambda optimisation) | convex in `k` | `O(n log C)` per run | `k` huge, replace the layer by a penalty per group |
| **monotone queue** | cost depends on `i - j` windows | `O(n)` | sliding-window minimum |

When both D&C and the hull trick apply, the hull trick is faster (`O(n)` per layer), but D&C asks only for the monotonicity, not for an algebraic identity.

## Pitfalls

1. **Applying it without monotonicity.** Check the quadrangle inequality, or at least compare against the slow DP on random small inputs, as the demo does. A cost like `(S[i] - S[p])^2` with **negative** weights breaks it.
2. **Wrong ranges for `p`.** Layer `j` needs `p >= j - 1` (at least `j - 1` items before the last group) and `p <= i - 1` (a non-empty last group).
3. **`INF` in the scan.** Skip states with `prev[p] == INF`, otherwise adding to `INF` overflows in C++ and Java.
4. **Boundary of the recursion.** The left call uses `[optlo, bestp]` and the right call `[bestp, opthi]`; both include `bestp` because ties are possible.
5. **Using one array for two layers.** Layer `j` reads layer `j - 1` while writing; keep two arrays and swap.
6. **Overflow.** The cost reaches `(sum of all weights)^2`, so use 64-bit integers.
7. **Forgetting the exactly-`k` constraint.** If at most `k` groups are allowed, take the minimum over all layers (or note that more groups never cost more here).
