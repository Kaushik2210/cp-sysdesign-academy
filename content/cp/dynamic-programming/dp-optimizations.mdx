## Intuition

Many DPs have a transition that tries **every earlier state**:

```text
dp[i] = min over j < i of ( dp[j] + cost(j, i) )
```

That is `O(n^2)`, and `n = 10^5` or `10^6` makes it hopeless. The reason it is often avoidable is that the transition has **structure**: for the right kind of `cost`, you can predict which `j` wins without trying all of them. Three families of structure cover most contest problems:

1. **Convex hull trick (CHT):** `cost` splits into a part depending on `j` and a part that is a **product** of something about `j` and something about `i`. Then each `j` is a *line*, and the transition is "lowest line at a point".
2. **Divide and conquer optimisation:** the best `j` for `i` never moves backwards as `i` grows (`opt(i) <= opt(i + 1)`). Compute the middle `i`, then recurse on the two halves with narrower candidate ranges.
3. **Knuth's optimisation** for interval DPs: the best split point is sandwiched between two neighbours, `opt[i][j-1] <= opt[i][j] <= opt[i+1][j]`.

## Convex hull trick

Take the batch problem from the practice section: split `n` parcels into consecutive batches; a batch of total weight `W` costs `W^2 + C`. With prefix sums `pre`:

```text
dp[i] = min over j < i of  dp[j] + (pre[i] - pre[j])^2 + C
```

Expand the square: `(pre[i] - pre[j])^2 = pre[i]^2 - 2*pre[j]*pre[i] + pre[j]^2`. Group what depends on `j` only, and what depends on `i` only:

```text
dp[i] = pre[i]^2 + C + min over j of ( (-2*pre[j]) * pre[i] + (dp[j] + pre[j]^2) )
                                         \_____ m_j _____/ x    \_______ b_j _______/
```

Each earlier index `j` is a **line** `y = m_j * x + b_j`, and `dp[i]` needs the **minimum of all lines at `x = pre[i]`**. The pointwise minimum of lines is a concave, piecewise-linear curve: the **lower envelope**. Only lines that appear on the envelope can ever be the answer, so keep just those.

When the slopes arrive in **monotone order** (here `m_j = -2*pre[j]` strictly decreasing, because weights are positive) and the queries `x = pre[i]` are **also monotone** (increasing), the whole thing is a deque and a pointer:

- **Adding a line** `l3` after `l1, l2` (slopes `m1 > m2 > m3`): the middle line `l2` is useless if `l1` and `l3` already cross at or before the point where `l1` and `l2` cross. Compare crossing points by cross multiplication (no division):

```text
(b3 - b1) * (m1 - m2)  <=  (b2 - b1) * (m1 - m3)      =>  remove l2
```

- **Querying** at an increasing `x`: advance the front pointer while the next line is no worse at `x`.

Every line is added once and removed at most once: **`O(n)` total**.

| situation | structure | cost |
| --- | --- | --- |
| slopes sorted and queries sorted | deque with a pointer (above) | `O(1)` amortised |
| slopes sorted, queries arbitrary | deque, **binary search** the hull for each query | `O(log n)` |
| lines and queries in any order | **Li Chao tree** over the `x` range (each node keeps one line, push the loser down) | `O(log n)` per line and per query |
| maximum instead of minimum | negate slopes and intercepts, or flip the comparison | same |

## Divide and conquer optimisation

A common layered DP: split an array into `k` groups, `dp[g][i] = min over j < i of dp[g-1][j] + cost(j, i)`. A layer is `O(n^2)` by brute force.

If `opt(g, i)`, the best `j` for `dp[g][i]`, satisfies `opt(g, i) <= opt(g, i + 1)`, compute a layer by recursion:

```text
solve(lo, hi, optlo, opthi):          # fill dp[g][lo..hi]; the best j for each lies in [optlo, opthi]
    mid = (lo + hi) / 2
    scan j in [optlo, min(mid - 1, opthi)] to find the best j* for mid
    solve(lo, mid - 1, optlo, j*)
    solve(mid + 1, hi, j*, opthi)
```

Every level of the recursion scans each candidate `j` about once in total, and there are `log n` levels: **`O(n log n)` per layer**, `O(k n log n)` overall.

**When does `opt` move monotonically?** If `cost` satisfies the **quadrangle inequality** (also called the Monge condition) for `a <= b <= c <= d`:

```text
cost(a, c) + cost(b, d)  <=  cost(a, d) + cost(b, c)
```

Sums of squares of group totals satisfy it. Intuitively: crossing intervals are never cheaper than nested ones, so the best split cannot move left when the right end moves right. Verify it (or test `opt` empirically) before relying on it: the optimisation silently gives wrong answers when it fails.

## Knuth's optimisation

For interval DPs, `dp[i][j] = min over k of dp[i][k] + dp[k+1][j] + cost(i, j)` (the [interval DP](/cp/dynamic-programming/interval-dp/) lesson), if `cost` satisfies the quadrangle inequality and is monotone, then `opt[i][j-1] <= opt[i][j] <= opt[i+1][j]`. Restricting the loop over `k` to that range makes the whole table `O(n^2)` instead of `O(n^3)`, because the total scan over a diagonal telescopes.

## Example, step by step

Weights `1 1 1 1`, `C = 1`; `pre = [0, 1, 2, 3, 4]`.

- Lines: `j = 0`: `m = 0`, `b = dp[0] + 0 = 0`.
- `i = 1`, `x = 1`: only line 0: value `0`, `dp[1] = 0 + 1 + 1 = 2`. Add line `j = 1`: `m = -2`, `b = 2 + 1 = 3`.
- `i = 2`, `x = 2`: line 0 gives `0`; line 1 gives `-4 + 3 = -1`. The minimum is `-1`: `dp[2] = -1 + 4 + 1 = 4`. Add `j = 2`: `m = -4`, `b = 4 + 4 = 8`.
- `i = 3`, `x = 3`: line 1 gives `-3`; line 2 gives `-12 + 8 = -4`. `dp[3] = -4 + 9 + 1 = 6`.
- `i = 4`, `x = 4`: line 2 gives `-8`; line 3 (`m = -6`, `b = 6 + 9 = 15`) gives `-9`. `dp[4] = -9 + 16 + 1 = 8`.

The answer `8` (four batches of one parcel) matches the problem statement.

ms, bs, ptr = [0], [0], 0

def bad(a, b, c):                       # is the middle line b never strictly the minimum?
    return (bs[c] - bs[a]) * (ms[a] - ms[b]) <= (bs[b] - bs[a]) * (ms[a] - ms[c])

for i in range(1, n + 1):
    x = pre[i]
    ptr = min(ptr, len(ms) - 1)
    while ptr + 1 < len(ms) and ms[ptr + 1] * x + bs[ptr + 1] <= ms[ptr] * x + bs[ptr]:
        ptr += 1                         # queries only increase, so earlier lines never win again
    dp[i] = ms[ptr] * x + bs[ptr] + x * x + C

    """dp[i] = min over j < i of dp[j] + (pre[i] - pre[j])^2 + C, in O(n^2)."""

def groups_slow(a, k):
    """Split a into exactly k consecutive groups; cost of a group = (its sum)^2. O(k n^2)."""
    n = len(a)
    pre = [0]
    for x in a:

        nd = [INF] * (n + 1)
        for i in range(1, n + 1):
            nd[i] = min(dp[j] + (pre[i] - pre[j]) ** 2 for j in range(i))
        dp = nd

def groups_dc(a, k):
    """Same answer in O(k n log n): the best split point opt(i) never decreases as i grows."""
    n = len(a)
    pre = [0]
    for x in a:
        pre.append(pre[-1] + x)
    INF = float("inf")

    for _ in range(k):
        cur = [INF] * (n + 1)
        def solve(lo, hi, optlo, opthi):        # compute cur[lo..hi]; the best j lies in [optlo, opthi]
            if lo > hi:
                return
            mid = (lo + hi) // 2
            best, bj = INF, -1
            for j in range(optlo, min(mid - 1, opthi) + 1):
                v = prev[j] + (pre[mid] - pre[j]) ** 2
                if v < best:

            cur[mid] = best

            solve(mid + 1, hi, bj, opthi)       # larger i cannot have a smaller opt

## Choosing the technique

| pattern | technique | requirement |
| --- | --- | --- |
| `dp[i] = min_j (dp[j] + b_j * a_i) + f(i)` | convex hull trick | slopes and queries sorted for `O(n)`; otherwise binary search or Li Chao tree |
| layered `dp[g][i] = min_j dp[g-1][j] + cost(j, i)` | divide and conquer | `opt` monotone (quadrangle inequality) |
| interval `dp[i][j] = min_k ... + cost(i, j)` | Knuth | quadrangle inequality and monotone `cost` |
| exactly `k` groups, and the answer is convex in `k` | **Aliens trick** (Lagrangian relaxation): add a penalty `lambda` per group, binary search `lambda`, solve the penalised problem with CHT in `O(n)` | convexity of the answer in `k` |
| `dp[i] = min over a sliding window j in [i - L, i)` | monotone deque | window of fixed size |
| `dp[i] = min_j dp[j] + cost`, `cost` arbitrary | none: keep `O(n^2)` | |

## Pitfalls

1. **Using an optimisation without checking its condition.** CHT needs a separable cost; D&C and Knuth need the quadrangle inequality. A wrong assumption gives plausible but incorrect answers. Compare against the quadratic DP on small random inputs, as the demo does.
2. **Overflow in the cross multiplication.** Intercepts are around the DP values squared; their product with slope differences can pass `10^18`. Bound the values, use `__int128` in C++, or compare with doubles carefully. This is the most common bug.
3. **Wrong comparison direction** when switching between minimum and maximum, or when slopes are increasing instead of decreasing.
4. **Equal slopes.** Two lines with the same slope: keep only the one with the better intercept, or the cross-multiplied test divides by zero in the division form.
5. **Pointer walking with non-monotone queries.** The moving pointer is only valid when queries increase; otherwise use a binary search on the hull.
6. **Forgetting to clamp the pointer** after lines are popped from the back.
7. **D&C candidate range off by one.** For the middle `mid`, the candidate `j` must be `< mid` (a group is non-empty).
8. **Applying Knuth or D&C where `opt` is not monotone**, such as when the cost depends on `j` in a non-Monge way.
