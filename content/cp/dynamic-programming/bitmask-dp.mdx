## Intuition

You have `n` workers and `n` tasks with different prices. Trying all `n!` ways to pair them is hopeless at `n = 15` (over a trillion). But think about what you actually need to remember while handing out tasks to workers one after another: **not who did what, only which tasks are already gone**. Two different histories that used up the same set of tasks lead to the same future.

A set of at most `20` items fits in one integer: bit `j` is `1` when item `j` is in the set. The number of different sets is `2^n`, vastly smaller than `n!`. Dynamic programming over **subsets stored as bitmasks** is called **bitmask DP**.

## Definition

For the assignment problem let `dp[mask]` be the cheapest way to give the tasks in `mask` to the first `popcount(mask)` workers.

```text
dp[0] = 0
for every mask:
    i = popcount(mask)                      # the next worker to place
    for every task j not in mask:
        dp[mask | (1 << j)] = min(dp[mask | (1 << j)], dp[mask] + cost[i][j])
answer = dp[(1 << n) - 1]
```

Iterating `mask` in increasing order is valid: adding a bit always makes the number bigger, so a state is final before it is used. Time `O(2^n * n)`, memory `O(2^n)`.

The number of set bits already identifies the worker, so no extra dimension is needed. If an extra fact must be tracked (the last vertex visited, say) it becomes the second dimension: `dp[mask][last]`.

## Bit operations you need

| goal | expression |
| --- | --- |
| is item `j` in `mask`? | `mask >> j & 1` |
| add item `j` | `mask \| (1 << j)` |
| remove item `j` | `mask & ~(1 << j)` |
| number of items | `bin(mask).count("1")` (Python), `__builtin_popcount(mask)` (C++), `Integer.bitCount(mask)` (Java) |
| all items | `(1 << n) - 1` |
| iterate over submasks of `m` | `s = m; while s: ...; s = (s - 1) & m` |

## The travelling salesman in the same mould

Visit every city once and return, as cheaply as possible. State: `dp[mask][last]`, the cheapest way to have visited the cities in `mask` ending at `last`. Transition: extend to a city `nxt` not in `mask`. That is `O(2^n * n^2)`, which works up to `n` around `18`, instead of `n!`.

<Callout type="note" title="How large can n be?">
`2^20` is about a million states, comfortable. `2^25` is 33 million, borderline and heavy on memory. A rule of thumb: bitmask DP for `n <= 20`, and look for a polynomial algorithm (Hungarian for assignment, matching for pairing) beyond that.
</Callout>

## Related problems

| problem | state |
| --- | --- |
| assignment, minimum cost matching | `dp[mask]` |
| travelling salesman, Hamiltonian paths | `dp[mask][last]` |
| split `n` items into the fewest groups of limited capacity (elevator rides) | `dp[mask] = (groups, load of the last group)` |
| profile DP on grids (tilings) | `dp[column][mask of the boundary]` |
| subset sums over all subsets, sum-over-subsets (SOS) | iterate bits, update supersets |

## Pitfalls

1. **Forgetting `1 << n` states cost memory.** `n = 25` with `long long` is already 268 MB.
2. **Starting from the wrong base.** `dp[0] = 0` and everything else infinite, and skip infinite states.
3. **Using `+` instead of `|`** to add an item that may already be present; check the bit first.
4. **Wrong operator precedence.** `mask >> j & 1` is fine in Python and C++ (shift binds tighter than `&`), but add parentheses in other languages if unsure.
5. **Iterating masks in the wrong order.** Transitions that add bits need increasing order; transitions that remove bits need decreasing order.
6. **Recomputing popcount in the inner loop.** Compute it once per mask, as above.
