## Intuition

A network of roads is working fine, but you worry about single points of failure: **which one road, if closed, would cut the country in two?** Checking each road by deleting it and re-running a search costs `O(m (n + m))`. One depth-first search can answer for all roads at once.

The key observation: in a DFS tree, a road that is **not** in the tree (a *back edge*) always closes a cycle, so it can never be critical. A tree road `p → c` is critical exactly when the whole subtree below `c` has **no escape route** back to `p` or higher through a back edge.

## Definition

Run a DFS and number the vertices in the order they are first visited: `tin[v]`. Define

```text
low[v] = the smallest tin reachable from v's subtree
         using tree edges downward and at most one back edge
```

Updates, for each edge `v - to` (skipping the edge used to arrive at `v`):

```text
to already visited (back edge):   low[v] = min(low[v], tin[to])
to is a child (after returning):  low[v] = min(low[v], low[to])
```

A tree edge `(p, c)` is a **bridge** exactly when

```text
low[c] > tin[p]
```

Nothing in the subtree of `c` reaches `p` or an ancestor, so removing the edge isolates that subtree. If `low[c] <= tin[p]`, some back edge bypasses it. Total time is `O(n + m)`.

## Example

Two triangles joined by one road:

```text
1 - 2        4 - 5
 \ /    3-4   \ /
  3            6
```

The triangles' roads all lie on cycles, so their `low` values reach back to the triangle's first vertex. The road `3 - 4` is the only way across: `low[4] = tin[4] > tin[3]`, so it is the single bridge.

```python
def find_bridges(n, edges):
    adj = [[] for _ in range(n + 1)]
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        adj[v].append((u, i))
    tin = [0] * (n + 1); low = [0] * (n + 1)
    pe = [-1] * (n + 1); nxt = [0] * (n + 1)
    timer = 0; bridges = []
    for s in range(1, n + 1):
        if tin[s]: continue
        timer += 1; tin[s] = low[s] = timer
        stack = [s]
        while stack:                              # explicit stack: no recursion limit
            v = stack[-1]
            if nxt[v] < len(adj[v]):
                to, e = adj[v][nxt[v]]; nxt[v] += 1
                if e == pe[v]: continue           # skip the arrival edge by id
                if tin[to]:
                    low[v] = min(low[v], tin[to])
                else:
                    timer += 1; tin[to] = low[to] = timer
                    pe[to] = e; stack.append(to)
            else:
                stack.pop()
                if stack:
                    p = stack[-1]
                    low[p] = min(low[p], low[v])
                    if low[v] > tin[p]: bridges.append(pe[v])
    return sorted(bridges)
```

vector<vector<pair<int,int>>> adj;     // (neighbour, edge id)
vector<int> tin, low, bridges;
int timer_ = 0;

void dfs(int v, int parentEdge) {
    tin[v] = low[v] = ++timer_;
    for (auto [to, e] : adj[v]) {
        if (e == parentEdge) continue;             // by id, so parallel edges work
        if (tin[to]) {
            low[v] = min(low[v], tin[to]);          // back edge
        } else {
            dfs(to, e);
            low[v] = min(low[v], low[to]);
            if (low[to] > tin[v]) bridges.push_back(e);
        }
    }
}

        }
    }

## Articulation points (cut vertices)

A **cut vertex** is a vertex whose removal disconnects its region. The same `tin` and `low` work, with two small changes:

- A non-root vertex `p` is a cut vertex if some child `c` has `low[c] >= tin[p]` (note `>=`, because the escape route may land on `p` itself, which is deleted too).
- The DFS root is a cut vertex only if it has **two or more** DFS-tree children.

## Pitfalls

1. **Skipping the parent vertex instead of the parent edge.** With parallel roads the second copy is a genuine back edge. Compare edge ids.
2. **`>` versus `>=`.** Bridges use `low[c] > tin[p]`; cut vertices use `>=`. Mixing them up is the classic bug.
3. **Forgetting disconnected graphs.** Start a new DFS from every unvisited vertex.
4. **Recursion depth.** A path graph of `2·10^5` vertices overflows Python's stack (and risks the C++ one); use an explicit stack or raise the limit with care.
5. **Updating `low` through a visited vertex's `low`.** For a back edge use `tin[to]`, not `low[to]`; mixing them still gives bridges but breaks the 2-edge-connected-component and cut-vertex variants.
6. **Reporting vertex pairs instead of edge ids.** When the input has parallel edges the pair is ambiguous.
