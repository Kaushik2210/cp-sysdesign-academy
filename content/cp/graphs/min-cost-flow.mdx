## Intuition

[Maximum flow](/cp/graphs/maximum-flow/) tells you how many parcels can get from the source to the sink. But routes have **prices**, and among all ways to ship the maximum amount, some are cheaper than others. Ship greedily along the cheapest route and you may block a better combination later; ship along any route and you may overpay.

The fix reuses the residual-graph idea: **always send the next unit along the currently cheapest path**, where "cheapest" is measured in the residual graph. A reverse edge of a route with price `w` has price `-w`: using it **refunds** the price already paid, which is exactly what rerouting a parcel does.

## Definition

A **flow network with costs** has edges `(u, v)` with capacity `c` and price `w` per unit. A flow's **cost** is the sum of `flow(e) * w(e)`. **Min-cost max-flow** asks for a flow of maximum value whose cost is the smallest among all maximum flows.

**Residual graph.** Every edge gets a twin `(v, u)` with capacity 0 and price `-w`. Sending `d` units along `e` does `cap[e] -= d` and `cap[e ^ 1] += d`, and adds `d * w` to the cost.

**Successive shortest paths.**

```text
repeat:
    find a cheapest path S -> T among edges with positive residual capacity   (prices may be negative)
    if there is none: stop
    f = smallest residual capacity on the path
    push f units along it:  flow += f,  cost += f * (price of the path)
```

**Why it is correct.** Invariant: after every augmentation the current flow is a minimum-cost flow *among all flows of its value*, which is equivalent to the residual graph having **no negative cycle**. Augmenting along a cheapest path preserves that, so at the end the flow is a cheapest maximum flow. The prices of consecutive augmenting paths never decrease.

**Finding the cheapest path.** Residual prices can be negative, so use **SPFA** (Bellman-Ford with a queue, expected near-linear) or **Dijkstra with potentials**: keep `h[v]` = the distance from the last run, and run Dijkstra on the reduced prices `w + h[u] - h[v]`, which are non-negative. Initial potentials are zero when all prices are non-negative.

Each augmentation sends at least one unit, so there are at most `F` of them (`F` = the max-flow value).

## Example, step by step

Four hubs, routes `(from, to, capacity, price)`:

```text
1->2 (2, 1)    1->3 (1, 2)    2->3 (1, 1)    2->4 (1, 3)    3->4 (2, 1)
```

| round | cheapest path | price per unit | units pushed | flow | total price |
| --- | --- | --- | --- | --- | --- |
| 1 | `1 -> 3 -> 4` | 2 + 1 = 3 | 1 | 1 | 3 |
| 2 | `1 -> 2 -> 3 -> 4` | 1 + 1 + 1 = 3 | 1 | 2 | 6 |
| 3 | `1 -> 2 -> 4` | 1 + 3 = 4 | 1 | 3 | 10 |
| 4 | none (every route into hub 4 is full) | | | | |

Result: **3 parcels at total price 10**. Paths of equal price (rounds 1 and 2 tie) may be found in either order; the totals do not change. The prices of the augmenting paths, 3, 3, 4, are non-decreasing, as the theory promises.

graph = [[] for _ in range(n + 1)]
to, cap, cost = [], [], []
def add_edge(u, v, c, w):

    graph[v].append(len(to)); to.append(u); cap.append(0); cost.append(-w)

flow = total = 0
INF = float("inf")
while True:
    dist = [INF] * (n + 1); dist[S] = 0
    pe = [-1] * (n + 1); inq = [False] * (n + 1)
    q = deque([S])
    while q:                                         # SPFA
        v = q.popleft(); inq[v] = False
        for e in graph[v]:
            if cap[e] > 0 and dist[v] + cost[e] < dist[to[e]]:
                dist[to[e]] = dist[v] + cost[e]; pe[to[e]] = e
                if not inq[to[e]]:
                    inq[to[e]] = True; q.append(to[e])
    if dist[T] == INF:
        break
    f = INF; v = T
    while v != S:                                    # bottleneck of the path
        f = min(f, cap[pe[v]]); v = to[pe[v] ^ 1]
    v = T
    while v != S:                                    # push f units
        cap[pe[v]] -= f; cap[pe[v] ^ 1] += f; v = to[pe[v] ^ 1]
    flow += f
    total += f * dist[T]

## Modelling with min-cost flow

| problem | network |
| --- | --- |
| **Assignment** of `n` workers to `n` jobs with costs `a[i][j]` | source to worker (cap 1, price 0), worker to job (cap 1, price `a[i][j]`), job to sink (cap 1, price 0); min cost for flow `n` |
| **Transportation**: suppliers with stock, customers with demand | source to supplier (cap = stock), supplier to customer (price per unit), customer to sink (cap = demand) |
| **Min-cost `k` edge-disjoint paths** | capacity 1 per edge, stop after exactly `k` units of flow |
| **Max-weight matching in a bipartite graph** | assignment with negated weights (or price `max - weight`) |
| **Minimum path cover / scheduling with penalties** | split vertices, prices on the connecting edges |

**Exactly `F` units instead of the maximum**: stop augmenting when the flow reaches `F` (and push only `min(f, F - flow)` in the last round).

## Pitfalls

1. **Negative prices in the input.** The residual graph then starts with negative edges, and Dijkstra needs valid potentials: compute them with one Bellman-Ford pass first. With a negative **cycle** in the input, cancel it first or the algorithm does not terminate correctly.
2. **Forgetting `cost[e ^ 1] = -cost[e]`.** Without the negated twin price there is no refund and the result is not minimal.
3. **Using `int` for the total.** `flow * price * path length` overflows 32 bits quickly; use 64-bit integers.
4. **Wrong bottleneck traversal.** The previous vertex of `v` along edge `e` is `to[e ^ 1]`, not `to[e] - 1`.
5. **SPFA worst case.** SPFA can be slow on adversarial graphs (`O(V E)` per round); switch to Dijkstra with potentials for large inputs.
6. **Infinite capacity.** Represent it with a large finite number (`10^9` or `INF / 4`) so that `cap[e ^ 1] += f` cannot overflow.
7. **Confusing "max flow, then min cost" with "min cost, any flow".** This lesson fixes the flow value at the maximum; the cheapest flow of **any** value is the empty flow when prices are non-negative.
