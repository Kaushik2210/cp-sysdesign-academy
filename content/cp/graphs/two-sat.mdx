## Intuition

You are setting `n` light switches. Each **rule** says "switch `a` is in this state **or** switch `b` is in that state": for example "lamp 3 is on, or lamp 5 is off". Is there a way to set every switch so that all rules hold?

Trying all `2^n` settings is hopeless. But every rule involves only **two** statements, and that is enough to turn the puzzle into a graph. If a rule says "`a` or `b`", then whenever `a` is false, `b` is forced to be true, and the other way round. Follow such forced consequences and you either find a consistent setting or you find a lamp that is forced to be both on and off.

## Definition

A **2-SAT** formula is a list of clauses, each of the form `(x or y)` where `x` and `y` are **literals**: a variable or its negation. We ask whether some assignment makes every clause true.

**Implication graph.** Make two vertices per variable, one for the literal being true and one for it being false. A clause `(x or y)` is the same as two implications:

```text
not x -> y        (if x is false, y must be true)
not y -> x        (if y is false, x must be true)
```

Add both edges for every clause. Note the symmetry: if there is a path `p -> q`, there is also a path `not q -> not p`.

**Theorem.** The formula is satisfiable **if and only if** no variable lies in the same strongly connected component as its negation.

- If `x` and `not x` are in one component, then `x` implies `not x` and `not x` implies `x`, which is a contradiction either way.
- Otherwise a satisfying assignment exists. Compute SCCs with Kosaraju's algorithm (components are numbered in **topological order** of the condensation), and set each variable true exactly when the component of `x` comes **later** than the component of `not x`. Choosing the later one means everything implied by a true literal is also true.

The whole algorithm is linear: `2n` vertices, `2m` edges, `O(n + m)`.

## Example, step by step

Three lamps, three rules:

```text
(1 or 2)     (not 1 or 3)     (not 2 or not 3)
```

Implications for each clause (`~x` means "x is off"):

| clause | edges |
| --- | --- |
| `1 or 2` | `~1 -> 2`, `~2 -> 1` |
| `~1 or 3` | `1 -> 3`, `~3 -> ~1` |
| `~2 or ~3` | `2 -> ~3`, `3 -> ~2` |

No lamp shares a component with its negation: lamp 1 can force `3` and then `~2`, but nothing leads back to `~1`. So the answer is `YES`. One valid setting, found by the later-component rule: lamp 1 on, lamp 2 off, lamp 3 on. Check the rules: `1 or 2` holds because 1 is on, `~1 or 3` holds because 3 is on, `~2 or ~3` holds because 2 is off. ✓.

Now the impossible case, two lamps and all four combinations forbidden:

```text
(1 or 2)   (1 or ~2)   (~1 or 2)   (~1 or ~2)
```

Edges: `~1 -> 2`, `~2 -> 1`, `~1 -> ~2`, `2 -> 1`, `1 -> 2`, `~2 -> ~1`, `1 -> ~2`, `2 -> ~1`. Follow `1 -> 2` (from the third clause) and then `2 -> ~1` (from the fourth): lamp 1 on forces lamp 1 off. And `~1 -> 2 -> 1` gives the opposite direction. So `1` and `~1` are in one component, and the answer is `NO`.

<CodeRunner language="python" code={`import random

def two_sat(n, clauses):
    N = 2 * n
    node = lambda x: 2 * (x - 1) if x > 0 else 2 * (-x - 1) + 1
    adj = [[] for _ in range(N)]
    radj = [[] for _ in range(N)]
    for a, b in clauses:
        a, b = node(a), node(b)
        for u, v in ((a ^ 1, b), (b ^ 1, a)):
            adj[u].append(v)
            radj[v].append(u)
    seen = [False] * N
    order = []

    def dfs1(v):
        seen[v] = True
        for to in adj[v]:
            if not seen[to]:
                dfs1(to)
        order.append(v)

    for s in range(N):
        if not seen[s]:
            dfs1(s)
    comp = [-1] * N

    def dfs2(v, c):
        comp[v] = c
        for to in radj[v]:
            if comp[to] == -1:
                dfs2(to, c)

    c = 0
    for s in reversed(order):
        if comp[s] == -1:
            dfs2(s, c)
            c += 1
    if any(comp[2 * i] == comp[2 * i + 1] for i in range(n)):
        return None
    return [comp[2 * i] > comp[2 * i + 1] for i in range(n)]

def brute(n, clauses):
    for mask in range(1 << n):
        val = lambda x: ((mask >> (abs(x) - 1)) & 1) == (1 if x > 0 else 0)
        if all(val(a) or val(b) for a, b in clauses):
            return True
    return False

print("lesson example:", two_sat(3, [(1, 2), (-1, 3), (-2, -3)]))
print("all four combinations forbidden:", two_sat(2, [(1, 2), (1, -2), (-1, 2), (-1, -2)]))

random.seed(3)

## Modelling with 2-SAT

The hard part in contests is **recognising** it. Signals: every item has exactly two choices (in or out, left or right, team A or B), and every restriction involves at most two items.

| restriction | clause(s) |
| --- | --- |
| `a` and `b` cannot both be on | `(~a or ~b)` |
| if `a` is on then `b` is on | `(~a or b)` |
| `a` and `b` are equal | `(~a or b)` and `(a or ~b)` |
| `a` and `b` differ | `(a or b)` and `(~a or ~b)` |
| `a` must be on | `(a or a)` |
| at most one of three | pairwise `(~a or ~b)`, `(~a or ~c)`, `(~b or ~c)` |

"At most one of `k`" costs `k^2` clauses done naively; there is a prefix-variable trick that does it in `O(k)`. A restriction on **three** variables at a time ("at least one of `a, b, c`") is 3-SAT, which is NP-hard: no known linear algorithm, so 2-SAT cannot absorb it.

## Pitfalls

1. **Adding only one implication per clause.** Both `not a -> b` and `not b -> a` are needed; with one edge the graph is not symmetric and the theorem fails.
2. **Wrong literal numbering.** With `2i` and `2i + 1`, negation is `x ^ 1`. Mixing 0-based and 1-based lamp numbers when decoding `+x` / `-x` is the usual bug.
3. **Wrong direction for the assignment.** True when the component of `x` comes **later** in topological order than the component of `not x`. If your SCC numbering is reversed (as in Tarjan's, which numbers sinks first), flip the comparison.
4. **Forced literals.** A single fact `a` is the clause `(a or a)`, giving the edge `~a -> a`.
5. **Recursion depth.** `2n` vertices can form a chain of length `2n`; use an explicit stack in Python and Java for large inputs.
6. **Using it for three-variable clauses.** That is 3-SAT; re-model or use a different technique.
