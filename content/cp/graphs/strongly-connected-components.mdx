## Intuition

In an undirected graph, "connected" is easy: if you can walk from `a` to `b`, you can walk back. With **one-way streets** that breaks. You may be able to drive from `a` to `b` and never return.

Group the squares into **districts**: two squares are in the same district when you can drive from each to the other. Inside a district you can wander anywhere and always get back. Between districts traffic only flows one way, otherwise they would merge into one. So if you shrink every district to a single dot, **no cycle can remain**: the picture becomes a directed acyclic graph, and the tools from [topological sort](/cp/graphs/topological-sort/) apply again.

## Definition

In a directed graph, vertices `u` and `v` are **strongly connected** if there is a path `u -> v` **and** a path `v -> u`. This is an equivalence relation, and its classes are the **strongly connected components** (SCCs). Contracting each SCC to one vertex gives the **condensation graph**, which is always a DAG.

**Kosaraju's algorithm** finds all SCCs with two DFS passes in `O(n + m)`:

```text
pass 1:  DFS the whole graph; append each vertex to `order` when it FINISHES.
pass 2:  build the reversed graph (flip every edge).
         for v in reversed(order):        # latest finisher first
             if v is unvisited: DFS from v in the reversed graph; everything reached is one SCC.
```

**Why it works.** The vertex that finishes last in pass 1 lies in a *source* component of the condensation DAG (nothing points into it). In the reversed graph that component has no outgoing edges to the others, so the DFS from it reaches exactly its own vertices. Remove it and repeat: the next latest finisher is in a source of what remains.

## Example, step by step

Graph with 7 vertices:

```text
1->2  2->3  3->1     (a triangle)
3->4                 (a one-way bridge out)
4->5  5->6  6->4     (another triangle)
6->7                 (a one-way tail)
```

**Pass 1** from vertex 1 (neighbours in input order): `1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7`. Vertex 7 has no outgoing edge, so it finishes first. Then 6, 5, 4, 3, 2, 1 finish in that order:

```text
order = [7, 6, 5, 4, 3, 2, 1]
```

**Pass 2** on the reversed graph, scanning `order` from the end:

| start | reaches in reversed graph | component |
| --- | --- | --- |
| 1 | reversed edges lead 1 to 3, then 3 to 2; the reversed `4->3` points away from 4 only, so nothing outside the triangle is reached | `{1, 2, 3}` |
| 2, 3 | already visited | skipped |
| 4 | reversed edges lead 4 to 6, then 6 to 5; the reversed `3->4` is `4->3`, but 3 is already visited | `{4, 5, 6}` |
| 5, 6 | already visited | skipped |
| 7 | the reversed `6->7` is `7->6`, and 6 is already visited | `{7}` |

Three components of sizes `3, 3, 1`. The condensation is the chain `{1,2,3} -> {4,5,6} -> {7}`.

## Code

The recursive form is short. The sweep order is the important part.

```python
import sys
sys.setrecursionlimit(10000)           # fine for a few thousand vertices; use an explicit stack beyond that

adj = [[] for _ in range(n + 1)]
radj = [[] for _ in range(n + 1)]
for u, v in edges:
    adj[u].append(v)
    radj[v].append(u)

seen = [False] * (n + 1)
order = []
def dfs1(v):
    seen[v] = True
    for to in adj[v]:
        if not seen[to]:
            dfs1(to)
    order.append(v)                    # appended when v FINISHES

comp = [0] * (n + 1)
def dfs2(v, c):
    comp[v] = c
    for to in radj[v]:
        if not comp[to]:
            dfs2(to, c)

for s in range(1, n + 1):
    if not seen[s]:
        dfs1(s)
c = 0
for s in reversed(order):
    if not comp[s]:
        c += 1
        dfs2(s, c)                     # comp[v] in 1..c, numbered in topological order of the condensation
```

Labels come out in **topological order of the condensation**: an edge between two components always goes from a smaller label to a larger one. That is exactly what you need to run a DP over the DAG afterwards.

## What SCCs give you

- **Condensation DP.** Contract each component, then count paths, longest paths or reachable sets on the DAG in topological order. Typical statements: "maximum coins collected on a route that may revisit squares", "minimum number of edges to add so everything is reachable".
- **Source and sink components.** The condensation's source components (in-degree 0) are the places you must start from to reach everything.
- **2-SAT.** Each variable and its negation become vertices, each clause adds two implication edges, and the formula is satisfiable exactly when no variable shares an SCC with its negation.
- **Tarjan's algorithm** finds the same components in one DFS using `tin` and `low`, like the [bridges lesson](/cp/graphs/bridges/). Kosaraju is easier to remember; Tarjan needs no reversed graph.

## Pitfalls

1. **Using the wrong order in pass 2.** You must sweep from the **latest** finisher. Scanning `order` from the front merges components.
2. **Forgetting to reverse the graph** (or reversing it in pass 1). One pass is on the original edges, the other on the reversed ones.
3. **Appending on discovery instead of finish.** The list must be post-order, appended after the neighbour loop.
4. **Treating it like undirected connectivity.** Union-find does not work on directed edges.
5. **Recursion depth.** A chain of `2·10^5` vertices overflows the stack in Python and Java; use an explicit stack or run in a thread with a big stack. The practice problem's reference solution does the first pass iteratively.
6. **Vertex numbering.** Mixing 0-based and 1-based indexes when you size `comp` and `seen` is the classic off-by-one here.
