## Intuition

In an undirected graph, "connected" is simple: two vertices are connected or not. In a **directed** graph, there are two different questions: can you get from `a` to `b`, and can you also get back? If each can reach the other, `a` and `b` are in the same **strongly connected component** (SCC): think of a group of cities where you can drive from any city to any other, following one-way roads.

Why care? Because the components are the *real* nodes of the graph. If you squeeze every component into a single vertex, the leftover graph has **no cycles at all**: a DAG. Almost every hard directed-graph problem (dependency loops, reachability, 2-SAT, "can everything be reached") becomes easy once you work on that DAG instead of the messy original.

## Definition

- Vertices `u` and `v` are **strongly connected** if there is a path `u -> v` **and** a path `v -> u`.
- This is an equivalence relation, so the vertices split into disjoint **strongly connected components**.
- The **condensation** (component graph) has one vertex per SCC and an edge `A -> B` when some original edge goes from a vertex in `A` to a vertex in `B`. It is always a **DAG**: a cycle among components would merge them into one.
- In the condensation a **source** component has no incoming edge and a **sink** component has no outgoing edge.

## Tarjan's algorithm (one DFS)

Run a DFS and keep a stack of vertices that are "still open". For each vertex store:

- `tin[u]`: discovery time (the order the DFS first reached it).
- `low[u]`: the smallest `tin` reachable from `u`'s DFS subtree using tree edges plus **at most one** edge to a vertex that is still **on the stack**.

Processing an edge `u -> v`:

```text
if v not visited:   dfs(v);  low[u] = min(low[u], low[v])
else if v on stack: low[u] = min(low[u], tin[v])       # back edge into an open component
else:               ignore                              # v already belongs to a finished component
```

After all edges of `u` are processed, if `low[u] == tin[u]` then no vertex in `u`'s subtree can reach anything discovered earlier that is still open: `u` is the **root** of an SCC. Pop the stack down to `u`; those vertices are exactly that component.

Everything runs in `O(n + m)`. The components come out in a useful order: Tarjan finishes a component only after every component reachable from it, so **component ids are a reverse topological order of the condensation** (id `0` is a sink).

## Kosaraju's algorithm (two DFS passes)

1. Run DFS on the graph and record vertices in order of **finishing time**.
2. Build the **reverse graph** (every edge flipped).
3. Process vertices in **decreasing finishing time**; each DFS in the reverse graph that starts at an unassigned vertex collects exactly one SCC.

Same complexity, easier to prove, but needs the reverse graph. Tarjan uses one pass and no extra graph; many people use it for speed and memory.

## Example, step by step

Graph: `0 -> 1 -> 2 -> 0`, `2 -> 3`, `3 -> 4 -> 5 -> 3`.

- DFS from 0: `tin` = 0, then 1 (tin 1), then 2 (tin 2). Edge `2 -> 0`: 0 is on the stack, so `low[2] = tin[0] = 0`. Edge `2 -> 3`: visit 3 (tin 3), then 4 (tin 4), 5 (tin 5). Edge `5 -> 3` goes back to 3, which is on the stack: `low[5] = 3`, so `low[4] = 3`.
- Back at 3: `low[3] = 3 = tin[3]`, so 3 is a root. Pop 5, 4, 3: component `{3, 4, 5}`.
- Back at 2: `low[2] = 0`, it is not a root. Back at 1: `low[1] = 0`. Back at 0: `low[0] = 0 = tin[0]`: pop 2, 1, 0: component `{0, 1, 2}`.
- The edge `2 -> 3` joins the two components, so the condensation is `{0,1,2} -> {3,4,5}`: one source, one sink.

## What SCCs are used for

- **Make a digraph strongly connected** with the fewest new edges: after condensing, the answer is `max(sources, sinks)` (or `0` if there is only one component). This is the practice problem.
- **Reachability and "can everyone reach X?"**: work on the condensation DAG with DP in topological order, for example counting reachable vertices or finding the maximum collectable weight along a path of components.
- **2-SAT**: each variable `x` becomes two vertices `x` and `not x`. A clause `(a or b)` adds the implications `not a -> b` and `not b -> a`. The formula is unsatisfiable exactly when some `x` and `not x` land in the same SCC. Otherwise set `x` true when its component comes **later** in topological order, which with Tarjan means a **smaller** component id.
- **Dependency cycles**: detect circular dependencies and list which items are tangled together.
- **Reducing a graph before DP**: DP on a general digraph is ill-defined with cycles, but DP on the condensation is fine.

## Pitfalls

1. **Updating `low` from a vertex that is no longer on the stack.** An edge to a vertex of a finished component must be ignored. Without the `on_stack` test, separate components merge.
2. **Using `low[v]` instead of `tin[v]` for a back edge.** Both happen to work for SCC but `tin[v]` is the standard and is required for the related bridge and articulation algorithms.
3. **Forgetting to start a DFS from every unvisited vertex.** One call only covers what is reachable from one start.
4. **Recursion depth.** A chain of `10^5` vertices overflows a default stack. Raise the limit, run in a big-stack thread, or write the DFS iteratively.
5. **Assuming component ids are in topological order.** Tarjan gives **reverse** topological order; Kosaraju as written above gives forward topological order. Check which you have before using it.
6. **Counting a component with no edges as "not a source or sink".** An isolated vertex is both a source and a sink, so it counts on both sides in `max(sources, sinks)`.
7. **Ignoring duplicate edges and self-loops.** They are harmless for SCC but can inflate degree counts if you count edges between components rather than testing presence.
8. **Confusing SCC with connected components** of the undirected version: those ignore edge direction and give a different answer.
