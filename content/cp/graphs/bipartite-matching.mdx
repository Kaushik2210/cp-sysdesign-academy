## Intuition

Leaders on one side, followers on the other. Some pairs would like to dance together. Everyone dances with at most one partner. How many couples can dance at once? This is **maximum bipartite matching**, and the same shape appears everywhere: jobs to workers, students to projects, tasks to machines, rooks on a board with forbidden squares.

You already know a tool that solves it: [maximum flow](/cp/graphs/maximum-flow/). Put a source in front of the leaders, a sink behind the followers, give every edge capacity 1, and the max flow is the matching size. Matching deserves its own lesson because a much simpler algorithm works directly on the graph, and because three classical theorems (Berge, König, Hall) turn matching into a source of other answers.

## Definitions

A **matching** is a set of edges, no two sharing a vertex. A vertex in the matching is *matched*, otherwise *free*. A **maximum** matching has the most edges possible.

An **alternating path** alternates between edges *not* in the matching and edges *in* it. An **augmenting path** is an alternating path that starts at a free vertex on the left and ends at a free vertex on the right. Flipping it (swap which edges are in the matching) adds exactly **one** edge to the matching:

```text
before:  L1   L2 = R1   R2              (= is a matched edge)
path:    L1 - R1 = L2 - R2
after:   L1 = R1   L2 = R2              matching grew from 1 edge to 2
```

**Berge's theorem.** A matching is maximum **if and only if** it has no augmenting path. So the algorithm is: keep finding augmenting paths and flipping them until none exists.

## Kuhn's algorithm

For each leader `u`, in turn, try to find an augmenting path starting at `u` using a DFS:

```text
try_augment(u):
    for each follower v adjacent to u:
        if v was already visited in this search: skip
        mark v visited
        if v is free  OR  try_augment(partner[v]):     # v's partner can be re-matched elsewhere
            partner[v] = u
            return true
    return false
```

The recursion `try_augment(partner[v])` asks: "if I take `v`, can its current partner find a different follower?" A chain of such re-matchings *is* the augmenting path. The `visited` array is reset **per leader**, which bounds one search by `O(e)` edges. With `n` leaders the total is `O(n · e)`, fast enough for graphs with a few thousand vertices. For `10^5` vertices use **Hopcroft-Karp** (below).

## Example: why greedy fails

```text
leaders:    A     B
followers:  1     2
edges:      A-1, A-2, B-1
```

Greedy gives `A` the first follower `1`. Now `B` has only `1`, which is taken: matching of size 1. Kuhn processes `B` as follows: `B` tries `1`, whose partner is `A`; `A` tries `1` (visited) then `2` (free), so `A` moves to `2` and `B` takes `1`. Matching of size 2.

import sys
sys.setrecursionlimit(10000)

def max_matching(n, m, edges):                    # leaders 1..n, followers 1..m, edges (u, v)
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
    match = [0] * (m + 1)                         # match[v] = leader paired with follower v (0 = free)

    def try_augment(u, seen):
        for v in adj[u]:
            if not seen[v]:
                seen[v] = True
                if match[v] == 0 or try_augment(match[v], seen):
                    match[v] = u
                    return True
        return False

    return sum(1 for u in range(1, n + 1) if try_augment(u, [False] * (m + 1))), match

## Three theorems worth knowing

| theorem | statement | what it gives you |
| --- | --- | --- |
| **Berge** | a matching is maximum iff it has no augmenting path | the correctness of Kuhn's algorithm |
| **König** | in a bipartite graph, maximum matching = minimum **vertex cover** (fewest vertices touching every edge) | the minimum cover and the maximum **independent set** (`n + m −` matching) for free |
| **Hall** | the left side can be fully matched iff every set `S` of leaders has at least `|S|` neighbouring followers | a fast yes/no test, and a proof tool |

From **König's construction** (shown in the demo): after a maximum matching, take every vertex reachable from a free leader by alternating paths. The leaders **not** reached plus the followers reached form a minimum vertex cover.

## Faster: Hopcroft-Karp

Kuhn's algorithm finds one augmenting path per leader. **Hopcroft-Karp** finds a *maximal set* of shortest augmenting paths per phase: a BFS builds layers from the free leaders, then a DFS (like Dinic's blocking flow) collects vertex-disjoint augmenting paths along the layers. There are `O(√V)` phases, so it runs in `O(E √V)`. It is exactly Dinic's algorithm specialised to unit-capacity bipartite networks. A few extra tricks make plain Kuhn faster in practice:

- **Greedy initialisation:** pair each leader with any free neighbour first, then run Kuhn only for the rest.
- **Don't reset `seen`** between leaders when the previous search failed (a failed search proves those followers are dead ends).
- **Random shuffle** of adjacency lists to dodge adversarial orders.

## What matching can model

| problem | modelling |
| --- | --- |
| assign jobs to workers (each can do some) | leaders = workers, followers = jobs, edge = "can do" |
| **minimum path cover** of a DAG | split every vertex into out/in copies; `paths = vertices − matching` |
| place the most **non-attacking rooks** on a board with holes | rows vs columns, edge for every allowed square |
| maximum **independent set** in a bipartite graph | `n + m −` maximum matching (König) |
| **domino tiling** of a board with removed cells | colour the board like a chessboard; cells of one colour vs the other; a perfect matching is a tiling |
| minimum number of **lines** covering all marked cells of a grid | minimum vertex cover of the rows-versus-columns graph, equal to the maximum matching |

## Pitfalls

1. **Not resetting `seen` per leader.** The visited array must be fresh for each new search (except for the optimisation above, which is only valid for failed searches).
2. **Mixing the sides.** `match[v]` is indexed by *followers* and stores a *leader*; keep the two index ranges separate, or offset the followers.
3. **Counting duplicates.** Repeated pairs are harmless in Kuhn's algorithm, but make sure input duplicates do not inflate degrees in a degree-based check.
4. **Recursion depth.** The DFS depth can reach the matching size; raise Python's recursion limit or use an explicit stack for graphs beyond a few thousand vertices.
5. **Confusing matching with vertex cover.** They are equal in size only for **bipartite** graphs; for general graphs a different algorithm (Edmonds' blossom) is needed.
6. **Too slow on huge graphs.** `O(n · e)` is fine for thousands of vertices; for `10^5` use Hopcroft-Karp or Dinic.
7. **Assuming a perfect matching.** Check the size against `n` (and `m`); unmatched vertices are normal.
