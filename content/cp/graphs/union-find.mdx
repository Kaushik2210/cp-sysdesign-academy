## Intuition

You are merging groups of friends and, at any moment, asking "are these two in the same group?". Keeping a list of members per group makes the question easy but merging slow, because you must copy a whole list.

Instead give every group **one representative**, its root. Everyone remembers only *who they point to*, and following the pointers leads to the root. Two people are together exactly when their roots are the same. Merging two groups is a single pointer change: make one root point at the other.

## Definition

The structure is a forest stored in one array `parent`, with `parent[x] == x` for a root.

- `find(x)`: follow `parent` until you reach a root.
- `union(a, b)`: find both roots; if they differ, make one the parent of the other.

Two tricks make it nearly constant time.

| trick | what it does |
| --- | --- |
| **Path compression** | after `find`, point every node on the walked path straight at the root |
| **Union by size** | hang the smaller tree under the larger root, so trees stay shallow |

With both, the amortized cost per operation is `O(alpha(n))`, where `alpha` is the inverse Ackermann function and is at most 4 for any input that fits in the universe. With only one of them it is `O(log n)`, still fine for most problems.

## Code

<Tabs>
<Tab label="Python">

```python
parent = list(range(n))
size = [1] * n

def find(x):
    root = x
    while parent[root] != root:
        root = parent[root]
    while parent[x] != root:        # compress the path
        parent[x], x = root, parent[x]
    return root

def union(a, b):
    a, b = find(a), find(b)
    if a == b:
        return False                # already together
    if size[a] < size[b]:
        a, b = b, a
    parent[b] = a                   # smaller under larger
    size[a] += size[b]
    return True
```

## What it is used for

1. **Dynamic connectivity** when edges only get *added*: answer "are u and v connected?" online.
2. **Kruskal's minimum spanning tree**: sort edges by weight, add an edge if `union` returns `True`. Total `O(E log E)`.
3. **Cycle detection in an undirected graph**: an edge whose endpoints already share a root closes a cycle.
4. **Counting components**: start with `n` and subtract one per successful union.
5. **Grouping equivalences**: accounts that share an email, variables forced equal by constraints.

<Callout type="note" title="Deletions are not supported">
Union-find cannot undo a merge cheaply. If edges are also removed, process the queries **offline in reverse** (turning removals into additions) or use an offline divide-and-conquer with rollback (union by size without path compression).
</Callout>

## Pitfalls

1. **Recursive `find` on a long chain.** The first merges can build a path of length `n`. In Python, recursion overflows at about 1000 frames; write `find` iteratively.
2. **Merging without finding roots.** `parent[a] = b` on non-roots cuts a node off from its group and breaks other members' paths.
3. **Comparing `parent[a] == parent[b]`** instead of `find(a) == find(b)`. Only roots are comparable; `parent` is the immediate pointer, which may be stale.
4. **Union by size using `size[a]` of a non-root.** Read sizes only at roots.
5. **Off-by-one in indexing.** Decide on 0-based or 1-based nodes first, and allocate `n + 1` if 1-based.
6. **Using it when you need paths.** Union-find answers "same group?", not "what is the route?". Use BFS or Dijkstra for routes.
