## Intuition

Water enters a network of pipes at one junction and must leave at another. Each pipe has a **capacity**: the most it can carry per second. What is the largest amount per second that can get through?

A natural idea: find a path from source to sink, push as much as the narrowest pipe on it allows, repeat. This fails: an early choice can block a better combination. The fix is a small idea with big consequences: let the algorithm **take back** water it already sent. Pushing flow along a pipe also creates a **reverse pipe** carrying the same amount, and sending flow down the reverse pipe means "cancel what we sent".

## Definition

A **flow network** has directed edges with capacities `c(u, v) >= 0`, a source `s` and a sink `t`. A **flow** `f` assigns each edge a value `0 <= f(e) <= c(e)` so that at every vertex other than `s` and `t`, inflow equals outflow. Its **value** is the net amount leaving `s`.

**Residual graph.** For every edge `e = (u, v)` keep a twin edge `(v, u)` with capacity `0`. Define `residual(e) = capacity(e) - flow(e)`. Sending `d` along `e` does

```text
cap[e]     -= d        # less room forward
cap[e ^ 1] += d        # more room to cancel it later
```

(store each edge and its twin at indices `2k` and `2k + 1`, so the twin of `e` is `e ^ 1`).

**Augmenting path.** A path from `s` to `t` along edges with positive residual capacity. Pushing its bottleneck increases the flow.

**Max-flow min-cut theorem.** The flow is maximum **exactly when** the residual graph has no augmenting path. At that moment, the set of vertices reachable from `s` forms a **minimum cut**, and its capacity equals the flow value. So max flow also solves "cheapest set of edges to remove to disconnect `s` from `t`".

## From Ford-Fulkerson to Dinic

| algorithm | how it picks paths | worst-case time |
| --- | --- | --- |
| Ford-Fulkerson with DFS | any path | `O(E * maxflow)`, can be terrible with large capacities |
| Edmonds-Karp | shortest path by BFS | `O(V E^2)` |
| **Dinic** | all shortest paths per phase | `O(V^2 E)`; `O(E sqrt(V))` for unit capacities |

**Dinic's algorithm** runs in **phases**:

1. **BFS** from `s` over edges with positive residual capacity, giving each vertex a `level` (distance from `s`).
2. **DFS** from `s` that only follows edges `u -> v` with `level[v] == level[u] + 1` and residual `> 0`. This is the *blocking flow* search. A per-vertex pointer `it[v]` remembers which edge to try next, so an edge that led nowhere is never tried twice in the same phase.
3. When the DFS can push no more, start a new phase. When BFS cannot reach `t`, stop.

The shortest-path distance to `t` strictly increases every phase, so there are at most `V` phases.

## Example, step by step

Five pipes, each of capacity 1: `1->2`, `1->3`, `2->3`, `2->4`, `3->4`, source 1, sink 4.

The greedy first path `1 -> 2 -> 3 -> 4` pushes 1 unit. Now `1->2`, `2->3` and `3->4` are full, and the residual twins `2->1`, `3->2`, `4->3` each have capacity 1.

Is there an augmenting path left? Yes: `1 -> 3` (capacity 1), then `3 -> 2` along the **twin** of `2->3` (this cancels the earlier flow through `2->3`), then `2 -> 4` (capacity 1). Pushing 1 unit gives total flow **2**:

```text
final flow:   1->2->4  and  1->3->4
```

A purely greedy method without reverse edges would have stopped at 1. Dinic avoids the trap in a second way too: its BFS levels are `1:0, 2:1, 3:1, 4:2`, and it only follows edges that go exactly one level deeper. The edge `2->3` stays on the same level, so it is never used in phase 1. Phase 1 sends 1 unit along `1-2-4` and 1 unit along `1-3-4`, total 2, and phase 2's BFS can no longer reach vertex 4.

## What flow can model

Max flow is a **modelling** tool: many problems that do not mention water are flow problems in disguise.

| problem | graph |
| --- | --- |
| **Bipartite matching** | source to each left vertex (cap 1), left to right along allowed pairs (cap 1), each right vertex to sink (cap 1). Max flow = maximum matching. |
| **Edge-disjoint paths** | every edge capacity 1; max flow = number of edge-disjoint paths from `s` to `t`. |
| **Vertex-disjoint paths** | split every vertex `v` into `v_in -> v_out` with capacity 1. |
| **Minimum cut** | after max flow, the vertices reachable from `s` in the residual graph form the source side. |
| **Assignment with capacities** | people to jobs with limits on both sides, as in matching but with capacities above 1. |
| **Project selection** | profits and dependencies as a min cut (advanced). |

## Pitfalls

1. **Forgetting the reverse edges.** Without twins with capacity 0 the algorithm is just greedy path packing and gives wrong answers on cross-linked networks.
2. **Updating the twin in the wrong direction.** `cap[e] -= d` and `cap[e ^ 1] += d`. Reversing the signs inflates the flow forever.
3. **Parallel and antiparallel edges.** Both are fine in the edge-list representation; a capacity matrix must **add** capacities instead of overwriting them.
4. **Not resetting `it[]` per phase.** The pointer array must be zeroed before every phase.
5. **Overflow.** Flow values can reach `m * 10^9`: use 64-bit integers, and start the DFS with an infinity that fits (`LLONG_MAX`).
6. **Recursion depth.** The DFS depth is at most the longest level path, up to `V`. For `V` around `10^5` use an iterative DFS or a big thread stack.
7. **Using DFS-only Ford-Fulkerson with big capacities.** Its running time depends on the flow value, so a single unlucky path choice can cost billions of steps.
