## Intuition

A network of pipes, each with a capacity, carries water from a source `s` to a sink `t`. How much can reach `t` per second?

The obvious method is greedy: find any path with spare capacity, push as much as fits, repeat. It fails. The first path you pick may use a pipe that a better overall plan needed for something else, and now that pipe is full.

The fix is one clever idea: allow **undoing**. After pushing water along `u → v`, record that you could *send it back* along `v → u`. A later path is allowed to use that "reverse pipe", which cancels part of the earlier decision. With undo available, greedy becomes correct: when no path with spare capacity remains, you are done, and you have the maximum.

## Definition

A **flow** assigns each edge `e` an amount `f(e)` with `0 ≤ f(e) ≤ cap(e)`, such that at every vertex other than `s` and `t` the flow in equals the flow out. Its **value** is the net amount leaving `s`. The **maximum flow** problem asks for the largest value.

The **residual graph** records what is still possible. Each edge `e` with capacity `c` is stored together with a **twin** edge in the opposite direction with capacity `0`:

```text
send d along e:   cap[e] -= d      (less room forward)
                  cap[e ^ 1] += d  (the twin can now carry d back, i.e. undo)
```

Storing the edges in pairs at indices `2i` and `2i + 1` makes the twin of `e` simply `e ^ 1`.

An **augmenting path** is a path from `s` to `t` using only edges with positive residual capacity. Pushing the bottleneck amount along it increases the flow. When no augmenting path exists the flow is maximum.

## Max-flow min-cut

A **cut** is a set `S` containing `s` but not `t`; its capacity is the total capacity of the edges leaving `S`. Any flow must cross every cut, so `value ≤ capacity of any cut`. The theorem says the bound is tight:

```text
maximum flow  =  minimum cut capacity
```

When the algorithm stops, let `S` be the vertices still reachable from `s` in the residual graph. Every edge leaving `S` is saturated, so the cut `S` has capacity exactly equal to the flow. That gives you the **minimum cut for free**: the saturated edges leaving the reachable set.

## Algorithms

| algorithm | idea | time |
| --- | --- | --- |
| Ford-Fulkerson | any augmenting path (DFS) | `O(E · F)`, depends on the flow value `F`; can be awful |
| Edmonds-Karp | shortest augmenting path by BFS | `O(V · E²)` |
| **Dinic** | BFS levels, then a *blocking flow* with DFS | `O(V² · E)`; very fast in practice |

**Dinic's algorithm** works in phases:

1. **BFS** from `s` in the residual graph to give every vertex a `level` (its distance).
2. **DFS** from `s`, following only edges that go from level `L` to level `L + 1` and have spare capacity. A pointer `it[v]` remembers which edge of `v` to try next, so a dead end is never explored twice. Repeat until the DFS finds nothing: that is a *blocking flow*.
3. Repeat from step 1. The distance from `s` to `t` strictly increases each phase, so there are at most `V` phases.

from collections import deque

def max_flow(n, edges, s, t):                 # edges: (u, v, capacity), vertices 1..n
    to, cap = [], []
    adj = [[] for _ in range(n + 1)]
    for u, v, c in edges:
        adj[u].append(len(to)); to.append(v); cap.append(c)     # edge 2i
        adj[v].append(len(to)); to.append(u); cap.append(0)     # twin 2i + 1
    flow = 0
    while True:
        level = [-1] * (n + 1); level[s] = 0
        q = deque([s])
        while q:                                                # BFS levels
            v = q.popleft()
            for e in adj[v]:
                if cap[e] > 0 and level[to[e]] < 0:
                    level[to[e]] = level[v] + 1
                    q.append(to[e])
        if level[t] < 0:
            return flow                                         # t unreachable: done
        it = [0] * (n + 1)
        def dfs(v, f):                                          # blocking flow
            if v == t: return f
            while it[v] < len(adj[v]):
                e = adj[v][it[v]]
                if cap[e] > 0 and level[to[e]] == level[v] + 1:
                    d = dfs(to[e], min(f, cap[e]))
                    if d > 0:
                        cap[e] -= d; cap[e ^ 1] += d
                        return d
                it[v] += 1
            return 0
        while True:
            f = dfs(s, 10 ** 18)
            if f == 0: break
            flow += f

long long dfs(int v, long long f) {
    if (v == t) return f;
    for (; it_[v] < (int)adj[v].size(); it_[v]++) {

## What flow can model

Maximum flow is a general-purpose tool: model your problem as a network and read the answer off the flow.

| problem | network |
| --- | --- |
| **Bipartite matching** | source → each left vertex (cap 1), left → right for allowed pairs (cap 1), each right vertex → sink (cap 1). The flow value is the matching size. |
| **Edge-disjoint paths** | give every edge capacity 1; the max flow is the number of paths. |
| **Vertex-disjoint paths** | split each vertex `v` into `v_in → v_out` with capacity 1. |
| **Minimum cut / "which roads to close"** | run the flow, then take the edges from the residual-reachable set to the rest. |
| **Project selection** (profit minus dependencies) | source → profitable projects, costly projects → sink, dependency edges with infinite capacity; answer = total profit − min cut. |
| **Assignment with capacities** (workers, shifts, seats) | source → workers, workers → tasks, tasks → sink, with the capacities as limits. |

## Pitfalls

1. **Forgetting the twin edge.** Without the zero-capacity reverse edge you get the greedy trap and wrong answers. Always add both.
2. **Undirected edges.** Give both directions the full capacity (`u → v` and `v → u`, each with its own twin), or model one edge pair with capacity `c` on both.
3. **Overflow.** The total can reach `m · max capacity`; use 64-bit integers, and a large `INF` such as `10^18` (not `INT_MAX`) as the initial push.
4. **Re-running BFS inside the DFS.** The per-vertex pointer `it[v]` is what makes a phase fast; resetting it mid-phase makes Dinic slow.
5. **Treating the answer as a path count when capacities are not 1.** Max flow is a total amount; for path counting, set capacities to 1.
6. **Recursion depth.** The DFS depth is bounded by the number of levels (at most `V`), fine for hundreds of vertices; for very large graphs use an iterative DFS.
7. **Parallel edges and self-loops.** Parallel edges are fine (they just add). A self-loop never helps and can be skipped.
