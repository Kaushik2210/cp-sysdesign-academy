## Intuition

You must connect `n` towns with cables, and every possible cable has a price. You want everyone connected at the lowest total price. Two facts shape the answer:

- If a set of cables connects everything and still contains a loop, you can remove one cable of the loop and stay connected, saving money. So an optimal network has **no loops**: it is a tree with exactly `n - 1` cables.
- Among all such trees you want the cheapest one: the **minimum spanning tree** (MST).

A greedy idea works: look at the cheapest cable. If it joins two towns that are not connected yet, there is no reason to skip it.

## Definition

A **spanning tree** of a connected undirected graph is a subset of `n - 1` edges that connects all vertices without a cycle. An MST is one with the smallest total weight.

**Kruskal's algorithm**

1. Sort the edges by weight, cheapest first.
2. Go through them. If an edge joins two **different** components (checked with [union-find](/cp/graphs/union-find/)), take it and merge the components. Otherwise skip it, because it would close a cycle.
3. Stop when `n - 1` edges are taken. If the scan ends with fewer, the graph is not connected.

Time `O(m log m)`, dominated by sorting; the union-find operations are almost constant.

## Why greedy is correct: the cut property

For any way of splitting the vertices into two non-empty groups, the cheapest edge **crossing** the split belongs to some MST.

Why: take an MST that does not contain this edge `e`. Adding `e` creates a cycle, and that cycle crosses the split at least twice, so it contains another crossing edge `f` with `w(f) >= w(e)`. Swap `f` for `e`: still a spanning tree, with weight no larger.

Kruskal applies this repeatedly. When it considers an edge that joins components `A` and `B`, every cheaper edge has already been decided, so this edge is the cheapest one crossing the split "`A` versus everything else".

```python
def kruskal(n, edges):                 # edges: (w, a, b), vertices 1..n
    edges.sort()
    parent = list(range(n + 1))

    def find(x):
        root = x
        while parent[root] != root:
            root = parent[root]
        while parent[x] != root:
            parent[x], x = root, parent[x]
        return root

    total = used = 0
    for w, a, b in edges:
        ra, rb = find(a), find(b)
        if ra != rb:
            parent[ra] = rb
            total += w
            used += 1
    return total if used == n - 1 else None   # None: not connected
```

def prim(n, edges):
    adj = [[] for _ in range(n + 1)]
    for w, a, b in edges:
        adj[a].append((w, b))
        adj[b].append((w, a))
    seen = [False] * (n + 1)

    total = cnt = 0

## Kruskal or Prim

| | Kruskal | Prim |
| --- | --- | --- |
| idea | grow a forest, add the cheapest safe edge | grow one tree, add the cheapest edge leaving it |
| structure | sort + union-find | heap (like [Dijkstra](/cp/graphs/dijkstra-shortest-paths/)) |
| time | `O(m log m)` | `O((n + m) log n)` |
| good for | sparse graphs, edge lists, disconnected input | dense graphs (`O(n^2)` array version) |

Both give a tree of the same total weight (the tree itself may differ when weights tie).

## What else an MST gives you

1. **Bottleneck paths.** In an MST, the path between two vertices minimises the largest edge on it.
2. **Clustering.** Remove the `k - 1` heaviest MST edges to get `k` groups with the largest gaps between them.
3. **Second-best MST, MST with a forced edge:** small variations that start from the MST and swap one edge.

## Pitfalls

1. **Forgetting disconnected graphs.** Count the edges taken; fewer than `n - 1` means no spanning tree.
2. **Treating a directed graph as undirected, or the reverse.** An MST is for undirected graphs. Minimum-cost arborescences are a different, harder problem.
3. **Sorting by the wrong key.** Sort by weight first; in Python keep the tuple as `(w, a, b)`.
4. **Skipping the cycle check.** Without union-find you would add every edge.
5. **Overflow.** Totals up to `n * maxW` need 64-bit integers.
6. **Assuming a unique MST.** Ties allow several; if the answer must be unique (for example the lexicographically smallest edge set), break ties explicitly.
