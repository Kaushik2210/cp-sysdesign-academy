## Intuition

A communication network has a **single point of failure** if cutting one cable, or losing one server, splits it in two. Finding those weak points is the reliability question behind road networks, computer networks and power grids. In graph words:

- A **bridge** is an edge whose removal increases the number of connected components.
- An **articulation point** (cut vertex) is a vertex whose removal, together with its edges, increases the number of components.

Testing each edge by deleting it and recounting components costs `O(m * (n + m))`. A single DFS finds all of them in `O(n + m)`, using the same low-link idea as [strongly connected components](/cp/graphs/strongly-connected-components/).

## Definition

Run a DFS. It classifies every edge as a **tree edge** (used to discover a new vertex) or a **back edge** (to an already-visited vertex). In an undirected graph, all non-tree edges join a vertex to one of its **ancestors** or descendants, so there are no cross edges.

For every vertex `u`:

- `tin[u]`: discovery time.
- `low[u]`: the smallest `tin` reachable from the subtree of `u` using tree edges and **at most one back edge**.

```text
low[u] = min( tin[u],
              tin[w] for every back edge (v, w) with v in the subtree of u,
              low[c] for every DFS child c of u )
```

**Bridge rule.** A tree edge `(u, v)` with `v` a child of `u` is a bridge if and only if

```text
low[v] > tin[u]
```

Nothing in `v`'s subtree can climb back to `u` or above, so the edge is the only connection.

**Articulation rule.** A vertex `u` is an articulation point if and only if

- `u` is **not** the DFS root and has a child `v` with `low[v] >= tin[u]` (the subtree of `v` cannot escape strictly above `u`, so removing `u` cuts it off), or
- `u` **is** the DFS root and has **two or more** DFS children (the children's subtrees are not connected to each other except through the root).

The difference between `>` for bridges and `>=` for articulation points is the thing to remember: a back edge to `u` itself saves the **edge** `(u, v)` from being a bridge but does not save the **vertex** `u`.

## Example, step by step

Graph: a triangle `0-1-2`, a path from `2` to `3`, and a triangle `3-4-5`, then one more edge `5-6`.

- DFS from 0: `tin[0]=0`, go to 1 (`tin=1`), 2 (`tin=2`). The edge `2-0` is a back edge: `low[2] = 0`, so `low[1] = 0`.
- From 2 go to 3 (`tin=3`), then 4 (`tin=4`), then 5 (`tin=5`). The edge `5-3` is a back edge: `low[5] = 3`, so `low[4] = 3`. Then 5 goes to 6 (`tin=6`, no back edges: `low[6] = 6`).
- Edge `5-6`: `low[6] = 6 > tin[5] = 5`: **bridge**. Edge `2-3`: `low[3] = 3 > tin[2] = 2`: **bridge**.
- Articulation points: `2` (child `3` has `low = 3 >= tin[2] = 2`), `3` (child `4` has `low[4] = 3 >= tin[3] = 3`), `5` (child `6` has `low = 6 >= 5`). Vertex `0` is the root with a single child, so not an articulation point; `1` and `4` are not either.

The edge `3-4`, in contrast, is **not** a bridge: `low[4] = 3` is not greater than `tin[3] = 3`, because the cycle through `5-3` returns to 3. But `3` is still an articulation point.

## What you can do with them

- **2-edge-connected components.** Delete all bridges: each remaining connected piece is a 2-edge-connected component (it survives the loss of any one edge). Contract each piece to a vertex and the bridges form a **tree**, the **bridge tree**. Many problems ("how many roads to add so the network survives any single failure?", "longest path between two cities using bridges") reduce to tree problems on it. The number of leaves `L` of the bridge tree gives the answer `ceil(L / 2)` to "fewest edges to add so there are no bridges".
- **Biconnected components (blocks).** Maximal pieces with no articulation point. Contract them with the articulation points into the **block-cut tree**.
- **Orienting edges.** An undirected connected graph can be oriented to become strongly connected exactly when it has **no bridge** (Robbins' theorem). Orient tree edges downward and back edges upward in the DFS.
- **Reliability checks.** "Is the network still connected after any single failure?" is "no bridges and no articulation points".

## Pitfalls

1. **Skipping the parent by vertex** instead of by edge id. With two parallel cables between `u` and its parent, the second one is a back edge that makes the first not a bridge. The demo shows the wrong answer.
2. **Using `>=` for bridges or `>` for articulation points.** Bridges need `low[v] > tin[u]`; articulation points need `low[v] >= tin[u]`.
3. **Forgetting the root rule.** For the DFS root the condition `low[v] >= tin[root]` is always true, so counting it would mark every root. Count children instead.
4. **Marking an articulation point more than once** and then counting duplicates. Use a boolean array or a set.
5. **Not running the DFS from every unvisited vertex** for disconnected graphs.
6. **Recursion depth** on long paths. Use an iterative DFS or a larger stack for graphs with 10^5 or more vertices.
7. **Mixing directed and undirected logic.** For directed graphs the analogue is strongly connected components, not bridges.
8. **Updating `low[u]` with `low[v]` through a back edge** instead of `tin[v]`. The standard uses `tin[v]` for back edges (it matters for the block decomposition, even if bridges survive either).
