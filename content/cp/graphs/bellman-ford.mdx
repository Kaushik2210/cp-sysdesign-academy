## Intuition

[Dijkstra](/cp/graphs/dijkstra-shortest-paths/) is fast but breaks when an edge can be negative: a node that looked finished may still be improved by a path that goes through a negative edge later. Negative weights are real (profit on a trade, a discount, a refund), so we need a method that does not rely on "finished" nodes.

The idea is blunt: **relax every edge, over and over**. A shortest path without a loop has at most `n - 1` edges, and each full pass fixes at least one more edge of every shortest path, so `n - 1` passes are enough.

## Definition

Keep `dist[v]` (infinity, except `dist[source] = 0`). One **round** relaxes every edge `a -> b` of weight `w`:

```text
if dist[a] is finite and dist[a] + w < dist[b]:  dist[b] = dist[a] + w
```

Do up to `n` rounds. If a round changes nothing, stop. The cost is `O(n * m)`.

### Detecting a negative cycle

A **negative cycle** is a loop whose weights sum to a negative number; going around it makes any path through it arbitrarily short, so shortest distances to everything it can reach are undefined.

- Without such a cycle, everything is settled after round `n - 1`, so round `n` changes nothing.
- If round `n` still improves some `dist`, a negative cycle is **reachable from the source**.

Cycles that cannot be reached from the source never matter, because their vertices keep infinite distance and are skipped.

## Why it is correct

After round `k`, `dist[v]` is at most the weight of the best path from the source to `v` that uses at most `k` edges. (Induction: such a path ends with an edge `a -> v` after a path of at most `k - 1` edges to `a`, which round `k - 1` already covered.) A simple path has at most `n - 1` edges, so after round `n - 1` every `dist` is exact, unless a negative cycle lets a walk of `n` or more edges win. That is precisely what an improvement in round `n` reveals.

## Code

<Tabs>
<Tab label="Python">

```python
def bellman_ford(n, edges, s):           # vertices 1..n, edges (a, b, w)
    INF = float("inf")
    dist = [INF] * (n + 1)
    dist[s] = 0
    for round_ in range(n):
        changed = False
        for a, b, w in edges:
            if dist[a] != INF and dist[a] + w < dist[b]:
                dist[b] = dist[a] + w
                changed = True
        if not changed:
            return dist, False           # no negative cycle reachable
    return dist, True                    # still improving in round n
```

bool bellman_ford(int n, const vector<array<long long,3>>& edges, int s, vector<long long>& dist) {
    const long long INF = LLONG_MAX / 4;
    dist.assign(n + 1, INF);
    dist[s] = 0;
    for (int round = 0; round < n; round++) {
        bool changed = false;
        for (auto& [a, b, w] : edges)
            if (dist[a] != INF && dist[a] + w < dist[b]) { dist[b] = dist[a] + w; changed = true; }
        if (!changed) return false;          // no negative cycle reachable
    }
    return true;                             // negative cycle reachable
}

## Faster variants and relatives

| method | when to use |
| --- | --- |
| queue-based Bellman-Ford (SPFA) | usually fast in practice, worst case still `O(nm)`; only re-relax vertices whose distance changed |
| Dijkstra | all weights non-negative |
| DAG relaxation in [topological order](/cp/graphs/topological-sort/) | the graph has no cycles, even with negative weights: `O(n + m)` |
| Floyd-Warshall | all pairs, `n` up to about 400 |
| Johnson's reweighting | all pairs on sparse graphs with negative edges |

<Callout type="tip" title="Constraint check">
`O(n * m)` is about `10^7` operations for `n = 500` and `m = 2000`, fine; for `n = m = 2·10^5` it is far too slow, and you need Dijkstra, a DAG order or a different idea.
</Callout>

## Pitfalls

1. **Relaxing from an infinite distance.** `INF + w` with a negative `w` looks like a real distance. Always skip edges whose start is unreached.
2. **Stopping after `n - 1` rounds and not checking round `n`**, which misses the cycle.
3. **Treating a negative undirected edge as an ordinary edge.** An undirected edge with negative weight is itself a negative cycle (go back and forth).
4. **Reporting a negative cycle that is not reachable from the source**, when the problem only cares about reachable ones (or the opposite).
5. **Overflow.** Distances reach `n * maxW`; use 64-bit integers.
6. **Using Bellman-Ford when Dijkstra suffices.** It is `O(nm)` versus `O(m log n)`.
